# Правила работы — schoolbell / «Школьник»

1. Сначала читать README, TODO, CHANGELOG, docs/WORKFLOW.md и docs/MIGRATION.md;
   проверить Git и чужие изменения. Не сбрасывать и не прятать их автоматически.
2. Основная ветка пока master. Работать в codex/<задача> от актуальной чистой
   базовой ветки; после сообщения «слил» сверять локальный и удалённый HEAD.
   Переименование master в main — отдельный этап, не предполагать его выполненным.
3. Новые PR не создаются. Push, land, теги, релизы и Pages выполняет владелец,
   если отдельно явно не поручил агенту. Не применять force-push и обход CI.
4. Conventional Commits на английском, с подписью настроенного ключа.
   Первая итерация: исходники и проверки в WSL, коммит Windows Git через UNC.
   Проверять подпись после коммита. При ошибке не отключать подпись, не создавать
   ключи и не копировать закрытые ключи; оставить изменения и сообщить владельцу.
5. README, CHANGELOG и публичные руководства — RU/EN. ТЗ — на русском;
   требования и TC сохраняют номера. Для изменения ТЗ применять методику
   embedded-tech-spec из demo-stm32-skills, отмечать ревизию, происхождение
   [R]/[N]/[U], критерии и матрицу проверки. План миграции не заменяет ТЗ.
6. Runtime целевой базы: OpenWrt 19.07.9, MR3020 v3, kernel 4.14.267, Lua 5.1.
   Сборка и тесты на хосте; компиляторы на устройство не устанавливаются.
   Не объявлять текущий документационный каркас собираемым пакетом.
7. Отдельно различать стенд разработки и устройство приёмки. Перед разрешённой
   установкой сверить цель, сделать проверенную резервную копию, подготовить
   откат. Разрешение на код не разрешает установку, звук, автозвонки, изменение
   сети, часов/NTP, прошивку или перезагрузку. Уже разрешённое действие повторно
   не согласовывать в неизменных границах. Не открывать serial параллельно ядру.
8. Проверки по затронутому поведению: ошибки, границы, конкуренция, сохранность
   данных. Skipped не PASS; CI не заменяет аппаратную приёмку. UI и Pages имеют
   общие исходники; демо ограничивает оборудование, а не расходится по логике.
9. Обновлять TODO, CHANGELOG, требования и документацию. Сначала локальные
   проверки, подписанный коммит; затем владелец push, CI точного HEAD и land.
   Документальные изменения не повышают версию IPK. Пакет — major.minor.patch.
10. Не коммитить секреты, персональные пути, реальные идентификаторы стендов,
    бэкапы, аппаратные логи, скачанные инструменты, прошивки и результаты сборки.
    Исключение — уже публичный неизменяемый архив, описанный в его README.
    Добавлять только конкретные файлы; не применять git add -f для опытов.
11. Локальные исследования: docs/research/NN-name и tests/manual/NN-name,
    исключены Git. До опыта — цель, версии, условия; после — факты, ошибки,
    ограничения и HISTORY. Не считать старые результаты новой проверкой.
12. Новые каталоги lowercase-kebab-case. Архив docs/archive не исполняется,
    не становится runtime, Pages или тестовой фикстурой автоматически.

Методика ТЗ: https://github.com/ViacheslavMezentsev/demo-stm32-skills/tree/main/embedded-tech-spec
