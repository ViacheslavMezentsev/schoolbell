# Порядок совместной работы

[English](WORKFLOW.en.md) · [Правила](../AGENTS.md) · [Миграция](MIGRATION.md)

Владелец выбирает этап, принимает результат и выполняет push/land, релизы и Pages.
Codex готовит изменения, проверки, документацию и подписанный коммит. PR не нужны.

1. Проверить чистоту дерева, базовую ветку main и удалённый HEAD. Не затирать
   чужие изменения. Создать codex/<задача>; одна завершённая итерация — одна ветка.
2. Зафиксировать результат и границы. Новое поведение согласовать в ТЗ;
   документационная миграция не меняет контракт runtime.
3. Реализовать этап, обновить TODO/CHANGELOG RU/EN и затронутые документы.
   Выполнить профильные тесты, git diff --check и осмотр diff. Пока существует
   только `python3 scripts/check-foundation.py`: архив, инвентарь и ссылки.
   Полноценные runtime/UI/IPK-тесты будут перенесены отдельно.
4. WSL хранит рабочую копию и выполняет тесты. Windows Git обращается к той же
   копии через UNC, используя существующий SSH signing key. Не копировать ключ
   в WSL. Коммит с -S; git verify-commit HEAD и формат %G? должны подтвердить
   подпись. Следом проверить чистоту также Linux Git и отсутствие смены режимов.
5. Передать владельцу ветку, SHA, результаты и ограничения. Владелец отправляет
   ветку, ждёт workflow Foundation CI именно для её HEAD. Старый зелёный запуск
   не подходит. Затем только fast-forward; новый HEAD после исправлений проверять заново.
6. Установка — отдельный этап: подтвердить целевое устройство, проверить бэкап,
   иметь предыдущий IPK и зависимости для отката. Звук/автозвонки/часы/NTP/сеть
   не менять без соответствующего поручения. Не путать разработку и приёмку.
7. UI проверять короткими шагами с владельцем, сохраняя несохранённые правки.
   Не повторять запись при неизвестном исходе. Синхронизация исходников Pages
   и публикация — разные результаты. Демо не доказывает работу оборудования.
8. Протоколировать исходные ошибки и факты локально, публично переносить выводы
   без секретов. Обновить TODO; после «слил» снова проверить Git.

Команды владельца в WSL (BRANCH заменить конкретным именем):

```sh
git push -u origin BRANCH
gh run list --branch BRANCH
gh run view RUN_ID --json headSha,conclusion
gh run watch RUN_ID --exit-status
```

После успешного CI точного HEAD:

```sh
git switch main
git pull --ff-only origin main
git merge --ff-only BRANCH
git push origin main
```

git land — необязательный локальный helper, не встроенная команда Git.
В этом репозитории он пока не проверен: до проверки использовать явные команды выше.
Если fast-forward невозможен, не обходить отказ; согласовать интеграцию и повторить CI.

После проверки миграции владелец создаёт отдельное рабочее пространство schoolbell.
Текущее пространство продолжает openwrt-modbus-core. До этого миграция ведётся
из текущего чата, но изменения schoolbell — только в его отдельной WSL-копии.
