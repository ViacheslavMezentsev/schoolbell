# Подтверждение времени и нативная зависимость

Установлена5.0.27 с native clock1.0.0: проверены реальная конкуренция замка и подтверждение через браузер. Контроль включён, время подтверждено, автозвонки выключены; часы/NTP не менялись.

5.0.27: занятость результата команды времени означает ожидание, а не отказ; GET ожидает ограниченно, POST не повторяется. Ошибки хранилища отделены от busy.

Пока worker держит замок канала во время фиксации, poll возвращает ok/pending/waiting=writer. Клиент также пережидает старый busy GET в прежнем бюджете опроса 18 секунд. Busy POST означает непринятую заявку и автоматически не повторяется. Ошибка I/O/JSON возвращает mailbox_storage, а не busy.

В настройках после часового пояса появился блок «Проверка времени». Сначала
«Проверить и подтвердить время», затем сверка показанной даты и явное подтверждение.
Токен действует 15 секунд; если время раньше сохранённой опоры, нужна отдельная
галочка. Это заявление пользователя, не измерение точности UTC и не синхронизация.
Подтверждение и переключатель контроля отключают автозвонки. Сохранённый план
включается отдельно, через свежую проверку часов самим исполнителем.

«Отключить контроль времени» сохраняет явный bypass с предупреждением. После
повторного включения/перезапуска службы требуется новое подтверждение. Кнопка
«Без звука» заменяет надпись Mute; её действие не меняется. Ручной звук не зависит
от автоматического допуска. Часы, NTP и микшер этими действиями не изменяются.

## Команды и восстановление

LuCI cookie/session + form CSRF, POST до 1024 байт; GET только опрашивает исход.
clock-trust принимает prepare/confirm/policy/enable. Wire-ID — 32 hex, владелец —
SHA-256 сессии. В worker хранится настоящий непрозрачный токен, который не передаётся
в JSON и теряется при рестарте. Чужая сессия/устаревшая заявка не подтверждает время.

Приватный /tmp/schoolbell-clock-control, один request и последний result, каждый
до 4096 байт. Один проход обрабатывает не более одной команды; опрос также идёт
во время ожидания player. Заявка старше 15 секунд отклоняется. Перед действием
сохраняется tombstone outcome_unknown: после прерывания действие не повторяется
автоматически. Последний результат не является долговременным журналом: другая
операция может вытеснить его. При неизвестном исходе перечитайте состояние.
HTTP timeout 8 секунд на запрос, цикл polling 18 секунд плюс завершающий запрос;
POST никогда автоматически не повторяется. При ошибке кнопки возвращаются.

Политика /etc/schoolbell-editor/clock-policy.json содержит только boolean enforced,
до 256 байт. Отсутствие означает true. Сначала создаётся/синхронизируется pending,
затем .next/fsync/rename/fsync/readback, затем удаление pending/fsync. Ошибка текущей
операции блокирует допуск; оставшийся pending блокирует bypass после рестарта.
Политика не входит в SBB. Путь из 5.0.25 изменён до первой установки этого механизма;
автоматическая миграция неизвестного старого файла не выполняется.

При disable watermark не повышается недостоверным временем. Включение выполняется
worker после свежего gate.admit и повторной проверки черновика/медиатеки. Потеря
ответа не означает разрешения повторять изменение; состояние автозвонков видно
в верхней плашке. Отдельный журнал фиксирует подтверждение и смену контроля.

## Сборка

`scripts/build-schoolbell-clock.py --cc CC --include LUA_HEADERS --out OUT`
принимает явно выбранный MIPS/musl cross-compiler и Lua 5.1 headers (несколько
--include допустимы). Сборка прямая, без сборки OpenWrt/SDK. Проверяется ELF32 LE MIPS.
Для Debian headers может понадобиться соответствующий macro-header multiarch;
не используйте host libc headers вместо заголовков toolchain.

Результат: modbus-schoolbell-clock_1.0.0_mipsel_24kc.ipk, зависимости libc/libgcc1/liblua5.1.5,
/usr/lib/lua/schoolbell/clock_linux.so, manifest SHA-256. Payload отдельно содержит
/usr/share/schoolbell-editor/dependencies.json. Нативный бинарник не коммитится.
Для другого ABI требуется отдельная сборка и проверка загрузки; проверка ELF сама
по себе не доказывает совместимость libc. Обычный modbus-schoolbell IPK пока
остаётся media-only preview, не установщиком всего engineering payload.

## Проверки и следующий шаг

Команды проверены с реальной моделью доверия и подменяемым хранилищем: ownership,
expiry/restart, отдельное enable, ошибки, отсутствие повторного выполнения. HTTP:
сессия/CSRF/размер/тип. UI: подтверждение, rollback, bypass и возврат после сетевой
ошибки. Сборка MIPS выполнена на хосте; реальных часов/звука/роутера тесты не меняют.
Следующий этап — согласованная установка зависимости и payload, проверка
подтверждения/перезапуска/bypass на устройстве с выключенными автозвонками.
