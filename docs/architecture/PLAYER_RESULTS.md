# Результаты, ошибки и бюджеты player

[English](PLAYER_RESULTS.en.md) · [ТЗ 1.10](../requirements/TECHNICAL_SPECIFICATION.md)

Принят контракт 3.6.21–3.6.28. В р.1.12 добавлена изолированная модель; системная реализация отсутствует. TC-56–60 не имеют native-приёмки.
[Системный API](PLAYER_SYSTEM_API.md) и текущая изолированная очередь различаются.

## Результаты

```lua
handle, err   = player.begin(request, media_handle, permit)
snapshot, err = player.poll(handle)
ok, err       = player.release(handle)
```

Handle — непрозрачный нативный объект, не конструируемый из PID.
Poll возвращает копию снимка; неприменимые поля отсутствуют, а не равны нулю.

| Поле | Тип и значения |
| --- | --- |
| generation | Строка поколения экземпляра |
| attempt_id | Целое число попытки внутри экземпляра |
| state | launching / running / terminal / uncertain |
| exec_status | pending / confirmed / failed / unknown |
| outcome | При наличии: not_started / exit / signal / unknown |
| exit_code | Только для exit, целое 0–255 |
| signal | Только для signal, номер сигнала |
| error | При наличии: структурированная ошибка |
| launch_timeout | Булево, истекал ли срок подтверждения |
| cleanup_pending | Булево, осталась ли очистка |

Terminal означает отсутствие дальнейшего исполнения попытки, не слышимость.
При ранней смерти допустимы terminal, exec_status=unknown и outcome=signal.
Timeout остаётся отмеченным и после последующего уточнения результата.
Повторный poll сохраняет итог до release; unknown не разрешает release при
возможном исполнении. После завершения процесса запись остаётся занятой,
пока cleanup_pending=true. Release не является stop.

## Ошибки и служебный канал

Ошибка содержит code, stage и errno только при ошибке системного вызова.
Закрытые наборы:

- code: invalid_argument, invalid_handle, stale_handle, busy, limit,
  media_invalid, permit_denied, clock_error, spawn_failed, exec_failed,
  observe_failed, protocol_error, launch_timeout, not_terminal, cleanup_failed.
- stage: validate, lock, media, pipe, stdio, permit, fork, exec, observe, cleanup.

Пример: `{code="exec_failed", stage="exec", errno=2}`.
Ожидаемый EAGAIN чтения и waitpid без завершения не ошибки.
Возможный ребёнок требует сохранённого handle, а не только nil/err.

Ребёнок передаёт один кадр 16 байт:
`magic[4], version[1], kind[1], stage[2], errno[4], reserved[4]`.
Константы SBPE/v1 и big-endian закреплены в [контракте кадра](PLAYER_WIRE.md).
Это не сырая C-структура. Частичный кадр накапливается между poll.
Неверный, лишний или оборванный кадр даёт protocol_error; ошибка отправки
не превращается в подтверждение успешного запуска.

## Exec и завершение

До запуска удерживается проверенный executable. Пока ребёнок свой и ещё
не собран, открываем /proc/<pid>/exe и сравниваем device/inode через fstat
с удерживаемым файлом. Совпадение подтверждает exec; строки пути недостаточно.
Сообщённая ошибка exec даёт failed. EOF не доказывает запуск.
Недоступность /proc сохраняет pending, после таймаута — unknown.
Ранний exit/signal может оставить историю exec неизвестной, но доказать
завершение. После reap обращения по PID прекращаются; только адаптер
собирает своих детей. Проверка не подтверждает работу загрузчика или звук.

## Бюджеты

| Операция | Максимум системных операций |
| --- | --- |
| Подготовка родителя в begin | 64 |
| Подготовка ребёнка до exec | 64 |
| Один poll | 8 |
| Отдельный проход cleanup/release | 8 |

Один poll делает не более одного read, до 16 байт. Считаются операции нативных
обёрток, включая неуспешные попытки, часы, наблюдение, временные open/fstat/close.
Подтверждённый exec повторно не проверяется. Работа загрузчика и player после
exec исключена. Нет скрытых циклов повторов или дополнительного cleanup
сверх бюджета poll.

До fork резервируются учёт ребёнка и возможность очистки. Нехватка бюджета
подготовки отвергает запуск до fork. Очистка продолжается отдельными проходами,
не теряя запись или FD. Ограничение числа операций не гарантирует время
выполнения вызовов или расход памяти. Значения — защитные пределы для проверки.

Кадр, поколения и диапазоны приняты в р.1.11. Открыты системные часы/источник случайности,
атомарный допуск с удержанием медиа и recovery ссылок. Свойства madplay
и доступ /proc на target предстоит проверить отдельно. Код, IPK и роутер
не изменены; host-сценарии выполнятся без аудиоустройства.
