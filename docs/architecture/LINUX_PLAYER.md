# Изолированный Linux-адаптер schoolbell

[English](LINUX_PLAYER.en.md) · [ТЗ 1.13](../requirements/TECHNICAL_SPECIFICATION.md)

`packages/schoolbell/native/player.c` — отдельная C-библиотека для Linux.
Она действительно создаёт процессы на хосте, но не подключена к ядру, Lua,
очереди или IPK. Тесты запускают свою программу без аудиоустройства.
Madplay, OpenWrt/MIPS и звук в этом этапе не проверяются.

## Сборка и тесты

```sh
make -C packages/schoolbell/native
sh packages/schoolbell/tests/test-linux-player.sh
make test-schoolbell
make ci-schoolbell
```

Нужны Linux /proc, C99-компилятор, libc headers, make и timeout. Сборка библиотеки
идёт в out/native-schoolbell-player; тестовые файлы/бинарники — в отдельный
mktemp-каталог с очисткой. Core dumps в runner отключены. На роутер ничего
не копируется. CI schoolbell устанавливает gcc/libc6-dev/make явно.

13 групп: 8 с реальными процессами и 5 с подменой отказов системных вызовов.
Проверяются stdin и неизменное смещение исходного FD, exec identity, exit/signal,
большой stdout/stderr в /dev/null, независимые ресурсы и quota, symlink lock,
смерть владельца с живым ребёнком, повторные циклы без FD-утечки, предел FD
перед fork, random/pipe/clock/fork/read/wait/close и повреждение кадра.
Это host-покрытие TC-68/69, не аппаратный PASS.

## C-граница

`player.h` задаёт create, begin, poll, release, destroy.
Конструктор получает доверенные executable FD, lock-directory FD и argv-профиль;
таймаут 100..60000, лимит записей 1..128, ресурсы 1..4 задаются явно.
Caller удерживает неизменяемый executable и media. Произвольная заявка не задаёт
команду shell или профиль. В argv максимум 16 аргументов/2048 байт суммарно;
это защитный предел данного C backend, не пользовательского редактора.

Begin получает номер ресурса, regular-file FD мелодии и чистый bounded permit.
Адаптер переоткрывает медиа через /proc/self/fd с проверкой device/inode, чтобы
иметь независимое смещение; путь пользователя не открывается повторно.
Конкретное хранилище ревизий/проверка пути до исходного FD принадлежат caller.
Файл передаётся ребёнку как stdin, stdout/stderr идут в /dev/null.

Create возвращает NULL/errno при отказе. Успешные begin/poll/release возвращают
0; ошибка — -1 с заполненным sbp_result. При успешном begin выдан handle.
Нет Lua userdata/binding: C handle содержит owner/slot/attempt, проверяется
против экземпляра и не считается credential. Таблица C enum/числовых полей
преобразуется в Lua с отсутствующими неприменимыми полями будущим binding.
В C errno=0 означает отсутствие errno; exit_code/signal значимы лишь при
соответствующем outcome.

Generation получается из 16 байт getrandom(GRND_NONBLOCK), без fallback.
Attempt_id не переиспользуется. Poll получает время CLOCK_MONOTONIC и делает
один bounded проход. Terminal может появиться до EOF канала: release тогда
возвращает busy, следующий poll дочитывает. Окончательный результат стабилен.
Release не посылает сигналов; destroy отказывает, пока есть записи.
При потере права wait (ECHILD) сохраняется uncertain без дальнейшего
исследования /proc по PID и без разрешения release.

## Условия и границы безопасности

Процесс однопоточный, без стороннего reaper; SIGCHLD должен быть SIG_DFL без
SA_NOCLDWAIT. Стандартные FD 0/1/2 открыты. Обработчики сигналов не меняют
таблицу FD и не входят в адаптер. Эти условия не заменяются блокировками библиотеки.

До fork перечисляются FD через /proc/self/fd: максимум 32, иначе отказ.
После fork только нативные операции: настройка потоков/сигналов, закрытие
лишних FD по готовому списку и execve через удерживаемый executable FD.
От ребёнка после exec остаётся только унаследованный lock-FD кроме stdio;
это проверяет тестовая программа. Ошибки подготовки/exec идут кадром SBPE.

Lock-каталог приватный, принадлежит эффективному пользователю и не допускает
запись group/other. Lock-файл regular, без symlink/hardlink и доступа group/other.
Не удалять/заменять его при работе. Адаптер никогда не вызывает LOCK_UN:
закрытие своей копии не освобождает блокировку, пока ребёнок держит свою.
Это подтверждено тестом смерти владельца, но только для тестовой программы.

Подготовка/закрытия родителя укладываются в 64 вызова; poll/release — до 8.
Ребёнок имеет статически ограниченный путь до 64 при списке до 32 FD.
Время ОС и libc не ограничено этими числами; это не real-time гарантия.
Close не повторяется после EINTR на Linux, чтобы не закрыть чужой reused FD.
Сбой close остаётся диагностикой, очистку/запись клиент завершает явно.

## Что ещё отсутствует

Lua binding и интеграция очереди; target сборка/IPK; реальное удержание ревизий,
атомарная публикация и recovery медиатеки; административное восстановление
после потери права wait. Нет проверки свойств madplay FD/stdin, аудиоустройства,
слышимого звука или задержек/RAM MR3020. Расписание и UI этот backend не меняет.
