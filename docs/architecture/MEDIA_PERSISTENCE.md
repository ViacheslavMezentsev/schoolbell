# Постоянная медиатека schoolbell

Принятый контракт ТЗ 1.17, пункты 3.5.10–3.5.27; [English](MEDIA_PERSISTENCE.en.md).
Это требования, без реализации, реального звука и изменений роутера.

Штатные мелодии — ресурсы пакета, пользовательские — отдельные постоянные
данные. Обновление не перезаписывает пользовательские файлы. `/tmp` не является
постоянной медиатекой. Недоступное хранилище не заменяется пустым; внешний
накопитель будет отдельным этапом.

## Замена

Каждая ревизия неизменяема. Каталог содержит ID, ревизию, размер, SHA-256 и
проверенные параметры аудио; имя для пользователя не является путём. Поколения
снимков — внутренние метаданные, не дополнительные версии в настройках.

Одна изменяющая операция одновременно: проверка пикового места и запаса →
ограниченный потоковый приём → проверка MP3/совместимости → сохранение новой
ревизии → подготовка согласованного комплекта → публикация. Фактический размер
контролируется, весь MP3 в RAM не помещается. Ошибки места возможны и после
предварительной проверки. Существующие удерживаемые файлы ради загрузки не удаляются.

Загрузка не меняет планы. Отдельная команда замены показывает затронутые ссылки
выбранных расписаний и сохраняет их согласованно. Принятые заявки используют
прежнюю ревизию. Снимок связывает каталог, настройки и планы с точными файлами;
файлы могут совместно использоваться несколькими снимками.

## Сохранение и восстановление

«Сохранено» — только после подтверждённой постоянной записи файлов, метаданных
и публикации. Требуются синхронизация файлов и каталогов; один rename не является
доказательством долговечности. Конкретный протокол и подходящие ФС ещё выбираются.
Ошибка фиксации с неопределённым исходом означает «исход требует проверки»,
а не обещание прежнего состояния. Потеря ответа требует сверки, а не слепого повтора.

| Ситуация | Поведение |
| --- | --- |
| Незавершённая загрузка/неопубликованный комплект | Не активировать |
| Исправный текущий комплект | Проверить файлы/ссылки и обычные условия допуска |
| Повреждён текущий, исправен предыдущий | Восстановить целый предыдущий для просмотра; автозвонки на паузе до подтверждения |
| Исправного комплекта нет | Режим восстановления, без пустого плана и автозвонков |
| Перезагрузка | Не повторять старую очередь и не догонять пропущенные звонки |
| Авария только службы | Исключить старого проигрывателя до новых запусков/удаления его файлов |

Храним один предыдущий согласованный комплект по умолчанию; это не внешний
backup. Удаление возможно лишь после проверки ссылок сохранённых планов,
действующего комплекта, отката, незавершённого backup и живых удержаний.
При неопределённости очистка запрещена; повтор восстановления безопасен.
Публикация, восстановление и очистка сами не запускают звук.

## Проверки и следующие решения

TC-73–82 плановые: обновление/недоступность, неверные файлы и ссылки, ENOSPC,
короткие записи/обрыв, выборочная замена, конкуренция, прерывание каждого шага
фиксации, ошибки синхронизации/потеря ответа, повреждение обоих комплектов,
повтор recovery, старый процесс и очистка с живыми ссылками.
Host-проверки не подтверждают поведение flash при отключении питания: target
опыт требует отдельного согласования.

Открытый вопрос 8.2.12: точные пути/форматы, API и права, параметры аудио и
валидатор, квоты/запас, идентификация операций, протокол фиксации/сверки,
совместная публикация планов, поддерживаемые ФС и безопасная очистка.
Лимит 16 публикаций за жизнь media_linux — ограничение прототипа, не будущей
медиатеки. Общий механизм настроек core 6.6 не реализуется этой веткой.

Уточнение этапа 1.18: [формат, квоты и порядок фиксации](../formats/MEDIA_FORMAT.md) приняты. Перечень открытых вопросов выше относится к этапу 1.17; актуальные остаточные решения — 8.2.12 ТЗ 1.18.
