# Аудит запуска schoolbell 5.0.31

[English](STARTUP_AUDIT.en.md) · [Программа приёмки](../acceptance/ACCEPTANCE.md)

25.10.2026. AC-06, дополнение host-покрытия TC-132; прикладной контракт и
версия IPK не меняются. Исполняется настоящий `schoolbell-auto`, но часы,
хранилище, boot/TZ, mailbox, журнал и проигрыватель подменены. Аппаратный холодный
запуск, procd, flash и звук этим опытом не проверены. AC-06 целиком остаётся открытым.

| Исходное состояние | Проверенное поведение |
| --- | --- |
| Служба перезапущена, boot/TZ прежние, контроль включён, опора сохранена | Опора не переносит доверие между экземплярами; `clock_untrusted`, новых claim/записей опоры/звука нет |
| Часы позади сохранённой опоры | `before_reference`; запуск блокирован |
| Опора недоступна | `reference_unavailable`; запуск блокирован |
| Новый boot ID, включая явно выключенный контроль | `confirm_clock`; прежний план не получает разрешение |
| Сохранённый TZ отличается, включая выключенный контроль | `timezone_changed`; звука нет |
| Время подтверждено, но boot/TZ плана отличаются | Подтверждение не заменяет явного применения плана |
| План выключен, время подтверждено | План остаётся выключен |
| Недопустимая календарная дата при выключенном контроле | `clock_invalid`; звука нет |
| Рестарт в том же boot/TZ с явно выключенным контролем и разрешённым планом | Будущий звонок может исполниться; это не холодная загрузка и не импорт/обновление |
| Постоянная граница уже прошедших событий впереди текущего времени | `backward_hold`; старый звонок не повторяется |

При изменении TZ во время работы код завершает процесс для повторного запуска
procd с новым libc TZ. Это установлено анализом; фактический respawn и весь маршрут
смены TZ требуют отдельной аппаратной проверки. Загрузка init вызывает
`schoolbell-package initialize`; отсутствие package.pending и успешный запуск
процесса не равнозначны разрешению автозвонков. Ошибки native, политики, временных
токенов и записи опоры также покрываются существующими gate/trust/command тестами.

Новые 11 сценариев добавлены к 17 прежним в `test_automatic_service.lua`.
Они проверяют именно worker, но не HTTP-мост и не реальную долговечность записи.
Подтверждение времени и применение плана остаются отдельными действиями.
Нельзя писать в инструкции, что отключение контроля даёт разрешение после reboot,
либо что любой рестарт службы безусловно выключает уже разрешённый план.

Независимый `test_automatic_oracle.lua` задаёт буквальный список 21 момента:
15 основных и 6 предзвонков за 2 минуты, плюс отключённая строка. Проверяет
fixed на двух датах, annual на назначенной дате, тихие соседние даты и отсутствие
повтора в следующем году. Расчёт проверяется настоящими `automatic.events/step`,
с обходом по секундам. Эталон не строится через preview проверяемого календаря.
Это часть AC-03/TC-31; не проверяет слышимый звук, весь год или все интервалы pre.

Следующий шаг: после окончания измерения часов и отдельного разрешения выполнить
холодный запуск с выключенными автозвонками, проверить блокировку/сохранность и
подтверждение без активации. Звук, питание и изменение времени в этой ветке не разрешались.
