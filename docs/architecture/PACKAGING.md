# IPK и автономный комплект schoolbell

Проверка GitHub Releases и установка из интерфейса описаны как будущий общий контракт: [проверка и обновление](https://github.com/ViacheslavMezentsev/openwrt-modbus-core/blob/243a7ccad6aeb2499d3efd5d0c4cef9e822d393e/docs/core/RELEASE_UPDATES.md), schoolbell ТЗ 4.8. Текущий IPK 5.1.2 сам не проверяет релизы и не обновляется из сети. Manifest сборки и SHA256SUMS ещё не заменяют подписанный release manifest.

[English](PACKAGING.en.md)

5.0.31 упаковывает текущий инженерный исполнитель, LuCI, календарь, медиатеку,
backup, контроль времени и шесть штатных MP3. Это полноценный IPK текущего
приложения, но не завершение production-интеграции с публичным API ядра и
изолированной очередью/player. Нативные часы поставляются отдельным IPK 1.0.0.
Скриптовый IPK собирается без SDK. Установка через opkg, восстановительный откат и обновление проверены на роутере с сохранением данных и auto-off; браузерная приёмка отдельно.

## Сборка и совместный релиз

```sh
make build-schoolbell
# Нативный модуль: см. CLOCK_UI.md и scripts/build-schoolbell-clock.py --help.
# Для различимости сборки ядра явно задайте её версию:
make build-core VERSION=0.4.0-1+g$(git rev-parse --short HEAD)
python3 scripts/build-schoolbell-bundle.py \
  --schoolbell out/modbus-schoolbell_5.0.31_all.ipk \
  --native out/schoolbell-clock/modbus-schoolbell-clock_1.0.0_mipsel_24kc.ipk \
  --core out/modbus-rtu-core_0.4.0-1+g$(git rev-parse --short HEAD)_all.ipk \
  --out out/schoolbell-release --download
tar -czf out/schoolbell-release-openwrt-19.07.9-mipsel_24kc.tar.gz -C out schoolbell-release
sha256sum out/schoolbell-release-openwrt-19.07.9-mipsel_24kc.tar.gz
```

Повторная сборка из кэша выполняется без `--download`, в новый выходной каталог.
Сборщик отказывает при недостающем файле, другой SHA-256, архитектуре, версии
нативного модуля или незамкнутых зависимостях. Выход: IPK, manifest.json,
закреплённые зависимости, SHA256SUMS, read-only check.sh и эта памятка.
Манифест содержит исходный commit и признак незакоммиченного дерева; релиз
собирают повторно из чистого принятого HEAD после CI. Сборщик не публикует релиз.

Один GitHub Release может содержать IPK ядра, schoolbell и весь комплект,
с независимыми версиями компонентов. Профиль комплекта: **OpenWrt 19.07.9,
ramips/mt76x8, mipsel_24kc, musl, Lua 5.1**. Kernel ABI строго
`4.14.267-1-d92769dc5268e102503ae83fe968a56c`; libc `1.1.24-2` — часть прошивки.
Они не заменяются комплектом. `Architecture: all` у Lua-пакета не делает
бинарные зависимости переносимыми на другую прошивку. Комплект другой версии
OpenWrt собирают и проверяют отдельно. Ядро включено как совместный артефакт,
но schoolbell пока не зависит от его невыпущенного событийного API.

В lock-файле закреплены 33 официальных IPK (включая Lua/LuCI, madplay и USB audio),
950356 байт загрузки. Полный LuCI metapackage с firewall/network не нужен:
используются luci-base и тема. Все зависимости, кроме явно заданной firmware
базы, находятся в комплекте. Существующие версии LuCI могут отличаться от feed:
пакет допускает удовлетворяющие его Depends установленные библиотеки, но это
не аппаратная проверка всех комбинаций. Не обновляйте весь комплект вслепую.

SHA-256 обнаруживает изменение относительно проверенного lock/манифеста,
но не заменяет подпись происхождения релиза. Источники зависимостей — официальные
HTTPS feeds, лицензии указаны в lock; перед публичным распространением нужно
выполнить требования лицензий к исходникам/уведомлениям. Аудио перенесено по
поручению владельца исходного проекта; новая лицензия на него не назначается.

## Установка и откат (отдельный согласованный этап)

1. Скачать комплект на ПК; проверить SHA256SUMS и происхождение релиза. Сохранить
   проверенную `.sbb`, отдельную копию `/etc/schoolbell-editor`,
   `/etc/modbus-schoolbell/data`, метаданные opkg и совместимый прежний полный IPK.
   Резервная копия должна храниться вне роутера. Штатный `.sbb` не содержит
   device-specific опору/политику часов.
2. Сверить firmware, архитектуру, kernel ABI, установленные зависимости и их
   версии. `sh check.sh` проверяет идентичность/хеши и выводит место, **ничего не
   устанавливает**. Оценить пиковое место: IPK в `/tmp`, распаковка, opkg metadata,
   прежние данные/копии и запас не менее max(512 КиБ, 10% overlay). Поля payload
   и file_blocks_estimate — оценки; сжатый Installed-Size feed не равен этому пику.
   Полный комплект не обязан целиком помещаться в overlay: часть уже в squashfs.
   Общий системный admission/авторасчёт инкрементального пика ещё в TODO.
3. Отключить автозвонки, завершить операции звука/загрузки/backup, закрыть страницу.
   На первом переходе с инженерного tar особенно проверить владельцев файлов
   (`opkg search`) и резервную копию. Не использовать force-overwrite.
4. После отдельного разрешения установить **только отсутствующие** удовлетворяющие
   зависимости из локальных IPK, затем native clock, затем schoolbell через
   `opkg install /path/to/package.ipk`. Все нужные файлы уже доступны без сети;
   `opkg update` не требуется. При конфликте существующих ABI/версий остановиться,
   не применять force-depends. Ядро из комплекта устанавливается отдельным решением.
5. Хуки выключают startup службы, останавливают её, удерживают общий sound/media
   gate и постоянный `package.pending`. Postinst записывает и перечитывает
   `enabled=false`, снимает только собственный gate, запускает службу с выключенными
   звонками. Повреждённое состояние/чужая блокировка/ошибка записи останавливают
   процедуру; нельзя удалять чужой lock ради продолжения. Время/NTP/сеть не меняются.
6. Проверить версию, вход LuCI, чтение черновика/медиатеки/backup, статус auto-off
   и core/demo. Звук и включение плана — отдельные явные действия. Удалить только
   временные установочные IPK после успешной проверки, оставить внешнюю копию.

Откат: совместимый полный предыдущий IPK устанавливается локально через
`opkg --force-downgrade install /path/to/previous.ipk`; это разрешение понизить
**версию приложения**, не обход зависимости/ABI. Хуки также сохраняют auto-off.
Схема данных должна быть читаемой старым кодом; иначе восстановление проверенной
копии отдельно, без молчаливого удаления новых полей. Preview-IPK до 5.0.28 не
является полным откатом текущего приложения. Для первого перехода нужен сохранённый
инженерный payload и данные; процедуру проверяют отдельно на стенде.

Пользовательские каталоги не входят в data.tar.gz и не удаляются при uninstall.
После удаления сохраняется package.pending; новая полная установка завершает его.
IPKG_INSTROOT-хуки ничего не запускают: при включении службы в готовом образе
initialize создаёт приватные каталоги, чистая установка начинает с auto-off.
Служба не запускается при незавершённом package.pending. Это не транзакционный
откат opkg при потере питания: при повреждённом коде нужен внешний комплект восстановления.

## Проверки

TC-134: реальный payload и shell/Lua lifecycle в изолированном host-каталоге,
подменён только procd и привязка путей; установка/обновление/откат сохраняют данные,
коррупция и чужие locks дают отказ, повтор finish после потери tmpfs остаётся auto-off.
TC-135: замыкание зависимостей, SHA/архитектура/exact native version и отсутствие
автоскачивания при неполном кэше. CI не запускает MIPS-код и не заменяет тест opkg
на целевой flash. Перезагрузка, питание и годовая автономность здесь не проверялись.

При завершении установки удаляются только временные request/result/next командного
mailbox под его замком. Во время package.pending новые команды отклоняются до и
после захвата замка; отложенное включение из прежней версии не исполняется.

Результаты target-проверки: BusyBox может не содержать `stat`; хуки используют
объявленные Lua/nixio. opkg способен вернуть ноль после ошибок распаковки файлов
в отсутствующие каталоги: оба сборщика создают directory entries, проверка артефакта
отклоняет пропущенных родителей. Сверять каждый payload SHA, не только exit code.
LuCI 19.07 игнорирует mtime исходников в bytecode cache: postinst очищает только
модули/контроллер schoolbell и индексы dispatcher. Ядро и runtime native clock не меняются.

Первый откат выполнен локальным `5.0.27+recovery` IPK из точного снимка установленного
инженерного кода с поддержкой безопасного lifecycle, а не прежним публичным релизом.
Исходные байты кода и пользовательские данные сохранены. Перезагрузка, потеря питания
и первый запуск без сети не проверены; совместимость произвольных старых схем не обещается.
