# Системный адаптер опоры времени

Текущий этап 5.0.25: [интеграция с исполнителем и отключение контроля](CLOCK_EXECUTOR.md). Ниже сохранены границы первоначального этапа; изолированная target-проверка адаптера выполнена, установка интеграции и UI ещё впереди.

[English](CLOCK_SYSTEM.en.md)

Изолированный этап: `clock_system.lua` + нативный `clock_linux.so`. Проверяется на Linux-хосте, не включён в IPK schoolbell 5.0.14 и не подключён к исполнителю. Часы/NTP не изменяются.

## Источник времени

`clock_system.new(root, context_provider [, native])` возвращает порты для `clock_trust.new`. root — явно заданный существующий приватный каталог, без значения по умолчанию. context_provider — обязательная функция, возвращающая короткий идентификатор текущего контекста. При интеграции она должна меняться при смене наблюдателя/загрузки/настройки зоны. Она вызывается до и после пары и должна читать кешированные данные, без сети, процессов и файлов в каждом опросе. Новый экземпляр модели всегда начинает без доверия; контекст не является переносимым токеном разрешения.

Нативный sample снимает `CLOCK_BOOTTIME → CLOCK_REALTIME → CLOCK_BOOTTIME` тремя clock_gettime. BOOTTIME включает сон, поэтому долгий сон не скрывает разрыв наблюдения. Обе временные шкалы учитывают системную частотную коррекцию; BOOTTIME не является RAW. Разрешение обеих шкал проверяется clock_getres при создании адаптера: больше 1 мс или ошибка — отказ. Скрытого fallback на os.time нет.

UTC округляется вниз до целых миллисекунд, границы BOOTTIME наружу и расширяются на 2 мс с каждой стороны (квантование UTC и допуск разрешения). Модель допускает перекрытие соседних скобок, но уменьшение любой границы означает ошибку. Сохраняются лимиты 100 мс пары и 3000 мс промежутка; консервативное округление может раньше потребовать проверки. Это оценка привязки чтений при заявленном разрешении Linux, а не точность UTC относительно эталона. Разрешение clock_getres само по себе не доказывает аппаратную точность; target clocksource ещё требует проверки.

Поддерживаемая граница адаптера: epoch 0…2147483647999 мс (1970…2038), без обещания time64 для целевой 32-битной системы. Кодек по-прежнему допускает свой полный 53-битный диапазон. Поддержка последующих дат требует отдельного проверки libc/ядра/календаря. Нет clock_settime, adjtimex, NTP-запросов или shell.

## Хранилище

Каталог открывается покомпонентно через openat/O_DIRECTORY/O_NOFOLLOW. Конечный каталог принадлежит effective UID процесса и не доступен группе/остальным. Предки и процесс того же UID должны быть доверенными: это не песочница против владельца каталога или root. Автоматического mkdir/chmod/chown нет. Каталог не переименовывается и lock-файл не удаляется другими участниками во время работы.

Каждая load/save удерживает отдельный `.clock-reference.lock`: неблокирующий flock, стабильный inode, 0600, CLOEXEC. Разрешены только clock-reference.json и clock-reference.next. Обычные файлы принадлежат текущему UID, приватны, имеют одну жёсткую ссылку и размер до 1024 байт. Symlink/FIFO/каталог/слишком большой файл дают отказ, а не отсутствие. Ошибки I/O также не превращаются в пустую опору.

Чтение ограничено 1025 байтами для обнаружения превышения. Временный файл создаётся через O_EXCL; запись обрабатывает частичные результаты и EINTR. Менеджер сохраняет принятый порядок write → fsync файла → renameat → fsync каталога → readback. Все операции выполняются относительно удерживаемого directory FD. Закрытие/GC освобождает FD/lock; ошибка закрытия исключает успешный результат. После сбоя запись не повторяется автоматически. Сохраняются CAS, проверка checksum и запрет fallback из clock_reference_store.

Нативное хранилище синхронное: fsync не имеет гарантированного предельного времени. Модель повторно наблюдает часы после фиксации и блокирует допуск при потере непрерывности; интеграция этого поведения в ожидание player пока отсутствует.

## Проверки

TC-126: реальные часы и временные каталоги на хосте, roundtrip/reopen, отсутствие доверия после нового экземпляра, CAS, конкурирующие процессы, закрытие/GC, типы файлов/ссылки/лимиты. Отдельная тестовая сборка подменяет системные вызовы: отказы openat/read/write/fsync/renameat/flock/close и часов, частичные записи, счётчик FD. Production-модуль не экспортирует injection API. TC-125 дополнен перекрывающимися скобками.

Runner: `packages/schoolbell/tests/test-media-manager.sh`, через make all/ci-schoolbell. Модуль также собирается `make -C packages/schoolbell/native lua`. Тесты не меняют системное время и не требуют роутера. Power-cut, MIPS/time32, физическая flash и ресурсы роутера не проверены. Следующий шаг — отдельная изолированная target-проверка после согласования; затем интеграция контекста, наблюдения в ожидание player и UI подтверждения.

Основание выбора шкал: [Linux clock_gettime](https://man7.org/linux/man-pages/man2/clock_gettime.2.html). RAW полезен для оценки частоты аппаратного хода; он не включает коррекции NTP. Корректировать системное время по этой оценке без учёта уже действующей поправки нельзя. Этот адаптер поправок не применяет.
