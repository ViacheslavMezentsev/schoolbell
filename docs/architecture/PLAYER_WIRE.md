# Константы кадра, поколения и диапазоны player

[English](PLAYER_WIRE.en.md) · [ТЗ 1.11](../requirements/TECHNICAL_SPECIFICATION.md)

Приняты требования 3.6.29–3.6.34; кодек и изолированная модель добавлены в р.1.12, системный адаптер отсутствует.
Плановая проверка — TC-61–65. [Результаты API](PLAYER_RESULTS.md) сохранены.

## Кадр ребёнка

Ровно 16 байт; все многобайтовые числа беззнаковые, big-endian.
Не передавать сырую C-структуру.

| Смещение | Поле | Значение |
| --- | --- | --- |
| 0–3 | magic | ASCII SBPE: 53 42 50 45 hex |
| 4 | version | 1 |
| 5 | kind | 1, ошибка системной операции ребёнка |
| 6–7 | stage | Только 5, 8 или 10 |
| 8–11 | errno | 1..4095 |
| 12–15 | reserved | 0 |

Общая нумерация stage: validate=1, lock=2, media=3, pipe=4, stdio=5,
permit=6, fork=7, exec=8, observe=9, cleanup=10.
В кадре ребёнка допустимы только stdio/exec/cleanup; остальные этапы
передаются родительским API. Неизвестные значения и выход за диапазон —
protocol_error без угадывания версии.

Эталон exec/errno=2:

```text
53 42 50 45 01 01 00 08 00 00 00 02 00 00 00 00
```

Максимум один кадр, затем завершение ветки ошибки. Частичный кадр собирается
между poll, лишний/оборванный отвергается. Exit ребёнка сам по себе не заменяет
кадр. Ошибка внутренней логики не получает выдуманный errno; без достоверного
кадра сохраняется неопределённость подтверждения запуска.

## Поколение и попытки

Generation — 16 байт системного источника случайных данных, представленные
32 строчными hex-символами. Создаётся один раз на экземпляр и не меняется.
Недоступность источника отклоняет создание: нет fallback на время/PID.
В тестах источник подменяется.

Поколение не секрет и не авторизация. Нативный handle дополнительно привязан
к экземпляру; совпадение строкового поколения и номера не позволяет подделать
handle. Статистическая случайность не заявляется математической уникальностью.

Attempt_id — целое 1..4294967295, возрастающее без повторного использования.
Пропуск после отказа подготовки допустим. После последнего номера новые
попытки получают limit, старые продолжают обслуживаться; перехода через ноль нет.

## Конфигурация

| Параметр | Диапазон/значение |
| --- | --- |
| launch_timeout_ms | Целое 100..60000, по умолчанию 2000 |
| Ресурсы | 1..4 |
| Активные попытки | Одна на ресурс, включая launching/uncertain |
| Сохранённые записи адаптера | 1..128, по умолчанию 128; terminal до release тоже учитываются |
| ID ресурса | 1..64 ASCII [A-Za-z0-9_-] |
| exit_code | Целое 0..255 |
| signal | Положительный номер, допустимый на платформе |
| Монотонные метки | Целые миллисекунды 0..2^53-1 |

Таймаут, набор ресурсов и лимит записей фиксируются при создании экземпляра.
Дроби, NaN, бесконечности, числовые строки и переполнение дедлайна отвергаются;
нет округления или ограничения к ближайшей границе. Верхний предел signal=64
не предполагается: проверяет нативный слой на target.

Фиксированы: 64/64 операции подготовки, 8 на poll, 8 на отдельный cleanup,
один read до 16 байт за poll, ноль повторов запуска, ноль байт stdout/stderr.
Заявка не задаёт произвольные executable, argv или аудиоустройство —
они принадлежат доверенному профилю. Квоты записей адаптера не меняют лимиты
ожидающей очереди; размеры MP3/медиатеки относятся к менеджеру медиа.

## Следующий этап

Изолированные кодек и модель API с подменяемыми системными операциями:
эталон/неверные поля, все разбиения кадра, отказ источника поколения,
чужой handle, исчерпание счётчика и границы параметров. Реальные процессы
требуют дальнейшей проработки системных часов/источника случайности,
атомарного допуска с удержанием медиа и восстановления ссылок.
Первоначальный контракт был только документацией; изолированное покрытие р.1.12 описано ниже. Звука и изменений роутера нет.

ТЗ schoolbell 1.12: изолированные Lua-кодек SBPE и модель API проигрывателя с подменяемыми операциями. 32 группы host-тестов: кадры, поколения, сроки/исходы, квоты и очистка. Без native binding, процессов, звука, ядра и изменений роутера; IPK прежний. [Player model](PLAYER_MODEL.md).
