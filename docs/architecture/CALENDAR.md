# Вычислитель расписаний schoolbell

[English](CALENDAR.en.md) · [ТЗ 1.6](../requirements/TECHNICAL_SPECIFICATION.md) · [Lua-модуль](../../src/lua/schoolbell/calendar.lua)

Изолированный модуль Lua 5.1: проверяет и копирует модель, рассчитывает моменты
для предпросмотра и будущей регистрации. Не читает часы/файлы, не запускает
проигрыватель, не меняет cron, не обращается к ядру. В media-only IPK 0.0.1
модуль пока не включён. Это первый прикладной расчёт, не готовая замена оригинала.

## Принятые правила

- fixed: выбранное расписание повторяется каждый день независимо от планов.
- annual: выбирается назначение точной даты явно указанного года. Нет даты
  или плана на год — тихо; повторения на следующий год нет. Можно передать
  несколько разных годовых планов заранее. Недельных правил/приоритетов исключений пока нет.
- quiet, пустое расписание или расписание без включённых строк означают тихий день.
  Он не содержит ни основных звонков, ни предзвонков следующего дня.
- enabled=false сохраняет строку без обоих событий. pre=true добавляет предзвонок
  с общей мелодией и интервалом 1–10 минут, только если enabled=true.
- Интервал вычитается из местного календарного времени с переходом часа/суток.
  Предзвонок остаётся связанным с датой основного звонка. Если его фактическая дата
  тихая, подавляется только предзвонок. Просмотр последнего дня заглядывает
  в следующий исходный день, чтобы не потерять предзвонок через полночь.
- Несуществующее местное время (gap) или два возможных UTC (fold) — ошибка всего
  запрошенного окна. Нет нормализации, выбора первого/второго варианта или частичного
  списка. Это политика расчёта, не политика коррекции работающих часов/пропущенных звонков.
- Совпавшие моменты разных строк не объединяются; порядок стабилен: UTC, затем ID.
  Проигрывание по очереди и срок актуальности принадлежат будущему worker.

## Внутренняя модель и API

Это Lua-модель для тестируемого вычислителя, **не утверждённый формат settings.json,
импорта, миграций или публичного API ядра**. Все поля обязательны, кроме fixed_schedule
в annual; неизвестные поля отвергаются. Таблицы без metatable; списки плотные.

```lua
local calendar = require("schoolbell.calendar")
local model = assert(calendar.compile({
    revision = "draft1", mode = "annual", timezone = "UTC+05:00",
    pre_minutes = 2, pre_media = "pre",
    media = {"main", "pre"},
    schedules = {{id = "weekday", rows = {
        {id = "lesson1", time = "08:00", media = "main", enabled = true, pre = true}
    }}},
    plans = {{year = 2026, days = {["2026-10-26"] = "weekday"}}}
}))
local resolver = assert(calendar.fixed_offset("UTC+05:00", 300))
local result, err = model.calculate("2026-10-26", "2026-10-26", resolver)
-- result.events: 07:58/pre и 08:00/main; нет никаких действий с оборудованием.
```

fixed_schedule содержит ID существующего расписания либо reserved ID quiet.
Расписание с собственным ID quiet создать нельзя. plans может быть пустым;
даже неиспользуемые расписания/планы/выключенные строки проверяются. Media — список
допустимых ID; проверка реальных файлов и их ревизий остаётся у менеджера медиа.
Дата строго YYYY-MM-DD, время HH:MM, булевы значения не заменяются строками "on".
ID/revision — 1–64 ASCII символа A–Z/a–z/0–9/_/-. ID строк уникален внутри расписания.

| Операция | Результат |
| --- | --- |
| validate(config) | true либо nil, error; ничего не сохраняет |
| compile(config) | Независимый снимок с методом calculate либо nil, error |
| model.calculate(first, last, resolver) | Включительное окно местных дат; result либо nil, error |
| days_in_month(year, month) | Число дней либо nil, error |
| weekday(date) | ISO: понедельник=1 … воскресенье=7 |
| add_days(date, delta) | Проверенная дата плюс целое число дней |
| fixed_offset(zone, minutes) | Явный resolver постоянного смещения, без DST/tzdb |
| limits() | Копия защитных ограничений реализации |

result содержит revision, timezone, days (дата и выбранный schedule_id) и events.
Каждое событие: id, revision, timezone, date/time фактического момента, utc (целые
секунды), origin_date основного звонка, schedule_id, row_id, kind=main/pre и media.
ID составлен из revision/origin_date/schedule_id/row_id/kind; это внутренний ID,
не exactly-once гарантия. Владелец обязан менять revision при изменении модели.
Соседние окна сохраняют ID без потерь/дублей на границе; пересекающиеся окна
намеренно возвращают те же ID. Ошибки вида {code, path}, без частичного result.
Правки исходной модели или выданных событий не меняют скомпилированный снимок.

## Часовой пояс

Доверенный ограниченный resolver(zone, date, time) возвращает плотный список UTC:
один целый момент — успех; пустой — nonexistent_time; два — ambiguous_time.
nil/исключение означает ошибку resolver; неверная форма/число — отказ.
Моменты проверяются в пределах ±24 часов от местного времени, записанного как UTC.
Resolver должен быть детерминированным для выбранной версии правил зоны и не
блокировать вычислитель. Тесты подменяют его; production tzdb/системный адаптер
не реализован. fixed_offset поддерживает целые минуты от −840 до +840, включая
получасовые/четвертьчасовые зоны; он не превращает имя IANA в базу переходов.
Часовой пояс хоста и os.time/os.date не используются. Date arithmetic работает
с пролептическим григорианским календарём 0001–9999, что не обещает такую же
область time_t/scheduler на OpenWrt. Привязка к ABI и качеству часов ещё впереди.

## Защитные пределы и проверки

Текущие пределы: 16 расписаний, 8 разных лет,
64 media ID, максимум 366 назначений в год. Один запрос — не более 31 дня и
512 событий. Переполнение отклоняет окно целиком; для полного года вызывающий
считает небольшие окна, например по одному дню. Эти числа — пределы алгоритма,
не измеренные RAM/CPU-нормы роутера и не окончательные квоты хранения пакета.
Не разворачивается весь годовой набор событий при compile. Нижний/верхний край
области дат не создаёт события вне 0001–9999. Вложенные данные и выход ограничены;
общая Lua память, временные строки, сортировка и GC ещё требуют замера.

```sh
make test-schoolbell
make ci-schoolbell
make all
```

Нужны Lua 5.1 и Python 3.8+. Отдельный CI schoolbell запускает расчёт и проверку
неизменённого media-only IPK; полный make all включает те же тесты.
29 групп TC-36–38 покрывают правила и отказы. TC-39 сверяет 14 404 вектора с
независимым Python datetime за 400-летний цикл и края календаря. Полный високосный
год исходного примера проверяется по дням: 366 × (15+6) = 7 686 событий.

все 15 времён/флаги/мелодии сохранены; тест отдельно задаёт preinterval=2 и premelody=0
из исходных settings. Это не legacy importer и не установленный пользовательский план.
Четыре рабочих слота и пустой, пять выбираемых мелодий и test представлены в тестах.
