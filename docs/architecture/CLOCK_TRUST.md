# Достоверность времени schoolbell

Текущий этап 5.0.25: [интеграция с исполнителем и отключение контроля](CLOCK_EXECUTOR.md). Ниже сохранены границы первоначального этапа; изолированная target-проверка адаптера выполнена, установка интеграции и UI ещё впереди.

[English](CLOCK_TRUST.en.md)

Принятый контракт ТЗ 1.32, раздел 4.7. Ревизия 1.33 добавляет изолированную host-модель. Установленный schoolbell 5.0.14, прошивка/службы/часы/NTP не меняются. TC-113–124 частично покрыты TC-125; системная интеграция и UI пока плановые.

| Статус | Условие | Автоматические звонки |
| --- | --- | --- |
| Не подтверждено | Новая загрузка, нет пригодной опоры/контекста | Заблокированы |
| Обнаружен откат | UTC раньше сохранённой подтверждённой отметки более чем на 5 с | Заблокированы |
| Подтверждено | Принято подтверждение с указанным источником | Можно отдельно включить |
| Требуется проверка | Скачок, ошибка контроля, превышение согласованной неопределённости | Заблокированы |

После reboot сохранённая отметка даёт нижнюю опору, а не длительность отключения и не доверие. Положительное сравнение с ней не доказывает точность. При непрерывной работе сравниваем приращение UTC с приращением монотонных часов. Скачок строго больше 5 с в любую сторону требует проверки; равенство не считается срабатыванием. Пороги настраиваемые 1–60 с с шагом 1 с; бюджеты наблюдения приведены ниже. Перевод локального часа при DST сам по себе не является скачком UTC.

Первый этап: сохраняемая отметка/источник/checksum, статусы, блокировка на сервере, ручная сверка. Пользователь подтверждает показанные часы отдельно от включения плана. Браузер только помогает сверке. Ошибка сохранения или устаревший контекст не дают успеха. Исправление ошибочно будущей опоры требует явного подтверждения расхождения; watermark уже рассмотренных звонков не понижается. Сетевое автоматическое подтверждение и RTC будут отдельным этапом после выбора критериев качества.

Потеря доверия запрещает новые автоматические звонки/предзвонки и отменяет прежнее разрешение. Уже допущенный звук доигрывает; Mute действует. Ручной звонок остаётся доступен с обычными ограничениями. Подтверждение не возобновляет проигрывание; требуется явное включение, без догоняющих/повторных звонков. Проверка есть и перед допуском запуска, а не только в кнопке UI.

В плашке — статус, причина, источник и дата подтверждения; в журнале — переходы и действия, без записи каждого опроса. Год плана сохраняется независимо от часов. Нет плана для текущего года — тишина. Нельзя устанавливать часы из года плана. Копирование на другое устройство не переносит опору/доверие/разрешение запуска.

Открыто: системные источники часов и их погрешность, API-контекст подтверждения, будущая миграция формата, аппаратный износ/ресурсы, NTP/RTC качество, допустимая ошибка и срок автономного доверия. Порог 5 с не является обещанной точностью звонка. Отсутствие отката не выявляет весь неизвестный простой. Суточный пассивный опыт не даёт гарантии годовой точности. Общий API ядра этим контрактом не изменяется.

Файл `/etc/schoolbell-editor/clock-reference.json`: до 1024 байт, envelope data/checksum. В data ровно format="schoolbell-clock/1", source="manual", confirmed_utc_ms, checkpoint_utc_ms. SHA-256 канонического data, контрольный вектор и строгие границы — в ТЗ 4.7.13 и приложении T. Неизвестный формат не перезаписывается. Существующий 32-битный кодек медиатеки нельзя напрямую использовать для UTC-ms; используется изолированный clock_reference без изменения медиатеки.

Фиксация: temp → fsync → атомарная замена → fsync каталога. Только успешная фиксация даёт подтверждение. Orphan temp не становится опорой; повреждение основного файла не вызывает fallback. Сразу при ручной сверке, затем не чаще 3600 с по монотонным часам. confirmed/source не обновляются ежечасно: меняется только контрольная отметка при непрерывном доверии, в том числе при выключенных автозвонках. Потеря доверия прекращает продвижение; ошибка обязательной записи требует проверки. Примерно 24 периодические фиксации в сутки не определяют физический износ flash.

| Бюджет | Значение |
| --- | --- |
| Наблюдение | Раз в 1000 мс |
| Допустимый промежуток | До 3000 мс включительно |
| MONO → UTC → MONO | До 100 мс включительно, учитывать неопределённость привязки |
| Перед допуском звука | Дополнительная свежая проверка после подготовки |
| Подтверждение | Истекает через 15000 мс; связано с текущим контекстом |

Неоднозначность превышения порога требует проверки, а не оптимистического допуска. Контроль продолжается внутри ожидания проигрывателя; потеря доверия не обрывает текущий звук. Обычный опрос не пишет flash, не ходит в сеть и не запускает процессы. Изменение порога не снимает блокировку. Следующий этап — системный адаптер и интеграция контроля, без обещания аппаратной точности.

Реализация host-модели добавлена в ревизии 1.33: [API и ограничения](CLOCK_TRUST_MODEL.md). Плановые проверки выше частично покрыты изолированными тестами; системная интеграция, UI и роутер по-прежнему не реализованы в этом этапе.

Этап р.1.34: [системный адаптер](CLOCK_SYSTEM.md) реализован и проверен на хосте; утверждения выше о будущем адаптере относятся к его target-проверке и подключению. Исполнитель/UI пока не интегрированы.
