# Удержание ревизии при приёме заявки

Изолированный Linux/Lua 5.1 модуль `schoolbell.media_linux`, проверяемый TC-72
на хосте. Это владение уже подготовленными неизменяемыми файлами, не загрузчик
мелодий и не постоянная медиатека. Ядро, звук, роутер и IPK не подключены.

## API

- `Media.new()` создаёт каталог userdata.
- `store:publish(id, revision, source_fd)` регистрирует точную пару и открывает
  собственный read-only FD того же регулярного inode через `/proc/self/fd`.
  Позиция исходного FD не наследуется. Caller может закрыть свой FD.
- `store:acquire(id, revision)` возвращает приватный lease userdata либо
  `nil, {code=...}`. Выделение памяти предшествует увеличению ссылки.
- `lease:fd()` возвращает заимствованный FD; его нельзя закрывать или изменять.
- `store:release(lease)` идемпотентно снимает ссылку без системных вызовов.
- `store:remove(id, revision)` закрывает FD каталога, но не удаляет файл с диска.
  При наличии ссылок возвращает `busy`. Пара не переиспользуется даже после удаления.
- `store:close()` требует отсутствия ссылок, затем закрывает каталог; повтор допустим.

ID и ревизии: 1–64 ASCII символа `[A-Za-z0-9_-]`. Ограничения экземпляра:
16 публикаций за его жизнь (включая удалённые), 128 одновременно удерживаемых
ссылок. Это ограниченный host-прототип, не согласованный бюджет всей медиатеки
или измерение RAM роутера. Для нового экземпляра нужен явный перенос живого
состояния; автоматический rollover не реализован.
Ошибки: `closed`, `invalid_argument`, `exists`, `limit`, `media_invalid`,
`missing`, `busy`, `invalid_handle`, `stale_handle`, `close_failed`; системная
ошибка может содержать `errno`. После close_failed владение FD уже снято:
повторять close по старому числу нельзя.

## Композиция

`Queue.new(clock, bridge, options, store)` включает admission. Валидация,
квоты, снимок заявки и место в очереди подготовлены до acquire. Квитанция
выдаётся только после удержания точной пары; отказ даёт `media_unavailable`
и убирает резерв заявки. Разрыв в номерах квитанций допустим.
Без четвёртого аргумента сохранён старый API модели.

Bridge получает приватный lease и использует его FD вместо resolver.
`native:begin(request, fd, permit, retained_userdata)` удерживает необязательный
четвёртый аргумент метода вместе с registry-pinned handle. Потеря Lua-ссылок
не снимает удержание, пока handle жив. Квитанции и события lease не раскрывают.

Queued отмена/просрочка снимают ссылку без запуска процесса. Для active ссылка
сохраняется через uncertain и finishing до подтверждённой очистки native handle.
GC lease освобождает счётчик; caller обязан обслужить handles и закрыть каталог
до завершения VM. Явное release — обязанность владельца, не недоверенного клиента.

## Границы и проверки

Доверенный publisher обязан обеспечить неизменяемость содержимого inode;
read-only FD не защищает от записи сторонним владельцем через другой FD.
Замена pathname и закрытие исходного FD не меняют принятую ревизию.
Это не sandbox: debug/registry, произвольные вмешательства в FD и callbacks
вне контракта не поддерживаются. Произвольный OOM всего Lua step, восстановление
после гибели VM/питания, ссылки планов расписаний, upload/MP3 validation и
атомарная публикация на диске остаются отдельными задачами.

Девять host-групп проверяют отказ без квитанции, общие ссылки, отмену/TTL,
подмену ревизии, cleanup/uncertain, signal/exec error, квоты/OOM, GC и замену
pathname. Fixture читает текст вместо MP3; контролируются FD и сбор детей.
Запуск: `make ci-schoolbell` с Lua 5.1 development headers/library и C compiler.

OOM на подготовительном Lua-участке submit может оставить экземпляр очереди заблокированным; квитанция и native lease ещё не выданы. Продолжение работы такой очереди не гарантировано; автоматический перезапуск с повтором заявки не допускается.
