# Системные механизмы и асинхронный API player

[English](PLAYER_SYSTEM_API.en.md) · [ТЗ 1.9](../requirements/TECHNICAL_SPECIFICATION.md)

Приняты требования, не реализация. Нормативные пункты: 3.6.6/3.6.8,
3.6.11–3.6.20; проверки TC-50–55 плановые. API существующей
[очереди](PLAYBACK_QUEUE.md) пока прежний.

## Механизмы

Отдельный нативный модуль schoolbell для Lua 5.1 выполняет fork, подготовку
дескрипторов и execve с массивом аргументов. Ребёнок после fork не возвращается
в Lua. Профиль madplay из [контракта](PLAYER_ADAPTER.md) сохранён.
Зависимость принадлежит комплекту schoolbell, ядро аудио-API не получает.

Отдельный служебный канал с CLOEXEC переносит этап/errno ошибки подготовки
или exec. Родитель читает его неблокирующе и сверяет состояние ребёнка.
EOF может сопровождать раннюю смерть: его недостаточно для доказательства exec.
Подтверждение запуска хранится отдельно от результата завершения.
waitpid(child, ..., WNOHANG) получает exit с кодом либо сигнал; сигнал
не кодируется как обычный exit 128+signal. Быстрый exit не требует предварительно
наблюдавшегося running. В р.1.10 принято наблюдение идентичности executable: [результаты](PLAYER_RESULTS.md).

Ресурс защищён flock(LOCK_EX | LOCK_NB) на одном lock-файле текущей загрузки,
который не удаляется/заменяется во время работы. Проигрыватель наследует FD
через exec. До завершения возможного старого процесса нельзя делать LOCK_UN:
блокировка общая для унаследованных дескрипторов. Это координация schoolbell,
не запрет стороннему приложению открыть /dev/dsp.

После аварии новый владелец проверяет блокировку. Её захват допускает новую
работу при выполнении остальных условий, но не восстанавливает утраченный
результат. Старую неизвестную заявку не повторяем. Сборка неиспользуемых медиа
запрещена до восстановления ссылок и исключения старого проигрывателя.

Конкретная сборка madplay должна пройти проверки сохранения lock-FD и чтения
из stdin. При провале требуется согласование альтернативы до интеграции.
Эти свойства пока не проверены. Удерживаемая ревизия открывается относительно
доверенного каталога с проверкой компонентов без symlink и fstat regular file;
ребёнок получает открытый файл как stdin. Открытый FD не делает содержимое
неизменяемым: это обязанность менеджера опубликованных ревизий.

## API

```lua
handle, err = player.begin(request, media_handle, permit)
snapshot = player.poll(handle)
ok, err = player.release(handle)
```

Это согласованная форма внутреннего интерфейса, не готовый Lua binding
и не публичный API ядра. Точные поля и ошибки приняты в р.1.10: [результаты](PLAYER_RESULTS.md).

Begin подготавливает ресурс/файл и проверяет permit непосредственно перед
разрешением создания ребёнка. TTL не продлевается. Возвращается launching,
без ожидания exec или звука. Задержки файловых операций ОС не объявляются
жёстко ограниченным временем. Отказ с доказанным отсутствием ребёнка может
вернуть ошибку без handle. Если процесс возможен, его нельзя потерять за
таким отказом: сохраняется handle для наблюдения.

Poll делает один неблокирующий проход и возвращает снимок:

| Поле по смыслу | Значения/правило |
| --- | --- |
| Состояние | launching, running, terminal, uncertain |
| Подтверждение запуска | Отдельно: подтверждено, не состоялось либо неизвестно |
| Итог при наличии | not_started, exit с кодом, signal с номером, unknown |
| Идентичность | Поколение экземпляра + попытка; не только PID |
| Диагностика | Этап, errno, причина неопределённости |

Unknown не разрешает release, пока возможно исполнение. Подтверждённый exit
или signal позволяет terminal, даже если история exec неизвестна.
Повторный poll сохраняет итог до явного release. Release допускается после
подтверждённого завершения либо отказа без процесса; он не останавливает player.
Чужое/устаревшее поколение не может управлять новой попыткой. Cancel/stop активного
процесса в первой версии нет. Потеря владельца не даёт durable queue/exactly-once.

## Начальные параметры и оставшиеся решения

| Параметр | Принято |
| --- | --- |
| Подтверждение запуска | 2000 мс по монотонным часам от разрешения, настраиваемо |
| Истечение таймаута | uncertain, без повтора/освобождения |
| Автоматические повторы | 0 |
| stdout/stderr | /dev/null, хранение 0 байт |
| poll | Один неблокирующий проход за вызов |

Структурированные ошибки доступны без текстового вывода. Служебный канал exec
не является stdout/stderr. Квоты приняты в р.1.10: 64/64 для подготовки родителя/ребёнка, 8 для poll
и 8 для отдельного cleanup; лимит транспорта 4 syscall/endpoint сюда не переносится.
2000 мс — исходная настройка для проверки, не измеренная норма.

Кадр, поколения и диапазоны приняты в [р.1.11](PLAYER_WIRE.md). Открыты
системные часы/источник случайности, атомарность приёма с удержанием медиа и восстановление ссылок. Host-приёмка использует подменный процесс без
аудиоустройства. Target-сборка/реальный звук — отдельный согласуемый этап.

ТЗ schoolbell 1.12: изолированные Lua-кодек SBPE и модель API проигрывателя с подменяемыми операциями. 32 группы host-тестов: кадры, поколения, сроки/исходы, квоты и очистка. Без native binding, процессов, звука, ядра и изменений роутера; IPK прежний. [Player model](PLAYER_MODEL.md).
