# Загрузка мелодий — инженерный профиль

## Совместимость динамической медиатеки — 5.1.27

Динамические ID имеют вид `user_<hex>` (загрузка) или `userN` (импорт), не более 64 ASCII-символов. Старые `user1`–`user8` сохраняются. Штатные `test`, `0`–`4` неизменяемы. Номер строки списка — только отображение, не идентификатор.

Фрейминг `.sbb` остаётся `SBBACKUP1`, `.sbp` — `SBPLAN1`. Версия находится в манифесте: `schoolbell-backup/2` используется для расширенных ID или более восьми пользовательских мелодий; `schoolbell-plan/2` — для более восьми пользовательских зависимостей. Кодеки читают версии 1 и 2; старый читатель обязан отклонить неизвестную версию. Для совместимых малых наборов экспорт сохраняет версию 1. В версии 2 нет квоты числа медиа/файлов; сохраняются проверки ссылок, целостности, размера манифеста и архива. Pages создаёт планы только со штатными мелодиями; пользовательское аудио допустимо для предварительной проверки импорта, без загрузки на GitHub.

Это частичный этап общей файловой политики: кодирование A–P, число расписаний/диапазонов и внутренние бюджеты расчёта ещё требуют отдельной миграции.

Ниже описан прежний этап; при расхождениях действует новая заметка о совместимости выше.

Вкладка «Мелодии» содержит шесть защищённых штатных позиций test и 0–4 и восемь пользовательских user1–user8. API запрещает замену штатных; операция удаления отсутствует. Загружать и заменять можно только пользовательские позиции. Сначала отключите автозвонки. Ссылки черновиков на позицию сохраняются; следующий запуск получает новую ревизию. Это не миграция production-планов с закреплёнными ревизиями.

Авторизованный raw POST использует CSRF-заголовок, ожидаемое поколение и случайный ID операции 128 бит. Потоковый приём ограничен блоком 16 КиБ. MP3: до 512 КиБ и 60 секунд. Сканирование кадров и декодирование madplay в null предшествуют публикации, без звука. Успешный decoder exit не доказывает качество звучания. Общий замок исключает замену/GC одновременно с проигрыванием и включением автоматики. При неизвестном исходе decoder замок удерживается для административного восстановления, не удаляется по возрасту.

Готовый manager сохраняет immutable SHA-256 объекты в /etc/modbus-schoolbell/data, атомарные current/recovery и предыдущий снимок. Исходные комплектные файлы не меняются. Загрузка, удерживаемые объекты и копия должны поместиться в 2 МиБ с запасом max(512 КиБ,10% ёмкости ФС) и дополнительным местом для метаданных. Реальный диск может ограничить размер сильнее. Конфликт, обрыв, неверный MP3 и отказ допуска не меняют опубликованную библиотеку. Потерянный ответ сверяется по ID операции; unknown не означает отказ. Повреждение блокирует библиотеку без молчаливой подмены оригиналом.

Инженерный снимок содержит только замены медиа. Полные снимки настроек/календаря, backup/import, production FD leases и явное подтверждение fallback остаются впереди. Авария запроса может оставить общий замок: перед восстановлением требуется проверка процессов и хранения. Гарантии отключения питания нет. Прослушивание в браузере потоковое под тем же замком; публичное демо содержит только исходный test и не загружает файлы на роутер.

Тесты: test_mp3.lua, test_media_library.lua, test_media_http.lua и прежние 25 crash-точек менеджера. Host/target не заменяют power-loss опыт. Ядро, NTP и сеть не меняются.

Полоса места — снимок statvfs постоянного раздела, не ОЗУ. Отдельно показаны свободный системный запас и объём пользовательских объектов/удерживаемых копий против квоты 2 МиБ. Данные обновляются вместе со списком; свободное место само по себе не гарантирует допуск загрузки.

Пустая пользовательская позиция не проигрывается; активация плана с включённой строкой, использующей отсутствующий файл, отклоняется. Пять позиций не отменяют общую квоту/запас и не гарантируют приём пяти файлов максимального размера.
