# Возврат заводской прошивки TL-MR3020 EU v3.30

[English](SETUP_RECOVERY.en.md) · [Мастер](../tools/setup/README.md)

## Результат 09.11.2026

На отдельном EU v3.30 подтверждён возврат с OpenWrt 19.07.9 на TP-Link **1.8.0 0.9.1 v0001.0 Build 250625 Rel.56805n**. Приняты 8 126 464 байта, конечный ACK15873. После записи появились нормальная индикация и заводская Wi-Fi сеть; DHCP, ping и HTTP200 проверены по выделенному Ethernet. После отдельно разрешённого сброса владелец задал новый пароль и показал авторизованную Status с указанной версией и TL-MR3020 v3 00000003. Рабочее устройство не использовалось.

До опыта сохранены все семь MTD-разделов с совпадающими SHA256 на устройстве до/после чтения и на ПК, конфигурация и overlay. Составной образ 8 МиБ собран из неперекрывающихся boot/firmware/config/factory. Восстановление этих копий не проверялось; секретные дампы и логи не публикуются.

## Причина прежнего отказа

Неизменный OEM up_boot содержит внешний заголовок 512 байт, padded bootloader 128 КиБ и внутреннюю прошивку 0x7a0000 байт. Внутренний заголовок начинается по 0x20200. Установленный U-Boot побайтно совпал с загрузчиком OEM. Его recovery загружает файл в RAM 0x80060000 и копирует 0x7a0000 байт от 0x80080000 во flash от 0x20000, то есть пропускает ровно 128 КиБ. Поэтому исходный OEM-файл размещал заголовок/ядро на 512 байт позже. Полная TFTP-передача прежнего файла была подтверждена; это не был только сетевой отказ.

Рабочий recovery: **128 КиБ нулевого префикса + исходный внутренний образ от 0x20200**. Ядро, rootfs и поля внутреннего заголовка не изменяются, OEM-загрузчик в результат не включается. Область записи [0x20000,0x7c0000); boot, config и factory вне неё. Контрольная сумма исходного OEM и распаковка ядра проверены. Это правило применяется только к закреплённому исходнику, не как универсальное обрезание прошивок.

| Артефакт | SHA256 |
| --- | --- |
| OEM BIN Build250625 | `1141467bd4b7b8292e2a50811a388eb999f4cbf207365e1be47718ebc6143d2f` |
| Подготовленный recovery, 8 126 464 байта | `2b0d85b1c7f5e6c65930e117ada0afe60a29a35882ecac65610191876b6b0665` |

[Официальный архив TP-Link](https://static.tp-link.com/upload/firmware/2025/202507/20250714/TL-MR3020_3.0_1.7.0%20Build%20250625.zip) имеет имя 1.7.0, но вложенный BIN и работающий интерфейс показывают 1.8.0. Проверка строится по хешу, не по имени ZIP. [OpenWrt image recipe](https://github.com/openwrt/openwrt/blob/v19.07.9/target/linux/ramips/image/mt76x8.mk) и [структура заголовка](https://github.com/openwrt/openwrt/blob/v19.07.9/tools/firmware-utils/src/mktplinkfw2.c) использованы при разборе. Бинарники не входят в Git.

## Пароль и ограничения

Recovery и сброс настроек — разные действия. Прежняя форма Login после возврата не означала универсального пароля: config сохраняется. При забытом пароле отдельный сброс на уже включённом устройстве позволяет создать новый. Подробные шаги — в README мастера.

Аппаратно подтверждён образ и ручной Python-TFTP путь OpenWrt → OEM. Позднее 09.11.2026 маршрут Setup.ps1 -RestoreFactory прошёл аппаратную приёмку в PowerShell 7: загрузка, вход без нового сброса, версия и очистка сети подтверждены; см. [протокол](acceptance/ACCEPTANCE_RUN.md). Оболочка Setup.cmd отдельно не проверялась. OEM → OEM Build250625 также проверен 09.11.2026: вход прежним паролем без сброса, версия и очистка сети подтверждены. Полная проверка всех функций OEM не выполнялась. Обратный переход OEM → OpenWrt и установка Школьника 5.1.123 из PowerShell 7 подтверждены позже 09.11.2026; см. [протокол](acceptance/ACCEPTANCE_RUN.md). Побайтовая сохранность защищённых разделов после записи не проверена. В первом опыте с образом config намеренно сброшен; последующая проверка мастера дополнительного сброса не потребовала. Исторического UART/дампа неудачной записи нет, поэтому точная стадия старого сбоя не установлена. Временная недоступность HTTP после записи не получила доказанного объяснения.
