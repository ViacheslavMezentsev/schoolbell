# Подпись контрольных сумм выпуска

[English](RELEASE_SIGNATURES.en.md) · [Подготовка выпуска](RELEASING.md)

Используется существующий Ed25519-ключ подписи через Windows OpenSSH и его агент. Новый ключ не создаётся; закрытый ключ не переносится в WSL, CI или релиз. Формат — SSHSIG, namespace и identity `schoolbell-release`, файл `SHA256SUMS.sig`.

Отпечаток [публичного ключа](../packaging/release/signing-key.pub): `SHA256:ekq3AjehBO2o+e63uOrpGLLKjmHc7kjnPZhIkgzLT88`. [Пользовательская инструкция проверки](../packaging/release/VERIFY.md) и allowed-signers доступны в репозитории по ссылкам из описания релиза. Отпечаток сверяется с доверенной копией репозитория: ключ из того же скачивания сам по себе не удостоверяет издателя.

После скачивания принятой пары Actions проверьте происхождение и состав. Из репозитория в Windows выполните (Python 3 либо `python/python.exe` распакованного мастера):

```powershell
python scripts/release-signatures.py sign --directory 'КАТАЛОГ-ФАЙЛОВ-ВЫПУСКА' --signing-key (git config user.signingkey)
python scripts/release-signatures.py verify --directory 'КАТАЛОГ-ФАЙЛОВ-ВЫПУСКА'
```

Команда принимает настроенный `.pub` только при совпадении с ключом проекта, проверяет суммы перед подписью и затем проверяет созданную подпись. Существующая подпись не перезаписывается. При отказе агента нужно восстановить доступ к существующему ключу, не создавать замену. Команда не загружает файлы и не создаёт тег/релиз.

Окончательные суммы подписываются после проверки именно скачанных артефактов. Подпись локального пробного комплекта не является подписью окончательного GitHub-выпуска. Для публичного набора из двух ZIP сформируйте новый список сумм и отдельно приложите его подпись; не публикуйте старый список сумм полного технического набора. Итоговые хеши и приёмку фиксируйте отдельно: подпись не означает аппаратную проверку или Authenticode.
