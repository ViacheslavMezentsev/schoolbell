# Сквозная приёмка «Школьника» на новом устройстве

[English](ACCEPTANCE_RUN.en.md) · [Программа AC-01–12](ACCEPTANCE.md) · [Поставка](../architecture/PACKAGING.md) · [Руководство](../user/USER_GUIDE.md)

31.10.2026. План проведения и шаблон протокола, **не акт приёмки**.
Текущий кандидат приложения — 5.1.22. Версия прошивки нового устройства и полный
набор артефактов ещё не зафиксированы. Здесь не меняются ТЗ или критерии AC.
Сейчас разрешена подготовка документов, не прошивка, звук, включение автоматики,
изменение часов/NTP, сети или отключение питания.

## 1. Что принимаем

Первый предлагаемый профиль: новое TP-Link TL-MR3020 EU v3.30, совместимый
автономный комплект и обслуживаемый запуск. После питания сотрудник проверяет
достоверность времени и включает применённый план; затем браузер не нужен.
Это предложение Q5 программы, а не молчаливо утверждённое исключение из ТЗ.
Необслуживаемое возобновление после питания требует отдельного профиля и
доверенного источника времени (например, будущего внешнего RTC).

Планировать расписание можно на сентябрь–май и через границы лет. Недельный
прогон не доказывает точность автономных часов на весь учебный сезон, работу
при летних температурах или безотказность на годы. Сетевая наблюдаемость не
равна проверке без Интернета; отключение Интернета и восстановление питания
проверяются отдельно. Демо Pages не заменяет устройство или акустическое наблюдение.

До начала приёмки владелец согласует Q1–Q5 из ACCEPTANCE.md: численные пределы
начала/остановки звука, длительность/нагрузку, ресурсные запасы и погрешность часов,
политику совпадающих звонков, профиль и явный список отложенных требований.
Предложенные ранее +1 с/1 с остаются предложениями. Без предела и измерительного
метода соответствующая строка не может получить ПРОЙДЕН.

## 2. Рабочее место и граница сетевого стенда

Ноутбук сохраняет основное подключение с его адресами, DHCP, DNS и маршрутами.
Отдельный USB–Ethernet адаптер выделяется под новый MR3020. До действий записать
его имя, индекс, MAC, текущую конфигурацию и способ восстановления **локально**;
проверить соответствие физическому разъёму отключением только стендового кабеля.
Не выбирать интерфейс по первому элементу списка. На основном интерфейсе ничего
не перенастраивать; не включать ICS, сетевой мост и дополнительный DHCP.

Для будущего прямого подключения адрес назначается только выделенному адаптеру,
после выбора процедуры и проверки отсутствия пересечения подсетей. Не задавать ему
шлюз/DNS без необходимости. При конфликте маршрутов сначала согласовать схему,
не исправлять основной интерфейс. VPN/брандмауэр не отключать целиком.
TFTP при необходимости привязать к нужному адаптеру; правило брандмауэра ограничить
стендом и удалить после опыта. Наличие USB-карты само по себе не гарантирует
отсутствия маршрутного конфликта.

До прошивки подготовить: надёжное питание, Ethernet-кабель, проверенный образ для
точной ревизии и сценария установки, официальные контрольные суммы, резервную
копию заводских настроек, совместимый образ/инструменты восстановления и понятный
путь первого входа после OpenWrt. Factory, sysupgrade и recovery не взаимозаменяемы;
точные имена, адреса, кнопки и процедура проверяются по официальным материалам
перед отдельным шагом прошивки. Не использовать догадки из инструкции другой ревизии.
Текущий пароль, MAC/серийник, фотографии наклейки и резервные копии не публиковать.
Старое рабочее устройство не является целью прошивки или сетевой перенастройки.

## 3. Паспорт неизменного комплекта

Заполненный паспорт и доказательства хранятся локально в отдельной паре
`docs/research/NN-schoolbell-acceptance/` и `tests/manual/NN-schoolbell-acceptance/`.
Публичный репозиторий содержит только шаблон и обезличенное резюме.

| Поле | Что фиксировать перед первым тестом |
| --- | --- |
| Run ID / профиль | Уникальный номер, оператор, дата/TZ, согласованные Q1–Q5, исключения и разрешения |
| Устройство | Модель, EU/ревизия, локальный идентификатор; не путать с прежним стендом |
| Исходное состояние | Заводская версия, способ доступа, backup с SHA; это не полный дамп flash |
| OpenWrt | Версия, build, target/subtarget, архитектура, kernel и полная ABI, libc/Lua/LuCI; точный файл образа, тип, источник, размер, SHA-256, результат проверки подлинности |
| Исходники | Полный commit, чистое дерево, CI run и точный headSha; патчи/dirty не скрывать |
| Пакеты | Ядро и «Школьник»: Name/Version/Architecture и точные IPK; нативные часы, madplay, драйверы и транзитивные зависимости — каждый отдельно |
| Комплект | manifest, SHA256SUMS, автономный архив, инструкции и rollback: имя, байты, SHA; замкнутость зависимостей и соответствие kernel ABI |
| Pages | URL, commit и дата сборки; версия формата .sbp и штатного набора мелодий |
| Данные испытаний | .sbp/.sbb, MP3, независимый эталон событий, TZ, настройки громкости/звука и лимиты; SHA каждого файла |
| Периферия | Аудиокарта/хаб/питание/колонки/накопитель, браузеры/ОС, схема кабелей |
| Измерения | Средство наблюдения звука, часы отсчёта, точность, частота опросов, версия сборщика и место хранения |

Для каждой строки файла: `role, filename, size_bytes, sha256, source, version,
architecture, verification`. Не подставлять SHA из памяти. Проверить скачанный
файл и копию перед установкой. `Architecture: all` не отменяет ABI зависимостей;
manifest/SHA256SUMS сами по себе не являются цифровой подписью релиза.
Итоговый набор утверждается до прошивки/установки, а не задним числом по успеху тестов.

Изменение IPK, прошивки, драйвера, данных эталона или значимой конфигурации создаёт
новую редакцию паспорта. Старые результаты сохраняются; отмечается, какие AC надо
повторить. Изменение исполнителя/часов/хранения прерывает сравнительный прогон:
после исправления начать новый полный срок, не складывать разные версии и boot-эпохи.

## 4. Последовательность этапов

Каждый этап: предусловия → разрешение на его воздействие → шаги → доказательства →
проверка конечного состояния. Пропущенный этап не считается успешным.

| Этап / AC | Действия и доказательство завершения |
| --- | --- |
| S0 / I | Паспорт, Q1–Q5, схема USB–Ethernet, выбранные образы и восстановление; все незаполненные поля явно помечены. Только подготовка. |
| S1 / AC-01 | После отдельного разрешения: заводской backup, прошивка нового устройства, первый вход, пароль и проверка версии/ABI. Документировать фактические шаги и восстановление сети адаптера. Не переносить настройки старого устройства вслепую. |
| S2 / AC-01/09 | Чистая установка из замкнутого автономного комплекта без скачивания зависимостей на устройстве; контроль свободного места, opkg, SHA payload, служб и auto-off. Сохранить исходный snapshot для отката. |
| S3 / AC-02/06/10 | Вход/выход/истечение сеанса, сохранение правок, первая настройка времени/TZ и доверия по отдельному разрешению; корректные предупреждения. Пока auto-off. Подтверждение времени не равно установке часов. |
| S4 / AC-02/03/04/07/08/10 | Через настоящий LuCI: планы сентябрь–май, граница года/високосный день, раскраска, тихие даты, черновик/активная копия. .sbp Pages → устройство; device user MP3 → экспорт → пустой приёмник, preview/conflicts; .sbb backup/restore. Сравнить содержимое, связи и SHA, не только сообщение успеха. Проверить восемь слотов в общей квоте, защиту штатных и отказы. |
| S5 / AC-03–05 | Разрешённые звук/автоматика, приглушённая громкость: независимый эталон рабочего дня (15 основных + 6 предварительных событий), ручной/тестовый звонок, «Без звука», включение ранее применённого плана, отсутствие догоняющих/дублирующих звонков, перекрытия и отказы. Измерить фактический звук и остановку с погрешностью. После коротких опытов auto-off. |
| S6 / AC-06/09/10/11 | Отдельно разрешённые обрыв сети, закрытый браузер, offline, reboot/холодный старт, аудиоотказ, обновление/откат с backup и физический сбой записи. По сценарию сохранить старую/новую целую копию либо явную блокировку, без автоматического запуска. Реальное питание и перестановка часов не заменяются тестом в моках. |
| S7 / AC-11/12 | Только после устранения блокирующих дефектов: отдельное разрешение непрерывного автоматического прогона не менее 7×24 часов, согласованные звуковые окна и эталон. Собрать полное покрытие и состояние, затем выключить автозвонки и проверить данные. |
| S8 / AC-01–12 | Закрыть каждую обязательную строку и паритет со «Школьник-4», сверить руководство, дефекты и ограничения. Подписать решение владельца для точного комплекта и профиля; выпуск/публикация отдельно. |

Нереализованная установка часов из браузера, системные события, внешний RTC или
другие пробелы не получают ПРОЙДЕН за наличие похожей функции. Их либо реализуют
и проверяют, либо владелец явно ограничивает первый профиль; полный паритет тогда
не объявляется. Набор известных пробелов сверяется с текущим кодом перед S0.

## 5. Недельный прогон

До старта зафиксировать UTC и местные start/end, TZ, период опроса (предложение:
60 с), ожидаемое число снимков с seq, поведение при пропуске связи и порог
устаревания (предложение: три периода). Утвердить запас места на наблюдающем ПК,
ресурсные пределы устройства и срок хранения. На устройстве журнал ограничен и
ротируется: копировать новые записи достаточно часто, чтобы не потерять события;
не расширять журнал без отдельной необходимости. Сам монитор не должен создавать
существенную нагрузку или писать частые измерения во flash.

Собирать boot ID, uptime, версию, состояние/применённую ревизию, доверие времени,
очередь и исходы команд, PID/starttime/FD/RSS/CPU, flash/tmp и журнал. Эталон событий
создать независимым расчётом до запуска, включая ожидаемые подавления; для каждого
события сопоставить ожидание, выдачу заявки, запуск/завершение процесса и акустическое
свидетельство там, где заявляется факт звука. Exit 0 не доказывает слышимый звонок.
Разрыв наблюдения отмечается НЕ ПРОВЕРЕН, а не отсутствием ошибок.

Предложение графика: первый день — контрольный рабочий день; остальные дни — обычная
нагрузка, отдельная тихая дата и заранее согласованные переключения режима.
Сетевой и offline-интервалы обозначить отдельно. Не двигать часы, чтобы ускорить
календарные границы: их проверять независимыми host-тестами и отдельно описанными
стендовыми датами. Измерение ухода часов — отдельный опыт; поправку не применять
в ходе этого прогона без новой редакции условий.

Мониторинг запускать только после утверждения паспорта, времени и доступа. При
штатной работе молчать; уведомлять о значимом сбое, необходимости действия и
завершении. Не повторять закончившийся сбор, не перезапускать службы автоматически.
При блокирующем дефекте сохранить факты и следовать заранее согласованному безопасному
останову. По окончании отключить монитор, удалить только собственные временные средства.

## 6. Шаблон заполненного протокола

Для каждой проверки записать:

- `Run ID / редакция паспорта / S / AC / подсценарий / дата UTC и местная / оператор`;
- предусловия, разрешение, версии и SHA, backup/rollback, точные действия;
- независимое ожидание, фактический результат, способ измерения и погрешность;
- ссылки на локальные доказательства, дефекты и повторные проверки;
- ПРОЙДЕН / НЕ ПРОЙДЕН / НЕ ПРОВЕРЕН и конечное состояние.

Таблица решения содержит все AC-01–12; частичный успех не закрывает целую строку.
Обязательный НЕ ПРОВЕРЕН или блокирующий дефект запрещает приёмочный PASS.
Итог: точный комплект, профиль, разрешённое применение, ограничения, нерешённые
вопросы, дата и решение владельца. После завершения сохранить auto-off, целые данные,
отсутствие тестовых проигрывателей и восстановленную конфигурацию стендового адаптера.
