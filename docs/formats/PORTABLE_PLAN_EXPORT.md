# Сборка экспортируемого .sbp

[English](PORTABLE_PLAN_EXPORT.en.md) · [Формат](PORTABLE_PLAN_WIRE.md) · [Предварительный импорт](PORTABLE_PLAN_PREVIEW.md)

Изолированные export.lua/export.js в packages/schoolbell/portable-plan реализуют
сборку выбранных календарных планов. ТЗ 1.69, TC-177, 29.10.2026. Код не входит
в IPK, LuCI или Pages; версия установленного пакета остаётся 5.1.18.

## Вход и выбор зависимостей

Снимок содержит ровно draft, selected, timezone, media, exporter:

- draft — текущая модель черновика, прошедшая штатную валидацию, до 12 КиБ;
- selected — от 1 до 8 уникальных ID выбранных планов; неизвестный ID — отказ;
- timezone — объект name/posix; exporter — name/version по wire-контракту;
- media — до 14 объектов id/title/size_bytes/sha256 установленного каталога.

Весь снимок проходит строгий JSON до 16 КиБ, 4096 узлов и глубины 8.
Он копируется до вызова внешних функций; исходные данные не изменяются.
Выходной порядок планов и расписаний сохраняет порядок черновика, независимо
от порядка selected. Старые записи year преобразуются в range с ID year-YYYY,
именем «План YYYY» и полным годом. Отсутствующий color назначается как в UI:
индекс расписания в исходном черновике по модулю 16, считая с 1.

Включаются все schedule_ids выбранных планов, даже если соответствующие символы
не встречаются в days. Мелодии берутся из всех строк, включая отключённые, и
pre_media всегда. Режим, fixed_schedule, manual_media и системные настройки
не экспортируются; зависимость только ручного звонка не добавляется.
Недостающая используемая мелодия — отказ, без подстановки тестового звонка.

Каталог упорядочен test, 0…4, user1…user8. ID слота становится локальным ID
архива; импорт впоследствии переназначает его. Штатные файлы не вкладываются.
Пользовательские payload объединяются по SHA, разные названия остаются отдельными
записями media. Одинаковый SHA с разными размерами отвергается. Для общего payload
читается первый слот в указанном порядке. Файлы media/<sha>.mp3 идут по SHA.
Экспортёр schoolbell-pages отвергает выбранные пользовательские зависимости;
посторонние мелодии, не связанные с выбранными планами, в архив не попадают.

## API и владение

`prepare(snapshot, hashFactory)` в JS асинхронно возвращает manifest/calendar
как Uint8Array и sources: список name/slot/size_bytes/sha256. В Lua
`prepare(snapshot)` возвращает те же метаданные строками; SHA метаданных считает
существующий media_codec. Это подготовка, а не проверка аудиобайтов.

`encode(snapshot, sourceFor, hashFactory, emit)` собирает полный контейнер через
существующий потоковый кодек и возвращает число байт только при успехе.
В JS результат — Promise. sourceFor(slot, metadata) возвращает источник блоков
до 16384 байт с EOF null в JS / nil в Lua. hashFactory даёт update/finish;
emit получает выходные блоки. Возврат false или исключение callback прекращают
работу. Контракт потока и пределы — в [описании кодека](PORTABLE_PLAN_CODEC.md).

Источник должен удерживать соответствующую ревизию медиа до окончания/ошибки.
В этом слое нет файловых дескрипторов или блокировок: закрытие источников и
освобождение удержаний всегда выполняет вызывающий адаптер, включая ошибки.
Данные пользователя не накапливаются целиком; размер и SHA проверяются при
передаче. Изменённый, усечённый или удлинённый источник отвергается.
Все выданные байты предварительные: при любой ошибке получатель обязан удалить
частичный результат и не выдавать его за готовый .sbp. Сам emit не публикует файл.

Каноническая сериализация сортирует ключи, экранирует управляющие символы,
кавычки и обратный слеш через Unicode escape; итоговые Lua/JS байты совпадают.
Действуют ограничения wire: calendar 12 КиБ, manifest 16 КиБ, один MP3 512 КиБ,
сумма уникальных MP3 2 МиБ, общий контейнер до 2125906 байт.

## Проверки и ограничения

35 общих сценариев test-export.py запускают обе реализации. Независимый Python
строит ожидаемые байты контейнера; каждый успешный результат повторно читается
кодеком и передаётся preview. Проверяются выбор части/нескольких планов, старый
год и граница года, тихий план, неиспользуемые schedule_ids, отключённые строки,
предзвонок, цвета, Unicode, одинаковые payload с разными именами, предельные
размеры, отсутствие зависимостей и ошибки открытия/чтения/выдачи потока.
Снимок должен оставаться неизменным; ранний отказ не выдаёт выходных байтов.
Тест включён в make test-schoolbell / make all. Аудиобайты синтетические;
проверки проигрывания и валидности MP3 этим не подтверждаются.

Адаптер ещё должен получить согласованные снимки и удержать ревизии, проверить
штатную поставку, закреплённую зону и MP3/длительность, обеспечить отмену и
очистку временных файлов. Проверки реального RSS и ресурсов устройства остаются
отдельным этапом. UI должен явно показывать экспорт несохранённого черновика.
Следующий этап — подключение экспорта и предварительного импорта в Pages,
затем системный допуск/фиксация на устройстве. Автозвонки не включаются.
