# Импорт календарного плана на устройство

[English](PORTABLE_PLAN_IMPORT.en.md) · [Формат](PORTABLE_PLAN_WIRE.md)

Кандидат **5.1.20**, проверка на хосте. Установленная5.1.19 не менялась.
Это добавление в сохранённый черновик, не восстановление резервной копии.

## Маршрут

1. Сохранить или явно отменить собственные правки; выключить автозвонки.
2. «Календарь → Импорт календарного плана .sbp → Загрузить для проверки».
3. Проверить диапазоны и импортируемые имена. При совпадении имён изменить
   только имена новых планов/расписаний; нажать «Проверить добавление».
4. Проверить состав, мелодии, часовой пояс, предзвонок и запас места.
5. «Добавить в черновик». После committed редактор перечитывает сохранённые данные.
   Применённая копия остаётся прежней, автозвонки остаются выключенными.

При потере ответа нажать «Проверить состояние». Не повторять upload/commit вслепую.
При recovery_required доступно продолжение **той же** операции. Не удалять файлы
pending, staging или замки вручную. Неожиданное изменение данных блокирует resume.
До intent можно отменить импорт; после intent — только завершить его восстановлением.

## Проверки и хранение

Повторно используются строгий SBPLAN1-кодек, общий preview и менеджер медиатеки.
Проверяются все ссылки, включая отключённые строки, точные штатные SHA/размеры,
пользовательские MP3, свободные user1–user8, зона name/posix, пересечения и имена,
параметры предзвонка и итоговые лимиты черновика. Код из комплекта не исполняется.
MP3 проверяется декодированием в null, без аудиоустройства.

Upload и proof хранятся в частном /tmp/schoolbell-plan-import. Только одна операция;
preview15мин, неактивность30мин, monotonic/boot; GET не продлевает срок.
Под замками player → editor → media повторно проверяются ревизии и выключенная
автоматика. Новые объекты копируются в постоянный import-stage, затем фиксируется
проверяемый import.pending. После него обычный доступ заблокирован, пока не
опубликованы каталог и черновик, проверены хеши/ревизии и записан committed receipt.
Хранятся последние16 receipts. Существующие мелодии, настройки звука и применённый
план не заменяются. Обновление IPK отказывается начинаться при import.pending.

Расчёт свободного места консервативный: две копии нового аудио, метаданные,
полный бюджет16 receipts и служебный резерв. На больших host-разделах отображаемые
free/reserve ограничены2147483647байт с capped=true; admission использует полные
числа, поэтому это не обход проверки места. На MR3020 эти значения обычно ниже.

## HTTP

Все действия используют существующую административную сессию LuCI:
`plan-import?action=upload|preview|commit|status|cancel|resume&operation_id=...`.
GET разрешён только для status. POST проверяет Bearer с CSRF-токеном LuCI **до**
чтения тела. Upload — multipart с единственным file; остальные POST — ограниченный
JSON. Content-Length обязателен; chunked без длины отвергается. Контейнер ограничен
2125906байт независимо от multipart; HTTP-обёртка имеет отдельный запас8192байта.
Запись не повторяется автоматически после HTTP-ошибки.

## Граница проверки

- TC-180: реальная файловая система хоста, добавление с пользовательским MP3,
  сохранение старых объектов, повторный receipt, конфликт/expiry, повреждённые файлы;
  прерывания крупных этапов и до/после57 файловых операций write/sync/rename/copy.
- Системный gateway на host-FS с подменёнными nixio/часовым поясом/декодером;
  HTTP авторизация, размеры и действия; UI preview/dirty/revision/unknown outcome.
- Pages сохраняет экспорт и **предварительный импорт без записи** со штатными
  мелодиями. Устройство принимает также пользовательские MP3. Device UI не попадает
  в Pages и не обращается к оборудованию из демо.

До установки отдельно проверить на целевом LuCI multipart, живые таймауты сервера,
пиковые RSS/tmp/flash и длительность декодирования. Ограничения времени в callback
не являются доказательством прерывания заблокированного чтения сокета: нужно сверить
network/script timeout uhttpd с пределами60/300с. Эти аппаратные пункты остаются
открытыми; новый пакет пока не устанавливался. Физическое отключение питания,
звук, включение автоматики и настройка времени этим этапом не разрешены.

Следующий этап: целевая проверка после резервной копии и отдельного разрешения;
затем экспорт устройства с пользовательскими мелодиями и сквозной перенос.
