# Резервная копия schoolbell

## Совместимость динамической медиатеки — 5.1.27

Динамические ID имеют вид `user_<hex>` (загрузка) или `userN` (импорт), не более 64 ASCII-символов. Старые `user1`–`user8` сохраняются. Штатные `test`, `0`–`4` неизменяемы. Номер строки списка — только отображение, не идентификатор.

Фрейминг `.sbb` остаётся `SBBACKUP1`, `.sbp` — `SBPLAN1`. Версия находится в манифесте: `schoolbell-backup/2` используется для расширенных ID или более восьми пользовательских мелодий; `schoolbell-plan/2` — для более восьми пользовательских зависимостей. Кодеки читают версии 1 и 2; старый читатель обязан отклонить неизвестную версию. Для совместимых малых наборов экспорт сохраняет версию 1. В версии 2 нет квоты числа медиа/файлов; сохраняются проверки ссылок, целостности, размера манифеста и архива. Pages создаёт планы только со штатными мелодиями; пользовательское аудио допустимо для предварительной проверки импорта, без загрузки на GitHub.

Это частичный этап общей файловой политики: кодирование A–P, число расписаний/диапазонов и внутренние бюджеты расчёта ещё требуют отдельной миграции.

Ниже описан прежний этап; при расхождениях действует новая заметка о совместимости выше.

Версия 5.1.0 также сохраняет/восстанавливает именованные календарные диапазоны. Старый годовой payload остаётся читаемым без изменения checksum. Для отката на модуль до 5.1.0 используйте копию до миграции: старый модуль новые диапазоны не понимает. Переносимый комплект планов Pages — отдельная будущая функция, не этот полный backup.

[English](BACKUP.en.md)

Инженерный интерфейс 5.0.14: «Настройки → Резервная копия». Отключите автозвонки и сохраните правки редактора, затем скачайте `.sbb`. Копия содержит сохранённый черновик (настройки, расписания и назначения годов), Mute/громкость и текущие user1–user8 с названиями/MP3. Штатные мелодии защищены и остаются частью установки. Журнал, активное разрешение звонков, сеть, пароли, часы и NTP не копируются.

Для переноса на другое устройство установите совместимую версию модуля и штатные мелодии, настройте тот же часовой пояс. Загрузите файл копии и подтвердите замену. Восстановление заменяет весь сохранённый план и пользовательскую медиатеку; это не слияние. После успеха страница перечитывается, **автозвонки выключены**. Проверьте план, местное время и аудиовыход, затем включите вручную при необходимости. Это backup устройства, не отдельный шаблон партии.

Формат schoolbell-backup/1: `SBBACKUP1\n`, восемь десятичных цифр длины manifest и LF, 64 hex SHA-256 manifest и LF, JSON manifest, затем файлы по порядку manifest без разделителей. Первые три файла — draft.json, controls.json, catalog.json; далее уникальные SHA256.mp3. Manifest содержит format, timezone (точное содержимое /tmp/TZ), files[{name,size_bytes,sha256}]. SHA-256 обнаруживает повреждение, но не является цифровой подписью: используйте доверенные копии.

Общий предел — 2162816 байт; manifest и каждый JSON до 16 КиБ, восемь MP3 до 512 КиБ/60 секунд каждый. Действует совместная квота медиатеки 2 МиБ, включая staged/удерживаемые объекты и копирование. Свободный запас — max(512 КиБ,10% раздела), плюс временные метаданные. Восемь позиций не гарантируют размещение восьми максимальных файлов. Аудио поступает блоками до 16 КиБ; внутренний буфер может временно содержать два блока. Неверный файл/часовой пояс/ссылки/место отклоняются до изменения настроек. Madplay проверяет MP3 через null без звука.

Порядок: общий замок проигрывателя → замок редактора → замок медиатеки. После полной проверки staged-файлов сохраняется restore.pending; дальше автоoff, публикация медиатеки, черновик, Mute/громкость, проверка, receipt и удаление маркера. Пока маркер существует, обычная работа блокируется. Нажмите «Проверить состояние» и «Продолжить прерванное восстановление». Процесс не выполняет автоматический rollback. Не удаляйте маркер/стадию вручную.

Если процесс был аварийно завершён и оставил общий player gate, продолжение может вернуть «занято». Разработчик должен проверить отсутствие принадлежащего модулю проигрывателя и исход операции перед снятием замка; возраст замка недостаточен. Повреждённая стадия требует отдельного разбора и проверенной копии. После потери HTTP-ответа сначала проверьте состояние и сохранённые данные, не повторяйте импорт вслепую. Последняя операция хранится в restore-last.json.

Host-проверки покрывают повреждение, усечение, лишние данные, обход пути, несовпадение зоны, замену существующей библиотеки и прерывания на границах фиксации. Изолированная проверка на роутере не означает тест физического отключения питания. Production-привязка активных планов к ревизиям/FD leases остаётся отдельным этапом.

При обновлении инженерной установки выполните на роутере `sh invalidate-cache.sh` из каталога исходников router-page (передайте скрипт через SSH): он очищает только временный байткод schoolbell/его контроллера и индекс маршрутов LuCI. Иначе LuCI может использовать старый API при новой странице. Потоковый HTTP использует yield-совместимые защищённые вызовы Lua 5.1; это проверяется отдельно от обычного файлового экспорта.
