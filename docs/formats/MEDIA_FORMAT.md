# Каталог, квоты и фиксация медиатеки

Принятый контракт ТЗ 1.18: 3.5.28–3.5.41, 5.3; [English](MEDIA_FORMAT.en.md).
Только требования. Код, UI, IPK, аудиоустройство и роутер не изменены.

## Каталог

Строгий JSON штатным декодером: повторяющиеся ключи, неизвестные поля и
произвольные пути отклоняются. Запись мелодии содержит id, name, revisions.
Запись ревизии содержит revision, source, size_bytes, audio; audio содержит
format, duration_ms, sample_rate_hz, channels. Revision — 64 hex символа SHA-256
точных байтов файла, без отдельного дублирующего поля хеша. Source — bundled
либо user, format — mp3. Размер и audio устанавливает проверяющий модуль,
не браузер. Расписание ссылается на id + revision. Одинаковые байты допускают
один общий неизменяемый файл. Имя для пользователя не является путём.

Версия внутреннего формата одна, в служебном описании комплекта, вне настроек.
Её численное значение и точные оболочки/границы полей ещё не назначены.

## Размещение

```text
/etc/modbus-schoolbell/data/
  objects/       пользовательские неизменяемые MP3
  snapshots/     неизменяемые комплекты метаданных
  staging/       загрузка и подготовка
  current.json   текущий и предыдущий снимки
  recovery.json  сохранённый указатель для восстановления
```

Штатные файлы остаются в /usr/share/modbus-schoolbell/melodies. Изменяемые части
транзакции находятся на одной ФС. Путь вычисляет пакет. Снимок связывает каталог,
настройки, расписания и планы; служебное описание перечисляет фиксированные имена,
размеры и SHA-256 файлов. Смешивать снимки нельзя. Current содержит ссылки на
текущий/предыдущий снимки, хеши описаний и целое служебное поколение, не часы RTC.

## Начальные защитные квоты

| Параметр | Предел |
| --- | --- |
| Мелодии / ревизии одного каталога | 32 / 64 суммарно |
| Пользовательский MP3 | 512 КиБ; 60 секунд |
| Пользовательские MP3 вместе со старыми удерживаемыми и загрузкой | 2 МиБ |
| catalog.json | 64 КиБ |
| Все JSON одного снимка, включая описание | 256 КиБ |
| Потоковый буфер загрузки | 16 КиБ |
| Одновременные загрузки/изменения | 1 |
| Свободный запас после расчётного пика | max(512 КиБ, 10% ёмкости постоянного раздела) |

КиБ = 1024 байта, МиБ = 1048576 байт. Общий объект считается один раз по
физическому файлу; дополнительные копии и незавершённая загрузка занимают место.
Метаданные, временные данные и откат учитываются сверх объёма MP3 в расчёте пика.
Квоты не обещают наличия места: допустимый размер может быть меньше. ENOSPC
возможен и после предварительной проверки. RAM Lua/JSON/MP3 и FD надо измерить;
16 lifetime публикаций native-прототипа потребуется адаптировать с сохранением
живых удержаний. Ограничение буфера не ограничивает всю память процесса.

## Порядок фиксации

1. Исключительное владение изменениями и сверка ожидаемого поколения; иначе conflict.
2. Ограниченный потоковый приём, проверка MP3/длительности/совместимости.
3. Сохранение объекта и синхронизация файла/каталога.
4. Подготовка полного снимка, проверка ссылок/хешей, синхронизация файлов/каталогов.
5. Проверенная копия прежнего current в recovery с подтверждённой постоянной записью.
6. Временный новый указатель: текущий = новый, предыдущий = прежний текущий.
   Запись, синхронизация файла, rename поверх current, синхронизация родителя.
7. Только теперь saved. Очистка отдельно; её ошибка не отменяет коммит.

На пике могут потребоваться три поколения: новое, текущее, прежний откат.
До освобождения ссылок recovery его объекты не удаляются. После безопасной
очистки остаются текущий и один предыдущий комплект плюс объекты, необходимые
другим сохранённым планам/живым удержаниям. Точный переход recovery перед GC
ещё нужно определить; нельзя удалять файлы, на которые он продолжает ссылаться.

| Результат | Значение |
| --- | --- |
| saved | Постоянная фиксация подтверждена |
| rejected | Изменение не опубликовано |
| conflict | Изменилось ожидаемое поколение |
| needs_recovery | Исход фиксации нельзя надёжно установить |

ID операции сохраняется в описании снимка. Потерянный ответ сначала сверяется
по ID; неизвестный/очищенный ID не доказывает отказ. Это не бессрочный журнал
идемпотентности и не разрешение слепого повтора.

Восстановление проверяет current и весь комплект, затем при повреждении —
проверенные сведения recovery. Выбор «новейшего» каталога по имени/времени
запрещён. Fallback оставляет звонки на паузе; недостоверность — режим восстановления.
Незавершённая загрузка не активируется, старая очередь не повторяется.

## Оставшиеся решения и проверка

8.2.12: точные указатели/описания и проверка их целостности; диапазоны/ID;
первичное создание; безопасная замена recovery и аварийные переходы; сверка,
срок хранения результата и GC; оболочка каталога, схемы настроек/планов;
валидатор MP3, права/API, поддерживаемые ФС, расчёт доступности и округления
запаса. Пригодность ФС/носителя не следует из успешного rename на хосте.
TC-83–90 плановые: структура, размещение, границы, пик/ресурсы, конфликты,
каждый шаг фиксации, потеря ответа и восстановление/очистка. Аппаратные проверки
питания согласуются отдельно. [Предыдущая политика](../architecture/MEDIA_PERSISTENCE.md).
