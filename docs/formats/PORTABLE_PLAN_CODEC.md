# Изолированный кодек .sbp

Календарная модель следующего слоя теперь реализована отдельно: [preview](PORTABLE_PLAN_PREVIEW.md). Сам кодек сохраняет прежнюю границу проверки.

[English](PORTABLE_PLAN_CODEC.en.md) · [Принятый формат](PORTABLE_PLAN_WIRE.md)

Этап ТЗ1.67, TC-175. Исходники находятся в `packages/schoolbell/portable-plan/`:
`codec.lua`, `codec.js`, общий `fixture.json` и независимый `test.py` с runners
`test.lua`/`test.js`. Изначально проверялись изолированно; теперь JS включён в Pages, Lua — в кандидат IPK5.1.20. [Граница системного импорта](PORTABLE_PLAN_IMPORT.md). Установленная5.1.19 не меняется.

## Граница проверки

Кодек проверяет SBPLAN1 framing, размеры, SHA manifest и каждого payload, строгий
JSON manifest, его поля/типы, уникальные ID/файлы, допустимые пути, порядок файлов,
каталожные ссылки user→file и отсутствие файлов без каталожных ссылок.
`calendar.json` пока проверяется только как ограниченный строгий JSON.

Результат `admitted=false` означает: байтовый контейнер разобран, но сохранять его
нельзя. Следующий слой ещё должен проверить модель календаря и достижимость всех
мелодий из строк/предзвонка, штатные хеши установленной поставки, реальную зону,
MP3/длительность, конфликты с текущими данными, квоты и разрешение операции.
В корпусе есть синтетические аудиобайты, которые не являются допустимыми MP3.

JSON использует лимиты существующего строгого декодера ядра: 16 КиБ, глубина8,
4096 узлов; допустимые manifest/calendar по схеме укладываются в эти структурные
границы. Это не отдельный общий JSON API ядра. JavaScript сначала сканирует ключи,
экранирование/суррогаты и пределы, затем вызывает JSON.parse; обычного JSON.parse
недостаточно для обнаружения дублирующихся ключей.

## API без системных эффектов

Lua `decode(source, hash_factory, sink)` / JS `decode(source, hashFactory, sink)`:

- source возвращает непустые блоки до16384 байт, в конце nil/null. Ошибка чтения
  в Lua — второй результат либо исключение, в JS — отклонение Promise.
- hash factory создаёт независимый контекст `update(chunk)`, `finish()` с
  64 строчными hex-цифрами SHA256. Это доверенный внедряемый адаптер; при интеграции
  его правильность проверяется отдельно. Lua использует существующий metadata SHA
  для небольшого manifest; payload хешируется потоково адаптером.
- sink(name,chunk) необязателен; получает **предварительные** байты, не разрешение
  публикации. false или исключение останавливает операцию. JS API асинхронный,
  Lua API синхронный; планирование/отмена системного процесса вне этого кодека.
- Успех возвращает manifest, исходные calendar bytes, bytes и admitted=false.
  Ошибка — исключение. Подтверждения успешного завершения sink до конца нет.

`encode(raw_manifest, source_for, hash_factory, emit)` принимает проверяемые байты
manifest и фабрику source по имени файла. Выдаёт header/manifest/payload блоками
до16384 байт; проверяет точные длины, JSON календаря, SHA и EOF каждого источника.
Возвращает число байт только после успеха. Выход может оказаться частичным при
поздней ошибке: вызывающий код обязан удалить/отбросить весь предварительный результат.
Ни decode, ни encode не создают файл, не запускают звук, не вызывают сеть и не
публикуют данные. Исключение не является транзакционным rollback вызывающего кода.

`manifest(raw)` выполняет только проверку manifest/описателей; в Lua возвращает
manifest,total, в JS — объект manifest,bytes. Он не проверяет существование файлов.
Перенос больших данных целиком в строку не требуется; метаданные ограничены,
потребление памяти адаптером и пиковый RSS не измерены на устройстве.

## Воспроизводимые проверки

`make test-schoolbell` и `make all` включают тест через существующий host-runner
медиатеки, с Lua5.1, Node, Python и host C-помощником. Самостоятельно:

```sh
python3 packages/schoolbell/portable-plan/test.py
```

Нужны Lua5.1 и Node в PATH; host bit-помощник ускоряет существующий SHA, но не
меняет смысл теста. Python строит общий корпус независимо от JS/Lua кодеков,
используя hashlib. Закреплённый текстовый golden fixture содержит исходные байты
и SHA всего комплекта. Оба кодека обязаны воспроизвести их без изменения.

Проверены62 вектора,175 разбиений потока на каждом языке: блоки1/7/16384,
границы manifest/calendar/media, максимальная сумма медиа2 МиБ, ошибки заголовка,
усечение/trailing, хеши, дубли включая escaped keys, UTF-8/суррогаты, пути/порядок,
потерянные/лишние payload и отказы source/sink/hash. Round-trip не используется
единственным эталоном: ожидаемые байты и SHA получены независимо.

TC-168–174 целиком не закрыты: зависимости/admission, UI и восстановление теперь
проверяются на хосте; интеграция на устройстве и приёмка после отключения питания
остаются отдельными этапами. В этом этапе установка, звук и тест питания не выполнялись.
