# Предварительный расчёт импорта .sbp

[English](PORTABLE_PLAN_PREVIEW.en.md) · [Формат](PORTABLE_PLAN_WIRE.md) · [Кодек](PORTABLE_PLAN_CODEC.md)

ТЗ 1.68, TC-176, 29.10.2026. Чистые модели `preview.lua` и `preview.js` в
`packages/schoolbell/portable-plan/`; не входят в IPK, LuCI или Pages.
Установленная версия остаётся 5.1.18. На устройстве этот этап не проверялся.

## Что рассчитывается

- Строгая схема календаря; диапазоны дат, строковые назначения, ссылки и пределы
  проверяются существующими валидаторами расписаний и диапазонов.
- Все расписания комплекта должны быть перечислены выбранными планами. Каталог
  содержит ровно мелодии строк (включая отключённые) и pre_media; потерянные или
  лишние зависимости блокируют предложение. Pre_media включается всегда.
- Проверяются совпадение зоны name/posix, доступность и размер/SHA штатных мелодий
  по переданному снимку, отсутствие пользовательских медиа для цели Pages.
- Проверяются выключенная автоматика и отсутствие несохранённых правок по снимку,
  пересечения с существующими диапазонами, названия и совместимость предзвонка.
  Отключённая строка с pre=true также защищает существующий предзвонок.
- Назначаются новые ID и свободные user-слоты; существующие данные не меняются.
  Занятый слот не переиспользуется даже при одинаковом SHA. Отсутствующий файл
  слота, на который ссылаются старые строки, pre_media или manual_media, тоже не
  разрешает занять этот слот: иначе изменится смысл старых ссылок.
- Формируется объединённый кандидат с сохранением режима, ежедневного расписания,
  ручной мелодии и всех существующих объектов. Применённый план не является входом
  этой модели и не меняется. Итог проходит прежние лимиты черновика, в том числе
  12 КиБ; байтовый расчёт использует одинаковое каноническое кодирование на JS/Lua.

## Вход и результат

`preview(manifestRaw, calendarRaw, context)` синхронно возвращает предложение.
JS принимает Uint8Array, Lua — строки. Эти байты должны происходить из **успешно
проверенного полного контейнера**. Модель повторяет структурную проверку manifest,
но не читает payload и не перепроверяет SHA calendar; произвольная пара входных
строк не является удостоверенным архивом.

Context — согласованный снимок, который системный адаптер ещё должен получить:

| Поле | Содержание |
| --- | --- |
| draft | Существующий сохранённый черновик, прошедший штатную валидацию |
| timezone | name/posix текущей зоны |
| media | До 14 записей id/size_bytes/sha256 для установленных мелодий; без аудиобайтов |
| operation_id | 32 строчные hex-цифры, источник новых ID |
| automatic_enabled, dirty | Булевы снимки условий допуска |
| target | device или pages |
| names | Объекты plans/schedules: старый ID → явно выбранное новое имя |

Неизвестные поля контекста/календаря отвергаются. Размер names до 4096 байт;
снимок для Lua должен укладываться в пределы строгого JSON (16 КиБ, 4096 узлов,
глубина 8). Невалидный или чрезмерный снимок не даёт разрешения на импорт.
Название сравнивается точно по UTF-8; автоматического переименования нет.

Всегда возвращается admitted=false. При ok=false выдаётся blockers — до 64
code/path, плюс blockers_truncated; candidate отсутствует. Некорректная структура
может дать один ранний отказ вместо списка: перечисление зависимых ошибок тогда
не имеет смысла. Коды отказа модели включают format, dependency, dirty,
automatic_enabled, timezone, overlap, unsupported_media, slots, name_conflict,
pre_conflict, conflict и size. dirty — локальная причина UI, не новый HTTP-статус.

При ok=true возвращаются candidate, mapping (plans/schedules/rows/media),
candidate_bytes, user_slots и pre_change с прежними/предлагаемыми параметрами.
Это **не контракт готового HTTP preview**: нет токена, ревизий/срока действия,
расчёта места, приёма файла или записи. Исходный context не изменяется.
Существующие legacy-year записи сохраняются в кандидате как есть; для сравнения
диапазонов используется их представление годом. Импортируемые записи только range.

## Оставшиеся слои

Системный адаптер должен связать полный проверенный архив и снимки ревизий,
проверить реальность/доверие зоны, MP3/длительность и место/RAM, сформировать токен,
повторить допуск под замками и выполнить durable commit/recovery. Проверка времени
звонков на DST gap/fold выполняется календарным вычислителем при соответствующей
проверке плана; сравнение строк зоны не доказывает эту проверку.

Экспорт выбранных планов с построением минимального комплекта — следующий этап;
модель здесь проверяет замыкание уже переданных зависимостей, но не собирает архив.
Pages ещё не загружает этот код. Не создаются файл/процесс, звук или команда часов.

## Проверки

`test-preview.py` строит 45 общих сценариев и запускает Lua/JS. Для успешных
случаев сравнивается весь результат, включая размер в байтах; отдельно проверяются
ожидаемые ID/слоты, сохранение старых объектов/настроек и неизменность входа.
Покрыты тихий диапазон, граница года/29 февраля, отключённые строки, отсутствующие
и лишние зависимости, имена, занятые и отсутствующие связанные слоты, конфликт
предзвонка, зона, dirty/автоматика, malformed, предел списка ошибок и итогового JSON.
Корпус включён в make test-schoolbell / make all рядом с 62 векторами кодека.
TC-168–174 целиком ещё не закрыты: это host-модель, не сквозная проверка импорта.
