# План реализации «Мастера установки»

[English](SETUP_WIZARD_PLAN.en.md) · [Текущие возможности](../tools/setup/gui/README.md) · [ТЗ](requirements/TECHNICAL_SPECIFICATION_SETUP_GUI.md)

Дата: 24.11.2026. План по запросу владельца, включая встроенный OEM для автономного
восстановления. Это последовательность разработки, а не подтверждение готовности
операций. Перед реализацией каждого этапа уточняются требования и тест-кейсы ТЗ.

## Исходное состояние

- GUI 0.2.1: три маршрута, темы, общий пароль с глазком, локальные сеансы и копии.
- Внешний ZIP: реальная свежая установка после удаления приложения проверена
  при сохранённых зависимостях. Установка всех зависимостей на чистую OpenWrt
  и восстановление копии ещё не приняты.
- Консольные Setup.ps1 / tftp_server.py умеют установку OpenWrt и RestoreFactory;
  GUI пока показывает для них инструкции. Непрерывный цикл с последними
  исправлениями DHCP/SSH требует отдельной приёмки.
- Старое GUI-обновление было проверено, но внешний ZIP пока не поддерживает upgrade.
- Проверенный профиль прошивки: **TL-MR3020 EU v3.30**. Определение OpenWrt
  «MR3020 v3» само по себе не подтверждает регион и точную аппаратную ревизию.
- Рабочая ветка `codex/setup-external-routes` содержит текущую группу изменений.
  Их не переносим и не прячем для начала новой задачи.

## Три пользовательских маршрута

| Маршрут | Шаги | Результат |
| --- | --- | --- |
| Установить OpenWrt | Оборудование → модель/ревизия → адаптер → образ и копия → проверка → Reset после READY → ожидание загрузки → доступ и пароль root | Подтверждённая OpenWrt; отдельная кнопка перехода к комплектам |
| Установить Школьник | Оборудование и пароль → один или несколько совместимых архивов → устройство → общий план и копия → подтверждение → установка → проверка | Пакеты и службы проверены; автозвонки выключены; настройки сохранены |
| Восстановить роутер | Оборудование → тип восстановления → профиль/копия → предупреждение о данных → подтверждение → восстановление → проверка | Подтверждённая заводская ОС либо отдельно восстановленные совместимые настройки |

USB–Ethernet обязателен в начальном списке. Имя адаптера, описание устройства и
адрес видны до подтверждения. Пароль запрашивается только когда нужен; сохраняется
в памяти текущего маршрута между операциями, показывается общей кнопкой с глазком.
Подробности — в «Справке», основные шаги и текущий результат — в рабочей области.
Подсказка Reset и фото с указателем появляются на нужном шаге, не заранее.

## Встроенное автономное восстановление OEM

По предложению владельца проверенный образ **EU v3.30 Build250625** поставляется
внутри мастера, а не ищется рядом с EXE или в Интернете. Предпочтительно включить
его как Qt-ресурс EXE. Профиль хранит модель/регион/ревизию, версию, происхождение,
точный размер и SHA256. Распаковка в приватный каталог сеанса проверяется до
назначения сетевых адресов и запуска TFTP. Исходный ресурс не изменяется.

Встроенный образ не означает встроенные пакеты Школьника: комплекты остаются
внешними ZIP. Для автономного возврата в поставке нужны также все компоненты
передачи и настройки сети; их наличие проверяется на чистой Windows без загрузок.
Если автономность именно одного EXE потребует упаковки helper/runtime, это входит
в этап поставки, а не объявляется готовым только за счёт статической Qt.

Возврат ОС не гарантирует очистку настроек: пароль и настройки TP-Link могут
сохраниться. Полный заводской сброс — отдельный явно описанный шаг после загрузки,
с подтверждением потери настроек и проверкой страницы первоначальной настройки.
Мастер не обещает восстановить забытый пароль. Build250625 — поддерживаемая
заводская версия, не обязательно версия, с которой конкретный роутер был куплен.
Другие OEM-архивы в репозитории не становятся доступными профилями прошивки без
отдельной проверки. Калибровки, идентификаторы устройства и загрузчик не заменяются
универсальным дампом другого устройства.

отдельными группами. Коммиты подписываются настроенным ключом; push, CI точного HEAD,
слияния, теги и публикации выполняет владелец. План не разрешает аппаратные операции.

## Общая архитектура и поведение при ошибках

- QML показывает шаги и вызывает операции. Общая логика Python используется GUI
  и CLI; правила совместимости и проверки копий не дублируются в двух установщиках.
- Только настройка сети/firewall выполняется с повышенными правами через узкий
  интерфейс. GUI и пароли не передаются как произвольный PowerShell-код; пароль
  не попадает в аргументы, журнал, файл или квитанцию.
- События содержат идентификаторы сеанса/операции и коды этапов; опоздавшее событие
  от предыдущей операции не меняет текущий экран. Журнал доступен для копирования,
  а основной итог написан обычным языком.
- До записи отмена завершает подготовку и возвращает сеть. Во время записи
  нельзя обещать безопасную остановку: GUI объясняет ожидание, не завершает worker
  принудительно. После обрыва — проверка факта, а не автоматическое повторение.
- Для сети сохраняется исходное состояние выбранного адаптера. Первый поддерживаемый
  профиль — отдельный адаптер с DHCP; ручная конфигурация отклоняется до изменений,
  пока её точное восстановление не реализовано и не проверено.
- TFTP ACK означает только передачу. Успех требует отдельной проверки ОС/версии;
  при отсутствии возможности автоматической проверки UI явно запрашивает ручную.
- На OEM не обещается SSH-копия: сохранение настроек через заводской интерфейс.
  У не загружающегося роутера копия может быть невозможна; это явно отражается
  перед подтверждением, существующие материалы никогда не заменяются пустой копией.
- Несколько ZIP — единый предварительный план: совместимость профиля, пакетов,
  зависимостей и версий, отсутствие конфликтов, итоговое место и последовательность.
  Не запускать архивы независимо друг за другом без общего анализа. Если нужна
  смена прошивки/ABI, направлять в маршрут OpenWrt, а не обновлять ядро через пакетный.
- Локальный SHA256 защищает от повреждения, но не заменяет доверенную подпись
  скачанного релиза. Ключ подписи и выпуск ключей решаются владельцем отдельно.

## Что проверять на каждом уровне

1. Host: совместимость/размеры/хеши, ограниченная распаковка, сохранность сеанса,
   ложные/старые события, частичные записи, отсутствие секретов, отмена и повторы.
2. Сеть на хосте: тестовый транспорт/loopback, DryRun, возврат исходной конфигурации
   при каждом отказе; без скрытого обращения к рабочему устройству.
3. GUI: обе темы, системная тема, масштаб 100/150/200 %, малое окно, клавиатура,
   длинные имена, доступность кнопок, копирование протокола, ясность следующих действий.
4. Устройство: только отдельно разрешённый стенд, проверенная копия/путь восстановления,
   точные версии и SHA артефактов, реальная проверка результата. Локальный PASS не
   закрывает аппаратный пункт. Рабочий стенд не используется автоматически.

## Кроссплатформенность

Сначала закончить принятый путь Windows 11. Профили, валидатор архивов, события,
сеансы и QML держать независимыми от ОС. Настройка адаптера, повышение прав,
firewall и поиск интерфейсов — отдельные платформенные реализации. Затем Linux,
после него macOS, каждый с собственной упаковкой, проверками и аппаратной приёмкой.
Наличие Qt/WSL не считается подтверждением поддержки Linux или macOS.

## Ближайший шаг

Завершить этап 0, затем общие операции и сеть (1–2). После этого последовательно
подключить OpenWrt и встроенное OEM-восстановление (3–4), расширить комплекты и копии
(5–6), добавить загрузку релизов и завершить поставку (7–8). Это даёт автономный
проверяемый цикл раньше, чем добавляется зависимость от GitHub.
