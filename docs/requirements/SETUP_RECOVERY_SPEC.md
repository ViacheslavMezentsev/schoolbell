## 1. Введение

1.1. Документ определяет мастер в tools/setup. Требования runtime Школьника не изменяются.

1.2. Происхождение: [R] — восстановлено из существующего кода/наблюдений; [N] — новое требование владельца; [U] — уточнение на основе проверки. Источники: запрос на DryRun обоих сценариев, исходники мастера, [протокол восстановления](../SETUP_RECOVERY.md).

1.3. Номера требований и TC сохраняются при изменениях; исключённые номера не используются повторно.

1.6. Структура: разделы 3–3 — нормативные; остальные разделы информативные.

## 2. Общее описание

2.1. Мастер выбирает установку OpenWrt со Школьником либо возврат заводской ОС через загрузчик. Передача файла и успешная загрузка ОС — разные этапы проверки.

2.2. DryRun проверяет локальную готовность, но не подтверждает пригодность физического устройства или доступность его интерфейса.

## 3. Требования

3.1. [N] `-DryRun` должен работать для установки и для `-RestoreFactory`, завершаться до любых изменений IP, firewall, состояния мастера, передачи TFTP, SSH и активных сетевых проб. Повышенные права не требуются.

3.2. [N] DryRun должен проверять SHA256SUMS, точный профиль образа, выбранный физический Ethernet, DHCP и отсутствие ручных адресов, поднятый link, пересекающиеся маршруты других интерфейсов, занятые UDP-порты и оставшееся состояние мастера. Для установки дополнительно проверяются локальные пакеты и наличие SSH-клиента. Ошибка должна давать ненулевой код возврата.

3.3. [N] DryRun должен показывать профиль, адаптер, образ и SHA256, временные адреса, правило firewall, этапы, очистку и ограничения. Reset не требуется. При `-InterfaceIndex` выбор адаптера не должен требовать ввода.

3.4. [U] `-CheckOnly` проверяет файлы и TFTP на loopback; это отдельный режим, несовместимый с DryRun. DryRun несовместим с RestoreNetwork; RestoreFactory несовместим с InstallOnly и RestoreNetwork.

3.5. [U] Профили должны принимать только закреплённые длины и SHA256. OEM Build250625 преобразуется из проверенного оригинала: 128 КиБ нулевого префикса плюс исходные байты с 0x20200. Проверяются хеши входа и результата. Другие образы отвергаются до открытия сокета.

3.6. [N] Возврат OEM должен требовать подтверждения модели и `RESTORE FACTORY`; не запускать SSH, opkg или установку Школьника. После передачи мастер должен восстановить DHCP и убрать свои временные адреса/правило. Успех передачи не выдаётся за успех загрузки.

3.7. [U] Инструкция должна объяснять необходимость резервной копии, возможное сохранение старого пароля TP-Link и отдельный сброс настроек на уже загруженном устройстве. Мастер не выполняет сброс автоматически. Ключ Wi-Fi и пароль администратора различаются.

3.8. [R] Сборщик должен включать OEM-профиль только при явном `--oem` с проверенным файлом. Без него установка OpenWrt доступна, возврат OEM должен завершаться ошибкой отсутствия образа. Все включённые файлы отражаются в SHA256SUMS.

3.9. [N] Репозиторий должен хранить неизменённые официальные ZIP прошивки и Python, HTML страницы поддержки EN и доступный русскоязычный оригинал, краткие MD-выжимки (русская — перевод английской), URL/дату/SHA256. Автономная подготовка OEM-комплекта на Windows 11 не должна требовать сети, WSL, установленного Python или устройства. Матрица поддержки ограничена TL-MR3020 EU Ver. 3.30 с оригинальным загрузчиком; остальные ревизии не заявляются.

## 4. Верификация

| TC | Проверка и ожидаемый результат | Метод |
| --- | --- | --- |
| TC-01 | Оба DryRun проходят с допустимой конфигурацией; нет мутаций и сетевых вызовов | tests/test-setup-dryrun.ps1, подменённая локальная инвентаризация и запрет мутаций |
| TC-02 | Ручной IP, VPN /32, занятый порт, повреждённый образ и несовместимые ключи отклоняются | Тот же PowerShell-тест |
| TC-03 | Преобразование, длины, хеши, отсутствие профиля, повреждение и упаковка проверены; --check не открывает сокет | tests/test_setup_firmware.py |
| TC-04 | TFTP повторяет потерянный ACK, завершает передачу | tftp_server.py --self-test, только loopback |
| TC-05 | Полный новый мастер: подтверждение, передача, загрузка, очистка сети | Отдельная аппаратная проверка; ещё не выполнена |
| TC-07 | Архивы совпадают с манифестом; автономный OEM ZIP собран, хеши/лицензия/путь модулей корректны; повреждённый архив отвергается до записи | Python host-тест и Windows Prepare-Recovery + CheckOnly |
| TC-06 | Пароль сохраняется; отдельный сброс позволяет вход и проверку версии | Подтверждено владельцем для подготовленного OEM-кандидата; не для полного нового мастера |

## 6. Ограничения и открытые проверки

6.1. Подтверждён переход OpenWrt → OEM подготовленным кандидатом. OEM → OEM, обратная установка OpenWrt и полный новый мастер на устройстве остаются непроверенными. DryRun и тесты на хосте их не заменяют.

6.2. Встроенный комплект пакетов остаётся версии 5.1.100; изменение мастера не повышает версию IPK и не обновляет комплект автоматически.

6.3. Достоверность модели, свободные flash/RAM и пароль проверяются только в реальном маршруте, где применимо. Сброс настроек, восстановление повреждённого загрузчика и произвольные аппаратные ревизии вне области применения.
