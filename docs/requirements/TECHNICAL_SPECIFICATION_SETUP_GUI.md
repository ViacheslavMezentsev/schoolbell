## 1. Введение

Документ дополняет основное ТЗ Школьника, не меняя номера его требований и TC. Номера TC в этом отдельном документе локальны и не относятся к основному ТЗ. Область — обновление уже установленного 5.1.124 до 5.1.127, без перепрошивки. Происхождение: [N] новое, [R] сохранённое, [U] уточнённое. разделы 3–6 — нормативные; номера постоянны. Источник — запрос владельца о реальной установке поверх OpenWrt с выключенным автоматом и неизменной громкостью. См. [README мастера](../../tools/setup/gui/README.md).

## 2. Общее описание

Qt показывает состояние worker; Python использует Windows OpenSSH. Роутер не получает компиляторы. Пароль вводится в форме, askpass получает его по приватному локальному каналу текущего пользователя. Пользователь выбирает выделенный USB–Ethernet. Макет и реальная операция различимы визуально.

## 3. Состояния и данные

3.1.1. После неизвестного исхода записи мастер должен запрещать повторную запись и предоставлять отдельную проверку результата. Постоянный маркер сохраняется до ручного разбора. [N] (р.1.0)

3.1.2. Одновременно в каталоге сеанса может выполняться только один worker; оставшийся после аварии lock блокирует продолжение. [N] (р.1.0)

## 4. Функциональные требования

4.1.1. До записи проверяются прямой маршрут выбранного IPv4/адаптера, известный ключ SSH, плата MR3020 v3, OpenWrt 19.07.9, kernel ABI, native clock 1.0.0 и наличие версии, соответствующей IPK отката. Несовпадение останавливает операцию. [N] (р.1.0)

4.1.2. До установки сохраняются полный overlay и IPK отката на ПК; SHA256 копии сверяется с устройством, архив читается без распаковки. Повреждённая копия запрещает установку. [N] (р.1.0)

4.1.3. Установка требует подтверждения пользователя; подготовка действует 1800 секунд. Проверяется совпадение устройства/загрузки, настроек звука и контрольных сумм. [N] (р.1.0)

4.1.4. Успех показывается только после проверки целевой версии, отсутствия package.pending, выключенных автозвонков, сохранённых настроек звука, черновика, ревизии активного плана и работающих служб. [N] (р.1.0)

4.1.5. Пилот не должен перепрошивать устройство, настраивать сеть или часы, включать автозвонки и изменять громкость. При исходно включённом автомате подготовка прекращается. [N] (р.1.0)

## 5. Интерфейсы

5.1.1. Реальный режим должен быть явно отделён от макета; действия и результат отражают worker, без имитационного процента. Во время операции штатное закрытие окна блокируется. [N] (р.1.0)

5.1.2. Пароль не должен сохраняться на диск, в журнал или в командную строку; ввод выполняется в поле формы перед этапом; всплывающие окна отсутствуют. Поле очищается при запуске, состояние backend с паролем очищается после этапа. Неизвестные SSH-ключи не принимаются автоматически. [N] (р.1.0)

## 6. Нефункциональные требования

6.1.1. Сборка реального комплекта должна включать проверенный Python-архив, worker, manifest SHA256 и оба IPK; Qt EXE остаётся статическим. [N] (р.1.0)

## 7. Верификация

| TC | Условия и действие | Критерий |
| :--- | :--- | :--- |
| TC-01 | Подменить payload/копию/звук/исходную версию; запустить установку | opkg не запускается |
| TC-02 | Тайм-аут записи, повтор, параллельный worker | повтор записи и конкурентный запуск запрещены |
| TC-03 | Локальная сборка и осмотр GUI/поля пароля | комплект собран; ввод в форме; нет записи секретов; закрытие блокируется |
| TC-04 | Разрешённый стенд с выключенным автоматом: подготовка, установка, проверка | копия сверена; версия новая; звук/план сохранены; автомат выключен; сеть/часы не менялись |

## 9. Допущения и открытые вопросы

Пилот использует существующий доверенный ключ и рабочий выделенный маршрут. Подготовка новых ключей, новая установка зависимостей, автоматическое определение адаптера, автоматический откат и GUI перепрошивки отложены. После аварийного завершения worker оставшийся lock разбирается вручную. Полный overlay может содержать секреты и не предназначен для публикации. Аппаратная приёмка не заменяется тестами с подменённым SSH.

## Приложение A. Константы

PREPARE_TTL = 1800 с (4.1.3), REMOTE_TIMEOUT = 240 с, CONNECT_TIMEOUT = 8 с. Объём копии ограничен доступным tmpfs; исходная проверка требует 6144 КиБ tmpfs и 1024 КиБ overlay. Ограничения пилота подлежат расширению после аппаратной проверки.

Результат 24.11.2026: TC-01/TC-02 — девять локальных регрессионных тестов; TC-03 — сборка и визуальная проверка поля пароля/результата; TC-04 — реальное обновление отдельного устройства подтверждено worker и владельцем. Аппаратный обрыв записи не проверялся. Автопрокрутка журнала и повторное открытие подготовленного сеанса проверены в GUI.
