## 1. Введение

Документ дополняет основное ТЗ Школьника, не меняя номера его требований и TC. Номера TC в этом отдельном документе локальны и не относятся к основному ТЗ. Область — обновление установленного 5.1.124 до 5.1.127 и установка 5.1.127 с зависимостями на чистую OpenWrt, без перепрошивки. Происхождение: [N] новое, [R] сохранённое, [U] уточнённое. разделы 3–6 — нормативные; номера постоянны. Источник — запрос владельца о реальной установке поверх OpenWrt с выключенным автоматом и неизменной громкостью. См. [README мастера](../../tools/setup/gui/README.md).

## 2. Общее описание

Qt показывает состояние worker; Python использует Windows OpenSSH. Роутер не получает компиляторы. Пароль вводится в форме, askpass получает его по приватному локальному каналу текущего пользователя. Пользователь выбирает выделенный USB–Ethernet. Макет удалён; неподключённые операции прошивки явно обозначены.

## 3. Состояния и данные

3.1.1. После неизвестного исхода установки GUI ДОЛЖЕН показывать предупреждение и разрешать отдельную проверку либо новую явную установку без обязательного нового сеанса. Автоматически повторять запись НЕ ДОЛЖЕН. [U] (р.1.23)

3.1.2. Одновременно ДОЛЖЕН выполняться только один GUI worker для активного каталога, включая архивирование; блокировка ОС исключает живого конкурента. После получения блокировки ОС известные оставшиеся маркеры GUI ДОЛЖНЫ архивироваться автоматически. [U] (р.1.23)

3.1.3. Необязательный «Новый сеанс» ДОЛЖЕН архивировать предыдущий каталог с копиями и маркерами независимо от исхода установки. Архивирование НЕ ДОЛЖНО означать успех на устройстве. Пароль и выбор очищаются только при этом явном действии, но не при повторной установке. [U] (р.1.23)

3.1.4. GUI ДОЛЖЕН принимать этапы и итоги по отдельному от журнала локальному каналу с версией протокола, идентификаторами операции/сеанса, действием и возрастающим номером события. Повторное чтение неизменного события допустимо. Несовпадающие идентификаторы, неизвестные коды, регресс последовательности, изменение терминального итога или сообщение больше 65536 байт НЕ ДОЛЖНЫ давать успех. Успех ДОЛЖЕН требовать допустимый для действия итог и штатное завершение worker с кодом 0; текст журнала не участвует в выборе результата. Пароль и удалённый вывод НЕ ДОЛЖНЫ включаться в канал управления. `[N]` (р.1.13)

3.1.5. Мастер ДОЛЖЕН разрешать запрос отмены проверки ZIP, подготовки, копирования и проверки результата с обработкой между читающими запросами, не убивая текущий SSH. Установка и архивирование сеанса НЕ ДОЛЖНЫ прерываться этим запросом. Отмена ДОЛЖНА сохранять частичные материалы и освобождать штатные блокировки; при маркере возможной записи результат остаётся неизвестным. Пока worker работает, навигация и закрытие остаются заблокированными. `[N]` (р.1.13)

3.1.6. Восстановление известных аварийных маркеров GUI ДОЛЖНО выполняться под блокировкой ОС без доступа к устройству и без удаления копий или признаков записи. Неизвестный формат требует диагностики; живой worker запрещает параллельное выполнение. Неизвестный исход установки сам по себе НЕ ДОЛЖЕН блокировать повтор. [U] (р.1.23)


3.1.7. Планировщик сети ДОЛЖЕН принимать снимок интерфейсов, маршрутов, портов и состояния восстановления, проверять уникальный GUID физического USB–Ethernet с DHCP, отсутствие ручных/занятых адресов, конфликтов маршрутов и занятых портов профиля. Отсутствие IP НЕ ДОЛЖНО исключать адаптер из выбора; отсутствие линка ДОЛЖНО блокировать допуск. Фоновый маршрут через шлюз ДОЛЖЕН требовать последующей проверки прямого пути, а не безусловного отключения VPN. План ДОЛЖЕН содержать идентификатор адаптера, хеш снимка, закреплённые метаданные образа и границы очистки, не изменять вход, не обращаться к сети/устройству и не объявлять READY или проверку образа. `[N]` (р.1.15)

3.1.8. Сборщик Windows ДОЛЖЕН читать только локальные сведения об адаптерах, адресах, маршрутах, UDP-портах и оставшемся состоянии восстановления. Он НЕ ДОЛЖЕН отправлять сетевые пробы, обновлять DHCP или изменять настройки. GUI ДОЛЖЕН требовать выбор адаптера и подтверждение точной модели, заново собирать снимок перед каждой проверкой плана, сбрасывать результат при смене адаптера/профиля и блокировать навигацию во время чтения. Ошибка чтения НЕ ДОЛЖНА представляться успешной проверкой. `[N]` (р.1.15)


3.1.9. Сетевой helper ДОЛЖЕН запускаться только после явного подтверждения GUI и UAC, принимать фиксированные prepare/restore, профиль и GUID без произвольных команд. Подготовка ДОЛЖНА повторить preflight, сохранить защищённый журнал до добавления адреса и проверить прямой маршрут. Restore ДОЛЖЕН использовать GUID журнала, удалять только собственный адрес и подтверждать DHCP и полученный адрес с происхождением Dhcp и состоянием Preferred, отличный от APIPA/0.0.0.0; неудача ДОЛЖНА сохранять журнал. Живой второй helper и неопределённая принадлежность адреса ДОЛЖНЫ блокировать изменение. ## 5. Интерфейсы

5.1.1. Реальный режим должен быть явно отделён от макета; действия и результат отражают worker, без имитационного процента. Во время операции штатное закрытие окна блокируется. [N] (р.1.0)

5.1.2. Пароль не должен сохраняться на диск, в журнал или в командную строку; ввод выполняется в поле формы один раз в текущей вкладке; всплывающие окна отсутствуют. Поле ДОЛЖНО сохранять пароль в памяти текущей вкладки между операциями, включая ошибки. Общий компонент ДОЛЖЕН иметь справа кнопку показа/скрытия с подсказкой и доступом с клавиатуры. По умолчанию и при запуске операции пароль скрыт. При уходе из вкладки, смене подключения или закрытии пароль очищается; backend очищает свою копию после этапа. Подготовка ДОЛЖНА указывать необходимость знать пароль OpenWrt для SSH; для Reset-восстановления он не требуется. Неизвестные SSH-ключи не принимаются автоматически. [U] (р.1.1)

5.1.3. Мастер ДОЛЖЕН показывать работающие Ethernet-подключения с IPv4 в сети цели по имени, краткому описанию и IP; обновление обозначается ↻. Перед SSH сохраняется проверка прямого маршрута. Вне операции подключение ДОЛЖНО оставаться доступным для выбора; пароль при смене подключения очищается. [U] (р.1.23)


5.1.4. Мастер ДОЛЖЕН выделять результаты рамкой и предоставлять кнопку ⧉ для копирования всего протокола, включая строки вне видимой области. Пустой протокол отключает кнопку; успешное копирование показывается знаком ✓ на две секунды. [N] (р.1.5)

5.1.5. Мастер ДОЛЖЕН отделять подробные инструкции во вкладку «Справка», оставляя в «Установке» краткое пояснение и условия подготовки. Обе вкладки ДОЛЖНЫ прокручиваться независимо; при рабочей области 800 × 450 логических пикселей нижние кнопки доступны прокруткой, группы действий переносятся по ширине. Чтение справки НЕ ДОЛЖНО очищать пароль или прерывать операцию; показ пароля при этом выключается. Выход из реального режима сохраняет прежнее правило очистки. [N] (р.1.6)

5.1.6. Все выпадающие списки простого, экспертного и реального режимов ДОЛЖНЫ использовать общий стиль и одинаковую рисованную стрелку, без зависимости от текстового символа шрифта. Область стрелки — 24 × 24 логических пикселя, шрифт списка — 18 пикселей, минимальная высота строки — 48 пикселей. Списки строк и объектов должны одинаково отображать выбранное значение, раскрытые варианты, фокус и disabled в обеих темах. [N] (р.1.10)

5.1.7. Мастер ДОЛЖЕН показывать при запуске три маршрута: установка OpenWrt на новый роутер, установка комплекта Школьника из выбранного ZIP и восстановление заводской прошивки. Пока операции прошивки не подключены, соответствующие страницы ДОЛЖНЫ явно обозначать это, не запускать сервер и не имитировать передачу или успех. Смена маршрута во время операции ДОЛЖНА блокироваться; выход из маршрута комплекта ДОЛЖЕН очищать пароль, сохраняя материалы сеанса. `[N]` (р.1.12)

5.1.8. Оба маршрута прошивки ДОЛЖНЫ последовательно показывать подключение, проверку, подготовку, готовность сервера, передачу, ожидание загрузки, восстановление сети и проверку результата. Основное действие ДОЛЖНО соответствовать текущему шагу; статус и следующее действие ДОЛЖНЫ оставаться в постоянной области вне прокручиваемой справки. Инструкция Reset ДОЛЖНА появляться после READY. Передача, восстановление сети и подтверждение загрузки пользователем ДОЛЖНЫ различаться; Мастер ДОЛЖЕН предлагать открыть интерфейс и сверить версию текстовой подсказкой, без кнопки «Роутер работает» и обязательной отметки результата. 5.1.9. Во время фиксированного ожидания запроса роутера (180 с) и ожидания записи/загрузки (90 с) мастер ДОЛЖЕН показывать обратный отсчёт мм:сс по сроку текущего этапа helper. Повторное чтение события НЕ ДОЛЖНО перезапускать таймер. Окончание отсчёта НЕ ДОЛЖНО само завершать этап или объявлять успех; переход определяется helper. Неполный снимок, нехватка места, неподдержанный upgrade или repair ДОЛЖНЫ приводить к отказу без плана записи. Результат ДОЛЖЕН явно указывать preliminary-only и write_authorized=false: снимок не подтверждает текущее состояние, резервную копию или исправность служб. [N] (р.1.8)

6.1.5. ZIP ДОЛЖЕН оставаться ограниченным: ZIP_MAX 64 МиБ, ZIP_CONTENT_MAX 128 МиБ, ZIP_FILES_MAX 512, ZIP_MEMBER_MAX 16 МиБ. Небезопасные пути, ссылки, дубликаты и повреждённые суммы отклоняются с ошибкой. GUI ДОЛЖЕН создавать уникальные каталоги попыток вне комплекта, сохраняя прежние данные; неизвестный исход НЕ ДОЛЖЕН блокировать новую попытку. Ограничения отдельной полной копии BACKUP_MAX 32 МиБ и BACKUP_RAM_RESERVE 6144 КиБ не являются допуском к установке. [U] (р.1.23)

6.1.6. Проект ДОЛЖЕН поддерживать единое руководство выбора GUI/консольного способа с таблицей реализованных и аппаратно проверенных маршрутов. Заметка выпуска ДОЛЖНА указывать независимые версии мастера/комплекта, точные артефакты, совместимость, проверенные сценарии и ограничения. Предварительный выпуск НЕ ДОЛЖЕН обходить проверки целостности и совместимости; незавершённый аудит материалов НЕ ДОЛЖЕН блокировать выпуск по решению владельца от 25.11.2026. Обновление маршрута ДОЛЖНО сопровождаться обновлением руководства, TODO и заметки выпуска. `[N]` (р.1.17)

6.1.7. Упаковщик мастера ДОЛЖЕН брать файлы только из явного списка, сверять worker с исходниками, квитанцию версии/хеша EXE и закреплённый образ восстановления. Python ДОЛЖЕН восстанавливаться из проверенного upstream-архива; сеансы, копии и произвольные файлы каталога сборки НЕ ДОЛЖНЫ попадать в поставку. ZIP ДОЛЖЕН содержать manifest, контрольные суммы и инструкции RU/EN, создаваться только в новом каталоге и быть детерминированным при одинаковых входах. `[N]` (р.1.18)

6.1.8. Workflow GitHub ДОЛЖЕН запускаться вручную, собирать целевой MIPS-комплект и Windows x86_64 мастер, выдавать совместимую по формату пару ZIP и суммы без создания тегов или релизов. Метаданные ДОЛЖНЫ отличать сборку от аппаратной приёмки; публикация остаётся отдельным действием владельца. `[N]` (р.1.18)

## 9. Допущения и открытые вопросы

GUI принимает новый SSH-ключ по явному подтверждению. Автоматический откат не выполняется. Повторяемая установка требует отдельной аппаратной приёмки. Для свежей OpenWrt пароль предварительно задаётся через LuCI. Аппаратная приёмка свежей установки ещё не выполнена. Блокировки старого или неизвестного формата разбираются вручную; формат GUI с блокировкой ОС восстанавливается по 3.1.6. Полный overlay может содержать секреты и не предназначен для публикации. Аппаратная приёмка не заменяется тестами с подменённым SSH.

## Приложение A. Константы

PREPARE_TTL = 1800 с (4.1.3), REMOTE_TIMEOUT = 240 с, CONNECT_TIMEOUT = 8 с. Объём копии ограничен доступным tmpfs; исходная проверка требует 6144 КиБ tmpfs и 1024 КиБ overlay. Ограничения пилота подлежат расширению после аппаратной проверки.

Аппаратный обрыв записи не проверялся. Автопрокрутка журнала и повторное открытие подготовленного сеанса проверены в GUI.

ZIP_MEMBER_MAX = 16 МиБ; BACKUP_MAX = 32 МиБ; BACKUP_RAM_RESERVE = 6144 КиБ (6.1.5).
Host CLI не заменяет GUI: приёмка подключения Windows/OpenSSH, свежей установки из ZIP
и восстановления overlay на устройстве остаётся открыта. Локальная проверка shell
