## 1. Введение

Документ дополняет основное ТЗ Школьника, не меняя номера его требований и TC. Номера TC в этом отдельном документе локальны и не относятся к основному ТЗ. Область — обновление установленного 5.1.124 до 5.1.127 и установка 5.1.127 с зависимостями на чистую OpenWrt, без перепрошивки. Происхождение: [N] новое, [R] сохранённое, [U] уточнённое. разделы 3–6 — нормативные; номера постоянны. Источник — запрос владельца о реальной установке поверх OpenWrt с выключенным автоматом и неизменной громкостью. См. [README мастера](../../tools/setup/gui/README.md).

## 2. Общее описание

Qt показывает состояние worker; Python использует Windows OpenSSH. Роутер не получает компиляторы. Пароль вводится в форме, askpass получает его по приватному локальному каналу текущего пользователя. Пользователь выбирает выделенный USB–Ethernet. Макет и реальная операция различимы визуально.

## 3. Состояния и данные

3.1.1. После неизвестного исхода записи мастер должен запрещать повторную запись и предоставлять отдельную проверку результата. Маркер сохраняется и при архивировании; до подтверждения результата новый сеанс запрещён. [U] (р.1.2)

3.1.2. Одновременно ДОЛЖЕН выполняться только один worker для активного каталога сеанса, включая переименование в архив и создание нового каталога; оставшийся после аварии lock/guard блокирует продолжение. [U] (р.1.2)

3.1.3. «Новый сеанс» ДОЛЖЕН после подтверждения локально переименовать предыдущий каталог в уникальный каталог архива, сохранив копии, протокол и маркер записи. Если запись могла начаться, требуется подтверждение результата, связанное SHA256 с подготовкой и маркером; контрольные суммы копий и IPK отката должны совпадать. Старое подтверждение без этих связей требует повторной проверки. Проверка результата ДОЛЖНА использовать сохранённый комплект сеанса независимо от пересборки текущего; неудачная повторная проверка аннулирует прежнее подтверждение. Пароль и выбор подключения очищаются; операции с устройством не выполняются. [N] (р.1.2)

## 4. Функциональные требования

4.1.1. Для обновления до записи проверяются прямой маршрут выбранного IPv4/адаптера, известный ключ SSH, плата MR3020 v3, OpenWrt 19.07.9, kernel ABI, native clock 1.0.0 и наличие версии, соответствующей IPK отката. Несовпадение останавливает операцию. Свежая установка проверяется по п. 4.1.7. [U] (р.1.4)

4.1.2. До обновления сохраняются полный overlay и IPK отката на ПК; SHA256 копии сверяется с устройством, архив читается без распаковки. Повреждённая копия запрещает установку. Для свежей установки используется копия и образ из п. 4.1.7. [U] (р.1.4)

4.1.3. Установка требует подтверждения пользователя; подготовка действует 1800 секунд. Проверяется совпадение устройства/загрузки, настроек звука и контрольных сумм. [N] (р.1.0)

4.1.4. Успех показывается только после проверки целевой версии, отсутствия package.pending, выключенных автозвонков, сохранённых настроек звука, черновика, ревизии активного плана и работающих служб. Для свежей установки прежние данные Школьника отсутствуют; проверяются все версии пакетов, выключенный автомат, службы и неизменность защищённых сетевых/системных настроек. [U] (р.1.4)

4.1.5. Пилот не должен перепрошивать устройство, настраивать сеть или часы, включать автозвонки и изменять громкость. При исходно включённом автомате подготовка прекращается. [N] (р.1.0)

4.1.6. Если установлена целевая версия комплекта, мастер ДОЛЖЕН проверить совместимость среды, native clock, отсутствие package.pending, выключенный автомат и работающие службы. После успешной проверки он ДОЛЖЕН показать отдельное состояние «уже установлен», не создавать подготовку записи и не запускать opkg. Ошибка любой проверки не является успехом. [N] (р.1.3)

4.1.7. Для чистой OpenWrt мастер ДОЛЖЕН проверить плату, ABI/libc, отсутствие установленных данных Школьника, совместимость уже имеющихся зависимостей и SHA256 полного комплекта. До записи сохраняются полный overlay, список пакетов, идентичность устройства/загрузки и проверенный образ той же OpenWrt; откат требует повторной прошивки и восстановления overlay, автоматически не выполняется. Перед записью повторно сверяются подключение, загрузка, состав пакетов и защищённые настройки; требуется место для зависимостей и резерв. Маркер записи создаётся до SSH; неизвестный исход запрещает повтор и архивирование до успешной проверки. [N] (р.1.4)

4.1.8. После проверки установленного Школьника мастер ДОЛЖЕН предоставлять чтение резервной копии всех MTD-разделов и overlay. Каждый файл сверяется SHA256 с устройством и повторно на ПК; отметка verified создаётся только после сверки идентичности загрузки, выключенного автомата, звука и плана. Каталог уникален, прежние копии не перезаписываются; частичная копия не является проверенной. Операция не пишет flash. [N] (р.1.4)

## 5. Интерфейсы

5.1.1. Реальный режим должен быть явно отделён от макета; действия и результат отражают worker, без имитационного процента. Во время операции штатное закрытие окна блокируется. [N] (р.1.0)

5.1.2. Пароль не должен сохраняться на диск, в журнал или в командную строку; ввод выполняется в поле формы один раз в текущей вкладке; всплывающие окна отсутствуют. Поле ДОЛЖНО сохранять пароль в памяти текущей вкладки между операциями, включая ошибки. Общий компонент ДОЛЖЕН иметь справа кнопку показа/скрытия с подсказкой и доступом с клавиатуры. По умолчанию и при запуске операции пароль скрыт. При уходе из вкладки, смене подключения или закрытии пароль очищается; backend очищает свою копию после этапа. Подготовка ДОЛЖНА указывать необходимость знать пароль OpenWrt для SSH; для Reset-восстановления он не требуется. Неизвестные SSH-ключи не принимаются автоматически. [U] (р.1.1)

5.1.3. Мастер ДОЛЖЕН показывать локально обнаруженные работающие Ethernet-подключения с IPv4 в сети целевого адреса по имени и IP. Пользователь явно выбирает выделенное подключение; тип USB и наличие нужного роутера по одному списку не утверждаются. При наличии данных ОС к имени добавляется краткое описание адаптера; обновление списка обозначается ↻ с текстовой подсказкой. Индекс берётся из ОС; пустой список сопровождается подсказкой. Перед SSH сохраняется проверка прямого маршрута. В подготовленном сеансе подключение фиксировано до нового сеанса. [N] (р.1.2)


5.1.4. Мастер ДОЛЖЕН выделять результаты рамкой и предоставлять кнопку ⧉ для копирования всего протокола, включая строки вне видимой области. Пустой протокол отключает кнопку; успешное копирование показывается знаком ✓ на две секунды. [N] (р.1.5)

5.1.5. Мастер ДОЛЖЕН отделять подробные инструкции во вкладку «Справка», оставляя в «Установке» краткое пояснение и условия подготовки. Обе вкладки ДОЛЖНЫ прокручиваться независимо; при рабочей области 800 × 450 логических пикселей нижние кнопки доступны прокруткой, группы действий переносятся по ширине. Чтение справки НЕ ДОЛЖНО очищать пароль или прерывать операцию; показ пароля при этом выключается. Выход из реального режима сохраняет прежнее правило очистки. [N] (р.1.6)

## 6. Нефункциональные требования

6.1.1. Сборка реального комплекта должна включать проверенный Python-архив, worker, manifest SHA256 и оба IPK; для свежей установки добавляются полный проверенный bundle зависимостей, fresh_install.py и образ восстановления OpenWrt. Qt EXE остаётся статическим. [U] (р.1.4)

6.1.2. Мастер ДОЛЖЕН называться Schoolbell Setup Wizard / «Мастер установки Школьника», иметь независимую версию из wizard-version.txt и EXE schoolbell-setup-wizard.exe; версия ДОЛЖНА отображаться в окне и свойствах Windows. Переименование НЕ ДОЛЖНО менять существующее хранилище сеансов/копий. [N] (р.1.7)

6.1.3. Сборщик ZIP-кандидата ДОЛЖЕН проверять полный состав закреплённых IPK, control-метаданные, SHA256, ABI, отсутствие ссылок и небезопасных путей. Имена/структура определены в docs/formats/release-bundle-v1.md. Результат ДОЛЖЕН создаваться только в новом каталоге, сохранять исходное происхождение и отдельный commit упаковки. Без явного --candidate сборка НЕ ДОЛЖНА выдавать публичный релиз до завершения release gates. Для одинаковых входов ZIP ДОЛЖЕН быть детерминирован. [N] (р.1.7)

## 9. Допущения и открытые вопросы

Пилот использует существующий доверенный ключ и рабочий выделенный маршрут. Подготовка новых ключей, автоматический откат и GUI перепрошивки отложены. Для свежей OpenWrt пароль предварительно задаётся через LuCI; ключ SSH должен быть известен. Аппаратная приёмка свежей установки ещё не выполнена. После аварийного завершения worker оставшийся lock разбирается вручную. Полный overlay может содержать секреты и не предназначен для публикации. Аппаратная приёмка не заменяется тестами с подменённым SSH.

## Приложение A. Константы

PREPARE_TTL = 1800 с (4.1.3), REMOTE_TIMEOUT = 240 с, CONNECT_TIMEOUT = 8 с. Объём копии ограничен доступным tmpfs; исходная проверка требует 6144 КиБ tmpfs и 1024 КиБ overlay. Ограничения пилота подлежат расширению после аппаратной проверки.

Результат 24.11.2026: TC-01/TC-02 — девять локальных регрессионных тестов; TC-03 — сборка и визуальная проверка поля пароля/результата; TC-04 — реальное обновление отдельного устройства подтверждено worker и владельцем. Аппаратный обрыв записи не проверялся. Автопрокрутка журнала и повторное открытие подготовленного сеанса проверены в GUI.
