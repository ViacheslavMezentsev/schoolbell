## 1. Введение

Документ дополняет основное ТЗ Школьника, не меняя номера его требований и TC. Номера TC в этом отдельном документе локальны и не относятся к основному ТЗ. Область — обновление установленного 5.1.124 до 5.1.127 и установка 5.1.127 с зависимостями на чистую OpenWrt, без перепрошивки. Происхождение: [N] новое, [R] сохранённое, [U] уточнённое. разделы 3–6 — нормативные; номера постоянны. Источник — запрос владельца о реальной установке поверх OpenWrt с выключенным автоматом и неизменной громкостью. См. [README мастера](../../tools/setup/gui/README.md).

## 2. Общее описание

Qt показывает состояние worker; Python использует Windows OpenSSH. Роутер не получает компиляторы. Пароль вводится в форме, askpass получает его по приватному локальному каналу текущего пользователя. Пользователь выбирает выделенный USB–Ethernet. Макет удалён; неподключённые операции прошивки явно обозначены.

## 3. Состояния и данные

3.1.1. После неизвестного исхода записи мастер должен запрещать повторную запись и предоставлять отдельную проверку результата. Маркер сохраняется и при архивировании; до подтверждения результата новый сеанс запрещён. [U] (р.1.2)

3.1.2. Одновременно ДОЛЖЕН выполняться только один worker для активного каталога сеанса, включая переименование в архив и создание нового каталога; оставшийся после аварии lock/guard блокирует продолжение. [U] (р.1.2)

3.1.3. «Новый сеанс» ДОЛЖЕН после подтверждения локально переименовать предыдущий каталог в уникальный каталог архива, сохранив копии, протокол и маркер записи. Если запись могла начаться, требуется подтверждение результата, связанное SHA256 с подготовкой и маркером; контрольные суммы копий и IPK отката должны совпадать. Старое подтверждение без этих связей требует повторной проверки. Проверка результата ДОЛЖНА использовать сохранённый комплект сеанса независимо от пересборки текущего; неудачная повторная проверка аннулирует прежнее подтверждение. Пароль и выбор подключения очищаются; операции с устройством не выполняются. [N] (р.1.2)

3.1.4. GUI ДОЛЖЕН принимать этапы и итоги по отдельному от журнала локальному каналу с версией протокола, идентификаторами операции/сеанса, действием и возрастающим номером события. Повторное чтение неизменного события допустимо. Несовпадающие идентификаторы, неизвестные коды, регресс последовательности, изменение терминального итога или сообщение больше 65536 байт НЕ ДОЛЖНЫ давать успех. Успех ДОЛЖЕН требовать допустимый для действия итог и штатное завершение worker с кодом 0; текст журнала не участвует в выборе результата. Пароль и удалённый вывод НЕ ДОЛЖНЫ включаться в канал управления. `[N]` (р.1.13)

3.1.5. Мастер ДОЛЖЕН разрешать запрос отмены проверки ZIP, подготовки, копирования и проверки результата с обработкой между читающими запросами, не убивая текущий SSH. Установка и архивирование сеанса НЕ ДОЛЖНЫ прерываться этим запросом. Отмена ДОЛЖНА сохранять частичные материалы и освобождать штатные блокировки; при маркере возможной записи результат остаётся неизвестным. Пока worker работает, навигация и закрытие остаются заблокированными. `[N]` (р.1.13)

3.1.6. Мастер ДОЛЖЕН удерживать блокировку ОС активного сеанса во всех операциях, включая архивирование и восстановление. По явному подтверждению восстановления он ДОЛЖЕН сохранять известные маркеры GUI в отдельном архиве, не изменяя копии и признаки записи; живой worker, старый или повреждённый формат ДОЛЖНЫ блокировать восстановление. После возможной записи ДОЛЖНА оставаться отдельная проверка результата без автоматического повтора установки. Восстановление НЕ ДОЛЖНО обращаться к устройству. `[N]` (р.1.14)


3.1.7. Планировщик сети ДОЛЖЕН принимать снимок интерфейсов, маршрутов, портов и состояния восстановления, проверять уникальный GUID физического USB–Ethernet с DHCP, отсутствие ручных/занятых адресов, конфликтов маршрутов и занятых портов профиля. Отсутствие IP НЕ ДОЛЖНО исключать адаптер из выбора; отсутствие линка ДОЛЖНО блокировать допуск. Фоновый маршрут через шлюз ДОЛЖЕН требовать последующей проверки прямого пути, а не безусловного отключения VPN. План ДОЛЖЕН содержать идентификатор адаптера, хеш снимка, закреплённые метаданные образа и границы очистки, не изменять вход, не обращаться к сети/устройству и не объявлять READY или проверку образа. `[N]` (р.1.15)

3.1.8. Сборщик Windows ДОЛЖЕН читать только локальные сведения об адаптерах, адресах, маршрутах, UDP-портах и оставшемся состоянии восстановления. Он НЕ ДОЛЖЕН отправлять сетевые пробы, обновлять DHCP или изменять настройки. GUI ДОЛЖЕН требовать выбор адаптера и подтверждение точной модели, заново собирать снимок перед каждой проверкой плана, сбрасывать результат при смене адаптера/профиля и блокировать навигацию во время чтения. Ошибка чтения НЕ ДОЛЖНА представляться успешной проверкой. `[N]` (р.1.15)


3.1.9. Сетевой helper ДОЛЖЕН запускаться только после явного подтверждения GUI и UAC, принимать фиксированные prepare/restore, профиль и GUID без произвольных команд. Подготовка ДОЛЖНА повторить preflight, сохранить защищённый журнал до добавления адреса и проверить прямой маршрут. Restore ДОЛЖЕН использовать GUID журнала, удалять только собственный адрес и подтверждать конфигурацию DHCP; неудача ДОЛЖНА сохранять журнал. Живой второй helper и неопределённая принадлежность адреса ДОЛЖНЫ блокировать изменение. Helper НЕ ДОЛЖЕН менять DNS, другие адаптеры или запускать TFTP/firewall на этом этапе; подтверждение DHCP НЕ ДОЛЖНО означать получение аренды. Отмена UAC НЕ ДОЛЖНА считаться подготовкой сети. `[N]` (р.1.16)

## 4. Функциональные требования

4.1.1. Для обновления до записи проверяются прямой маршрут выбранного IPv4/адаптера, известный ключ SSH, плата MR3020 v3, OpenWrt 19.07.9, kernel ABI, native clock 1.0.0 и наличие версии, соответствующей IPK отката. Несовпадение останавливает операцию. Свежая установка проверяется по п. 4.1.7. [U] (р.1.4)

4.1.2. До обновления сохраняются полный overlay и IPK отката на ПК; SHA256 копии сверяется с устройством, архив читается без распаковки. Повреждённая копия запрещает установку. Для свежей установки используется копия и образ из п. 4.1.7. [U] (р.1.4)

4.1.3. Установка требует подтверждения пользователя; подготовка действует 1800 секунд. Проверяется совпадение устройства/загрузки, настроек звука и контрольных сумм. [N] (р.1.0)

4.1.4. Успех показывается только после проверки целевой версии, отсутствия package.pending, выключенных автозвонков, сохранённых настроек звука, черновика, ревизии активного плана и работающих служб. Для свежей установки прежние данные Школьника отсутствуют; проверяются все версии пакетов, выключенный автомат, службы и неизменность защищённых сетевых/системных настроек. [U] (р.1.4)

4.1.5. Пилот не должен перепрошивать устройство, настраивать сеть или часы, включать автозвонки и изменять громкость. При исходно включённом автомате подготовка прекращается. [N] (р.1.0)

4.1.6. Если установлена целевая версия комплекта, мастер ДОЛЖЕН проверить совместимость среды, native clock, отсутствие package.pending, выключенный автомат и работающие службы. После успешной проверки он ДОЛЖЕН показать отдельное состояние «уже установлен», не создавать подготовку записи и не запускать opkg. Ошибка любой проверки не является успехом. [N] (р.1.3)

4.1.7. Для чистой OpenWrt мастер ДОЛЖЕН проверить плату, ABI/libc, отсутствие установленных данных Школьника, совместимость уже имеющихся зависимостей и SHA256 полного комплекта. До записи сохраняются полный overlay, список пакетов, идентичность устройства/загрузки и проверенный образ той же OpenWrt; откат требует повторной прошивки и восстановления overlay, автоматически не выполняется. Перед записью повторно сверяются подключение, загрузка, состав пакетов и защищённые настройки; требуется место для зависимостей и резерв. Маркер записи создаётся до SSH; неизвестный исход запрещает повтор и архивирование до успешной проверки. [N] (р.1.4)

4.1.8. После проверки установленного Школьника мастер ДОЛЖЕН предоставлять чтение резервной копии всех MTD-разделов и overlay. Каждый файл сверяется SHA256 с устройством и повторно на ПК; отметка verified создаётся только после сверки идентичности загрузки, выключенного автомата, звука и плана. Каталог уникален, прежние копии не перезаписываются; частичная копия не является проверенной. Операция не пишет flash. [N] (р.1.4)

4.1.9. Host-установщик ZIP ДОЛЖЕН разделять prepare/install/verify и использовать общую с GUI логику свежей установки. До SSH проверяются комплект и образ восстановления; до публикации подготовки сохраняются и проверяются overlay, инвентарь, устройство/загрузка, защищённые настройки и образ на ПК. Инвентарь копии ДОЛЖЕН совпадать с исходным планом. Квитанция связывает SHA256 ZIP, подготовки и manifest полезной нагрузки; повторные операции сверяют также IPK и копии. Install ДОЛЖЕН требовать подтверждение с адресом, соблюдать п. 4.1.3 и перед записью повторно проверять состояние в той же SSH-команде. Маркер создаётся до SSH; повтор install запрещён даже после успешной записи, verify разрешён отдельно. Неудачная verify ДОЛЖНА аннулировать старое подтверждение. Подключение использует явно заданный локальный IPv4 и ранее сверенный ключ SSH, без изменения сети. Upgrade, repair и перепрошивка этим CLI НЕ выполняются. [N] (р.1.9)

4.1.10. GUI ДОЛЖЕН обнаруживать локальные schoolbell-v*-openwrt-*.zip рядом с EXE и предоставлять явный выбор между внешними ZIP. Выбор ZIP ДОЛЖЕН запускать только локальную проверку формата, состава, совместимости версии мастера и SHA256, без SSH и пароля; отказ блокирует подготовку. Версия на кнопке/в подтверждении берётся из проверенного ZIP. До подготовки повторно сверяется хеш выбранного файла, затем его байты закрепляются в сеансе и используются по п. 4.1.9. Проверка прямого маршрута выбранного адаптера сохраняется перед каждым SSH. Подготовленный, частичный или неизвестный сеанс блокирует смену ZIP; новый сеанс архивирует копии, но при возможной записи требует связанного подтверждения результата. Повторный запуск восстанавливает закреплённое подключение и сохраняет неизвестный исход до verify. Пароль остаётся в текущем общем поле по п. 5.1.2. ZIP в пилоте поддерживает только свежую установку; встроенная установка больше не предлагается. [U] (р.1.11)

4.1.11. Мастер ДОЛЖЕН блокировать новую установку без проверенного внешнего ZIP; полная копия MTD/overlay ДОЛЖНА быть доступна независимо от комплекта до записи. Старые копии и проверка неизвестного исхода сохраняются. [U] (р.1.11)

4.1.12. После неизвестного исхода мастер МОЖЕТ разрешить новый сеанс без подтверждения установки только после чтения и сверки идентичности устройства/загрузки, полного состава пакетов и защищённых настроек с подготовкой, отсутствия пакета и его данных. Доказательство ДОЛЖНО быть связано с конкретной подготовкой и попыткой; результат ДОЛЖЕН явно отличаться от успешной установки. Команда SSH ДОЛЖНА быть не длиннее 8000 байт. [U] (р.1.11)



## 5. Интерфейсы

5.1.1. Реальный режим должен быть явно отделён от макета; действия и результат отражают worker, без имитационного процента. Во время операции штатное закрытие окна блокируется. [N] (р.1.0)

5.1.2. Пароль не должен сохраняться на диск, в журнал или в командную строку; ввод выполняется в поле формы один раз в текущей вкладке; всплывающие окна отсутствуют. Поле ДОЛЖНО сохранять пароль в памяти текущей вкладки между операциями, включая ошибки. Общий компонент ДОЛЖЕН иметь справа кнопку показа/скрытия с подсказкой и доступом с клавиатуры. По умолчанию и при запуске операции пароль скрыт. При уходе из вкладки, смене подключения или закрытии пароль очищается; backend очищает свою копию после этапа. Подготовка ДОЛЖНА указывать необходимость знать пароль OpenWrt для SSH; для Reset-восстановления он не требуется. Неизвестные SSH-ключи не принимаются автоматически. [U] (р.1.1)

5.1.3. Мастер ДОЛЖЕН показывать локально обнаруженные работающие Ethernet-подключения с IPv4 в сети целевого адреса по имени и IP. Пользователь явно выбирает выделенное подключение; тип USB и наличие нужного роутера по одному списку не утверждаются. При наличии данных ОС к имени добавляется краткое описание адаптера; обновление списка обозначается ↻ с текстовой подсказкой. Индекс берётся из ОС; пустой список сопровождается подсказкой. Перед SSH сохраняется проверка прямого маршрута. В подготовленном сеансе подключение фиксировано до нового сеанса. [N] (р.1.2)


5.1.4. Мастер ДОЛЖЕН выделять результаты рамкой и предоставлять кнопку ⧉ для копирования всего протокола, включая строки вне видимой области. Пустой протокол отключает кнопку; успешное копирование показывается знаком ✓ на две секунды. [N] (р.1.5)

5.1.5. Мастер ДОЛЖЕН отделять подробные инструкции во вкладку «Справка», оставляя в «Установке» краткое пояснение и условия подготовки. Обе вкладки ДОЛЖНЫ прокручиваться независимо; при рабочей области 800 × 450 логических пикселей нижние кнопки доступны прокруткой, группы действий переносятся по ширине. Чтение справки НЕ ДОЛЖНО очищать пароль или прерывать операцию; показ пароля при этом выключается. Выход из реального режима сохраняет прежнее правило очистки. [N] (р.1.6)

5.1.6. Все выпадающие списки простого, экспертного и реального режимов ДОЛЖНЫ использовать общий стиль и одинаковую рисованную стрелку, без зависимости от текстового символа шрифта. Область стрелки — 24 × 24 логических пикселя, шрифт списка — 18 пикселей, минимальная высота строки — 48 пикселей. Списки строк и объектов должны одинаково отображать выбранное значение, раскрытые варианты, фокус и disabled в обеих темах. [N] (р.1.10)

5.1.7. Мастер ДОЛЖЕН показывать при запуске три маршрута: установка OpenWrt на новый роутер, установка комплекта Школьника из выбранного ZIP и восстановление заводской прошивки. Каждый маршрут ДОЛЖЕН содержать список оборудования и потребность в пароле. Пока операции прошивки не подключены, соответствующие страницы ДОЛЖНЫ явно обозначать это, не запускать сервер и не имитировать передачу или успех. Смена маршрута во время операции ДОЛЖНА блокироваться; выход из маршрута комплекта ДОЛЖЕН очищать пароль, сохраняя материалы сеанса. `[N]` (р.1.12)

## 6. Нефункциональные требования

6.1.1. Сборка реального комплекта должна включать проверенный Python-архив, worker, manifest SHA256 и оба IPK; для свежей установки добавляются полный проверенный bundle зависимостей, fresh_install.py и образ восстановления OpenWrt. Qt EXE остаётся статическим. [U] (р.1.4)

6.1.2. Мастер ДОЛЖЕН называться Schoolbell Setup Wizard / «Мастер установки Школьника», иметь независимую версию из wizard-version.txt и EXE schoolbell-setup-wizard.exe; версия ДОЛЖНА отображаться в окне и свойствах Windows. Переименование НЕ ДОЛЖНО менять существующее хранилище сеансов/копий. [N] (р.1.7)

6.1.3. Сборщик ZIP-кандидата ДОЛЖЕН проверять полный состав закреплённых IPK, control-метаданные, SHA256, ABI, отсутствие ссылок и небезопасных путей. Имена/структура определены в docs/formats/release-bundle-v1.md. Результат ДОЛЖЕН создаваться только в новом каталоге, сохранять исходное происхождение и отдельный commit упаковки. Без явного --candidate сборка НЕ ДОЛЖНА выдавать публичный релиз до завершения release gates. Для одинаковых входов ZIP ДОЛЖЕН быть детерминирован. [N] (р.1.7)

6.1.4. Комплект ДОЛЖЕН предоставлять локальный предварительный план по снимку устройства без сети и записи. Проверяются целостность комплекта, метаданные IPK, закреплённые зависимости, ABI устройства, выключенный автомат и отсутствие незавершённой записи. Перед новой установкой остаточные данные Школьника запрещены. Совместимые установленные зависимости сохраняются; их версии участвуют в проверке замыкания. Место оценивается по содержимому IPK с резервом PLAN_FLASH_RESERVE = 512 КиБ и PLAN_RAM_RESERVE = 4096 КиБ. Неполный снимок, нехватка места, неподдержанный upgrade или repair ДОЛЖНЫ приводить к отказу без плана записи. Результат ДОЛЖЕН явно указывать preliminary-only и write_authorized=false: снимок не подтверждает текущее состояние, резервную копию или исправность служб. [N] (р.1.8)

6.1.5. Распаковщик ДОЛЖЕН ограничивать ZIP до ZIP_MAX = 64 МиБ, суммарное содержимое до ZIP_CONTENT_MAX = 128 МиБ, число файлов до ZIP_FILES_MAX = 512 и файл до ZIP_MEMBER_MAX = 16 МиБ. Ссылки, шифрование, traversal, повторные пути без учёта регистра, специальные имена Windows и иной корень версии запрещены. Сеанс создаётся только в новом каталоге вне комплекта; постоянный guard блокирует параллельную операцию. Неизвестный исход нельзя обходить удалением маркера или новым сеансом. Копия ограничена BACKUP_MAX = 32 МиБ; её создание требует RAM не менее удвоенной оценки overlay плюс BACKUP_RAM_RESERVE = 6144 КиБ. Оставшиеся после аварии блокировки не удаляются автоматически. [N] (р.1.9)

## 9. Допущения и открытые вопросы

Пилот использует существующий доверенный ключ и рабочий выделенный маршрут. Подготовка новых ключей, автоматический откат и GUI перепрошивки отложены. Для свежей OpenWrt пароль предварительно задаётся через LuCI; ключ SSH должен быть известен. Аппаратная приёмка свежей установки ещё не выполнена. Блокировки старого или неизвестного формата разбираются вручную; формат GUI с блокировкой ОС восстанавливается по 3.1.6. Полный overlay может содержать секреты и не предназначен для публикации. Аппаратная приёмка не заменяется тестами с подменённым SSH.

## Приложение A. Константы

PREPARE_TTL = 1800 с (4.1.3), REMOTE_TIMEOUT = 240 с, CONNECT_TIMEOUT = 8 с. Объём копии ограничен доступным tmpfs; исходная проверка требует 6144 КиБ tmpfs и 1024 КиБ overlay. Ограничения пилота подлежат расширению после аппаратной проверки.

Результат 24.11.2026: TC-01/TC-02 — девять локальных регрессионных тестов; TC-03 — сборка и визуальная проверка поля пароля/результата; TC-04 — реальное обновление отдельного устройства подтверждено worker и владельцем. Аппаратный обрыв записи не проверялся. Автопрокрутка журнала и повторное открытие подготовленного сеанса проверены в GUI.

PLAN_FLASH_RESERVE = 512 КиБ, PLAN_RAM_RESERVE = 4096 КиБ (6.1.4). Это запас оценки пакетов, не места под резервную копию. Ручная установка из нового ZIP и аппаратная приёмка планировщика не выполнены.

ZIP_MAX = 64 МиБ; ZIP_CONTENT_MAX = 128 МиБ; ZIP_FILES_MAX = 512;
ZIP_MEMBER_MAX = 16 МиБ; BACKUP_MAX = 32 МиБ; BACKUP_RAM_RESERVE = 6144 КиБ (6.1.5).
Host CLI не заменяет GUI: приёмка подключения Windows/OpenSSH, свежей установки из ZIP
и восстановления overlay на устройстве остаётся открыта. Локальная проверка shell
использует искусственную файловую систему и не является целевой MIPS-проверкой.

Мастер 0.2.0: локальная GUI-интеграция ZIP не является аппаратной приёмкой. Проверка после настоящего перезапуска Windows и SSH-транзакция GUI ZIP на устройстве остаются открыты.

OPERATION_EVENT_MAX = 65536 байт (3.1.4). Период чтения GUI — 200 мс; событие — атомарный JSON-снимок последнего этапа. Идентификатор сеанса — SHA256 канонического пути, идентификатор операции — новый UUID; новый сеанс в том же каталоге различается UUID операций. История результатов установки подтверждается отдельными связанными квитанциями, а не старым событием.
