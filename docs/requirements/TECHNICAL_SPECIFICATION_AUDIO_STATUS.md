## 1. Введение

1.1. Назначение: дополнить шапку интерфейса без селектора карт и изменения воспроизведения.
1.2. Базовые номера требований и TC остаются неизменными; номера этого документа имеют собственную область AUDIO_STATUS. В базовом требовании 5.3.10 уточняется только нормальный цвет Flash: синий вместо зелёного по последнему запросу владельца. Остальные требования базового ТЗ сохраняются.
1.3. Источники: явные запросы владельца и существующие controls/sound_test/cpu.js. Маркеры `[R]` — сохранённое поведение, `[N]` — новое, `[U]` — уточнение. ДОЛЖЕН означает проверяемое обязательное требование. Номера не переиспользуются. разделы 3–5 — нормативные; остальные разделы информативные.

## 2. Общее описание

2.1. Индикация показывает метаданные выбранного по умолчанию выхода, а не подтверждение слышимости или успешного запуска. Громкость — сохранённое усиление следующего запуска, не положение несохранённого редактора и не уровень звукового давления.
2.2. Селектор, резервный маршрут и автоматический переход на другую карту вне объёма.

## 3. Модель данных

3.1.1. Исполнитель ДОЛЖЕН сохранять выход `/dev/dsp`; отсутствие этого пути НЕ ДОЛЖНО приводить к выбору `/dev/dsp1` или иной карты. `[R]`
3.1.2. Состояние индикации ДОЛЖНО различать ready, missing и unknown; отсутствие метаданных или ошибка чтения не равнозначны отсутствию карты. `[N]`
3.1.3. Состояние ready ДОЛЖНО содержать доступные контроллер, имя производителя и модель именно устройства, соответствующего `/dev/dsp`; при изменении сопоставления во время чтения результат ДОЛЖЕН быть unknown. `[N]`

## 4. Функциональные требования

4.1.1. Под Flash ДОЛЖНА отображаться строка «Аудио: контроллер · имя (модель)» без технического пути. Совпадающие имя и модель НЕ ДОЛЖНЫ дублироваться; неизвестные контроллер/карта обозначаются явно. `[N]`
4.1.2. При missing ДОЛЖНО отображаться «Аудио: не обнаружено»; при unknown, неудачном опросе или выходе из сеанса — «Аудио: нет данных». После возраста успешного ответа более 15000 мс строка ДОЛЖНА стать неизвестной при ближайшем проходе обновления (период 2000 мс). `[N]`
4.1.3. Справа ДОЛЖНО отображаться сохранённое усиление как `100 × 10^(dB/20)` процентов с максимум одним десятичным знаком и исходное значение дБ; диапазон −60…0 дБ. Примеры: −60 → 0,1%; −6 → 50,1%; 0 → 100%. Ошибочное или устаревшее значение ДОЛЖНО быть неизвестным. Редактирование без сохранения НЕ ДОЛЖНО менять индикатор. `[N]`
4.1.4. Нормальная линия Flash ДОЛЖНА использовать синий accent медиатеки при занятом объёме до 75% включительно; выше 75% — жёлтый, выше 90% — красный. CPU не изменяется. МиБ означает 1024² байт. `[U]`

## 5. Интерфейсы и ограничения

5.1.1. Метаданные ДОЛЖНЫ передаваться существующим ответом controls без дополнительного HTTP-опроса; чтение НЕ ДОЛЖНО открывать аудиоустройство, запускать звук или изменять настройки. `[N]`
5.1.2. Имена USB ДОЛЖНЫ выводиться как текст, без выполнения HTML; чтение строки ограничивается 257 байтами, принимается не более 256, вывод имени — не более 96 байт; поиск предков ограничивается 20 шагами. `[N]`
5.1.3. Pages ДОЛЖЕН использовать общий renderer и явно показывать демо без подключённого устройства, не выдавая фиктивный маршрут за аппаратный. `[N]`

## 8. Допущения

8.1. Sysfs и /dev принадлежат ОС. В интервале между опросами устройство может измениться; строка не резервирует карту для последующего воспроизведения.
8.2. Политика громкости при mute не меняется: показано настроенное усиление, состояние «Без звука» отображается существующей кнопкой.
8.3. Открытый вопрос за рамками изменения: устойчивый выбор нескольких карт и устранение причины отказов EHCI.

## Приложение A. Константы

Выход /dev/dsp; свежесть 15000 мс; обновление UI 2000 мс; метаданные 256/96 байт, 20 предков; −60…0 дБ; Flash 75/90%; 1 МиБ = 1048576 байт.
