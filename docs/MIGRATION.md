Дата: 2026-10-31. Этап M0: архив и организация работ. Это план миграции,
не новая редакция требований runtime и не отчёт о готовой автономной сборке.

Локальные HEAD сверены с GitHub API веток. История schoolbell продолжается,
не заменяется историей core. Происхождение будущего импорта фиксируется исходным
коммитом, путями и SHA-256 в [инвентаре](migration-inventory.json). Сам код не
скопирован. Для следующего этапа вновь проверить HEAD и либо сохранить эту базу,
либо явно обновить инвентарь. Не смешивать незаметно несколько ревизий.

Работа ведётся в WSL-копии schoolbell рядом с core. Windows-копия не меняется.
Windows Git подписывает коммиты той же WSL-копии; Linux Git пока не настроен
на подпись. Новый ключ и условный includeIf в этом этапе не создаются.

## M1–M5: порядок следующих итераций

1. **M1 — самостоятельные исходники и сборка.** Перенести по инвентарю, сохранив
   provenance. Сборка из чистого клона без соседнего core, ignored tests/manual
   или абсолютных путей автора. Явно описать host dependencies и native toolchain.
2. **M2 — совместимость и проверки.** Полные Lua/JS/C/player, .sbb/.sbp, media,
   UI, IPK/offline install/upgrade/rollback. Сопоставить payload старой и новой
   сборки; каждое отличие объяснить. Версия следующего IPK выбирается при сборке,
   M0 не повышает 5.1.27. Автовключение после restore не допускается.
3. **M3 — Pages и документация.** Предлагаемые пути /schoolbell/ (проект),
   /schoolbell/demo/, /schoolbell/guide/, /schoolbell/training/, /schoolbell/devices/.
   UI общий с устройством, недоступное оборудование в демо отключено. Проверить
   пути ассетов, ручное воспроизведение в браузере, issue forms, сборочный SHA,
   дату и ссылки обновлений. Публикация владельцем после проверки.
4. **M4 — отдельно разрешённый стенд.** Проверенный бэкап и комплект отката,
   обновление поверх существующего пакета без потери данных, отдельно новая
   установка. Устройство приёмки не обновлять по разрешению для стенда разработки.
5. **M5 — завершение разделения.** После успешных M1–M4 добавить ссылки/переходы
   со старых Pages и удалить дублируемые активные источники из core отдельной
   веткой. Сохранить историю и интеграционные контракты ядра. Владелец создаёт
   отдельное workspace schoolbell; этот чат/workspace возвращается к core.

## Совместимость, которую сохраняем при первом переносе

Пакеты modbus-schoolbell и modbus-schoolbell-clock, init/service, пути данных,
LuCI route и media ID не переименовываются одновременно с перемещением исходников.
Нет обязательной установленной зависимости от пакета ядра, но есть build-time
зависимость от strict JSON и общих инструментов — её нужно закрыть явно.
Форматы .sbb/.sbp и их поддерживаемые версии проверяются существующими тестами;
не преобразовывать пользовательские данные ради нового имени репозитория.
Не переносить реальные бэкапы, ключи, логи, прошивки и личные данные в Git.
Лицензии компонентов/аудио проверяются отдельно, новая общая лицензия не назначена.

Оба Pages находятся на одном origin viacheslavmezentsev.github.io. Ключ демо
openwrt-schoolbell-public-demo-v1 разделяется между путями: нужен явный сценарий
переноса/изоляции localStorage с сохранением пользовательского черновика, а не
очистка хранилища. Проверить переход со старой страницы, повторный вход и экспорт
.sbp. Старые ссылки сохраняются до готовности нового сайта.

## Проверка M0 и критерий завершения всей миграции

Для M0: `python3 scripts/check-foundation.py`, `git diff --check`, проверка всех
20 файлов против исходного Git-коммита и подписи нового коммита. Архив не запускать.
GitHub CI фиксируется отдельно после push владельцем; локальный PASS не означает
удалённый CI. На устройства в этом этапе не обращаемся.

Вся миграция завершена, только когда чистый клон собирает и проверяет продукт,
Pages работают, обновление/откат сохраняют данные, зависимости и лицензии явны,
а рабочий источник один. Короткая проверка UI не заменяет полную приёмку и
недельную эксплуатацию на зафиксированных артефактах.

## Переход основной ветки на main

После принятия M0 основная ветка GitHub переименована master → main штатным
API GitHub. Исторические исходные точки в таблице выше сохранены как факты.
WSL-копия отслеживает origin/main, origin/HEAD указывает на origin/main.
Правила, команды слияния и фильтр CI обновлены на main отдельной веткой.
Windows-копия не менялась. Для её будущей синхронизации, только при чистой
локальной master: git branch -m master main, git fetch origin,
git branch --set-upstream-to=origin/main main, git remote set-head origin -a.
Изменения веток не публикуют Pages и не обновляют устройства.
