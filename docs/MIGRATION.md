# Выделение «Школьника» в schoolbell

Дата: 2026-10-31. Этапы M0–M1: архив, организация работ и исходники. Это план миграции,
не новая редакция требований runtime. Результат автономной host-сборки M1 приведён ниже; целевая сборка и аппаратная приёмка ещё предстоят.

Локальные HEAD сверены с GitHub API веток. История schoolbell продолжается,

либо явно обновить инвентарь. Не смешивать незаметно несколько ревизий.

Работа ведётся в WSL-копии schoolbell рядом с core. Windows-копия не меняется.
Windows Git подписывает коммиты той же WSL-копии; Linux Git пока не настроен
на подпись. Новый ключ и условный includeIf в этом этапе не создаются.

Инвентарь содержит реальные файлы этих групп, не обещает полноты транзитивных
зависимостей. Маркеры review/split в proposed_destination требуют решения, это
не создаваемые сейчас каталоги. Перед переносом проверить все импорты и вызовы
сборщиков, fixtures, локальные ссылки, vendored файлы и NOTICE. Обнаруженные
дополнительные зависимости добавить в инвентарь с хешами.

## M1–M5: порядок следующих итераций

1. **M1 — самостоятельные исходники и сборка.** Перенести по инвентарю, сохранив
   provenance. Сборка из чистого клона без соседнего core, ignored tests/manual
   или абсолютных путей автора. Явно описать host dependencies и native toolchain.
2. **M2 — совместимость и проверки.** Полные Lua/JS/C/player, .sbb/.sbp, media,
   UI, IPK/offline install/upgrade/rollback. Сопоставить payload старой и новой
   сборки; каждое отличие объяснить. Версия следующего IPK выбирается при сборке,
   M0 не повышает 5.1.27. Автовключение после restore не допускается.
3. **M3 — Pages и документация.** Утверждённый вход /schoolbell/ сразу открывает интерфейс звонка,
   как на устройстве, без промежуточной страницы проекта. Руководство, обучение
   и устройства — отдельные страницы с возвратом в интерфейс.
   UI общий с устройством, недоступное оборудование в демо отключено. Проверить
   пути ассетов, ручное воспроизведение в браузере, issue forms, сборочный SHA,
   дату и ссылки обновлений. Публикация владельцем после проверки.
4. **M4 — отдельно разрешённый стенд.** Проверенный бэкап и комплект отката,
   обновление поверх существующего пакета без потери данных, отдельно новая
   установка. Устройство приёмки не обновлять по разрешению для стенда разработки.
5. **M5 — завершение разделения.** После успешных M1–M4 добавить ссылки/переходы
   со старых Pages и удалить дублируемые активные источники из core отдельной
   веткой. Сохранить историю и интеграционные контракты ядра. Владелец создаёт
   отдельное workspace schoolbell; этот чат/workspace возвращается к core.

## Совместимость, которую сохраняем при первом переносе

Пакеты modbus-schoolbell и modbus-schoolbell-clock, init/service, пути данных,
LuCI route и media ID не переименовываются одновременно с перемещением исходников.
Нет обязательной установленной зависимости от пакета ядра, но есть build-time
зависимость от strict JSON и общих инструментов — её нужно закрыть явно.
Форматы .sbb/.sbp и их поддерживаемые версии проверяются существующими тестами;
не преобразовывать пользовательские данные ради нового имени репозитория.
Не переносить реальные бэкапы, ключи, логи, прошивки и личные данные в Git.
Лицензии компонентов/аудио проверяются отдельно, новая общая лицензия не назначена.

Оба Pages находятся на одном origin viacheslavmezentsev.github.io. Ключ демо
openwrt-schoolbell-public-demo-v1 разделяется между путями: нужен явный сценарий
переноса/изоляции localStorage с сохранением пользовательского черновика, а не
очистка хранилища. Проверить переход со старой страницы, повторный вход и экспорт
.sbp. Старые ссылки сохраняются до готовности нового сайта.

## Проверка M0 и критерий завершения всей миграции

Для M0: `python3 scripts/check-foundation.py`, `git diff --check`, проверка всех
20 файлов против исходного Git-коммита и подписи нового коммита. Архив не запускать.
GitHub CI фиксируется отдельно после push владельцем; локальный PASS не означает
удалённый CI. На устройства в этом этапе не обращаемся.

Вся миграция завершена, только когда чистый клон собирает и проверяет продукт,
Pages работают, обновление/откат сохраняют данные, зависимости и лицензии явны,
а рабочий источник один. Короткая проверка UI не заменяет полную приёмку и
недельную эксплуатацию на зафиксированных артефактах.

## Переход основной ветки на main

После принятия M0 основная ветка GitHub переименована master → main штатным
API GitHub. Исторические исходные точки в таблице выше сохранены как факты.
WSL-копия отслеживает origin/main, origin/HEAD указывает на origin/main.
Правила, команды слияния и фильтр CI обновлены на main отдельной веткой.
Windows-копия не менялась. Для её будущей синхронизации, только при чистой
локальной master: git branch -m master main, git fetch origin,
git branch --set-upstream-to=origin/main main, git remote set-head origin -a.
Изменения веток не публикуют Pages и не обновляют устройства.

## M1 — исходники и автономная сборка

Перенос с той же базы 243a7cc: src, ui, packaging, assets, vendor, tests и scripts.
docs/source-map.json фиксирует источник/назначение и SHA-256 исходных файлов;
инвентарь M0 обновлён только для реально перенесённых элементов. Неперенесённые
документы/прототипы/Pages остаются отдельными этапами. Ссылки README ведут на
зафиксированные исходные документы до их отдельной миграции.

Кандидат 5.1.28 отличается от 5.1.27 версией, Installed-Size, двумя host fallback
путями portable-plan и путём manifest в NOTICE. Имена установленных пакетов,
Lua-модулей, служб, LuCI и данных не меняются. Целевые скрипты не устанавливались.
Offline-builder теперь допускает отсутствие --core; optional joint core сохраняется.
Тесты замыкания зависимостей и отказов работают с синтетическими пакетами.

Проверки: make all в WSL и в копии только подготовленных Git-файлов вне дерева
проекта; payload/control сравнены с исходной сборкой. Точные результаты и ограничения
фиксируются в CHANGELOG/TODO по завершении. Полный реальный MIPS offline-комплект,
обновление/откат на устройстве и браузерная приёмка остаются отдельными этапами.
Pages не публиковались. Владелец уточнил вход: корень Pages сразу показывает звонок.

## Следующая итерация: документация и FUNDING

После принятия ba2cf77 перенесены 81 документ с той же исходной базы. Разделы:
requirements, architecture, formats, user, acceptance, history. Текст сохранён,
только назначения Markdown-ссылок адаптированы к новым путям или закреплённому
исходному коммиту. Номера требований, TC/AC и ревизия ТЗ 1.76 сохранены.
Вход в документацию — [указатель](README.md); старые версии/команды обозначены
как исходные материалы, не как повторная аппаратная проверка.

FUNDING.yml добавлен владельцем локально и принят без изменения содержимого.
Изменение не публикует Pages. Следующие этапы: целевая MIPS-сборка и реальный
комплект зависимостей, перенос Pages/руководства/обучения, затем отдельно
разрешённая установка. Устаревшие команды в исходных материалах требуют
отдельной актуализации; текущая сборка описана в BUILD/PACKAGING.

## M3 — исходники Pages

Корень сайта открывает общий интерфейс звонка. Руководство, обучение RU/EN и
устройства перенесены отдельно; формы Issues ведут в schoolbell. Общие UI-файлы
не менялись. Статический сборщик подставляет demo API и метаданные сборки.
Хранилище отделено новым ключом; явное копирование старого черновика сохраняет
исходную копию и не перезаписывает новые данные или правки. Подробности и ручная
публикация: [Pages](../site/README.md). CI проверяет сайт без публикации.

Статусы стендов в руководствах обозначены историческими: нужно отдельно
актуализировать пошаговые команды после целевой сборки и новой проверки.
Старые Pages не перенаправляются и не удаляются этой веткой. Опубликованная
версия и работа в браузере владельца проверяются после ручного workflow.

## Целевой комплект после M3

Самостоятельная сборка SDK + patched Lua headers + 33 зависимых IPK проверена
на хосте, включая повтор без сети, ELF ABI и загрузку в QEMU. Команды и
ограничения — в [PACKAGING](PACKAGING.md). Пакеты 5.1.28/1.0.0 не установлены.
Остаются лицензии/NOTICE, отдельное разрешение стенда с бэкапом и откатом,
затем завершение разделения. Старые аппаратные результаты не перенесены в PASS.

## Проверка обновления на стенде

Из комплекта чистого коммита 5ab216e выполнено отдельно разрешённое обновление
5.1.27 → 5.1.28. Перед ним проверены .sbb, снимок данных/кода и пакет отката.
Новый native 1.0.0 загружается; содержимое .sbb после обновления идентично.
Автозвонки остались выключены, системные/NTP-настройки и загрузочная эпоха
не изменились. Приватные журналы и бэкапы не включены в Git. Это частичная
проверка M4: все 75 установленных файлов совпали с IPK; владелец подтвердил
версию и наличие прежних данных в UI. Реальный downgrade и новая установка
остаются отдельно. Приёмочное устройство не затрагивалось.
