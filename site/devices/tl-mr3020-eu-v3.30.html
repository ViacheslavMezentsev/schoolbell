1. Файл для конкретной ревизии

Корпус: TL-MR3020 EU v3.30. На новом устройстве наблюдалась версия 1.8.0 0.9.1 Build 250625 Rel.56805n. Официальный ZIP содержит BIN 1.8.0, хотя в имени ZIP написано 1.7.0. Исходный BIN сохраняется без преобразования.

Контрольные суммы рассчитаны нами после загрузки по HTTPS, это не цифровая подпись TP-Link. Совпадение номера выпуска не доказывает побайтовую идентичность установленной Flash.

Восстановление — функция загрузчика, а не обязательный отдельный выпуск прошивки. Инструкция PDF из OEM ZIP описывает веб-обновление, не TFTP. Первичный коммит OpenWrt описывает TFTP с образом OpenWrt; wiki упоминает OEM с удалённым заголовком, но не даёт проверенного рецепта для нашего Build 250625. Приём исходного BIN загрузчиком EU v3.30 пока не подтверждён. Не применяйте инструкции обрезки для v1 и не меняйте файл наугад.

2. Подготовить отдельную линию

Ноутбук → USB–Ethernet → LAN нового MR3020. Питание устройства отдельно. Домашний Ethernet ноутбука остаётся подключённым и не перенастраивается; мост и общий доступ не нужны.

  1. Сохраните конфигурацию USB-адаптера, DNS и маршруты. Убедитесь по имени и идентификатору, что выбрали именно его.
  2. Для recovery v3 документирован адрес сервера 192.168.0.225/24; для USB-адаптера не задавайте шлюз и DNS. Это не адрес обычной страницы управления.
  3. Проверьте конфликты подсетей/VPN. Настройте только выделенный адаптер; широкие отключения firewall и VPN не нужны.
  4. В Tftpd64 выберите Server interfaces: 192.168.0.225, отдельный Current Directory, только TFTP и чтение. DHCP, DNS и SNTP сервера выключены. Разрешение Windows Firewall ограничьте этим приложением, USB-интерфейсом, локальным IP и recovery-подсетью.

3. Сначала запрос, без прошивки

Активный каталог должен быть пустым. Не выбирайте каталог с OpenWrt или OEM образом. После отдельного согласования перезапуска запустите сервер, выключите MR3020, удерживайте Reset/WPS и подайте питание. Для v3 первоисточник указывает около 6–7 секунд до запроса. Сохраните журнал: IP клиента, запрошенное имя, время и ответ сервера. Документированное имя — tp_recovery.bin. С пустым каталогом ожидается отказ «файл не найден», а не передача прошивки.

Это проверяет путь запроса, но не запись Flash. Поведение и время удержания именно EU v3.30 ещё должны быть подтверждены на стенде. Отсутствие ping само по себе не означает отказ recovery.

4. Запись — следующий отдельный опыт

Сначала согласуем точный файл, SHA-256 и способ подачи после проверки требований загрузчика. Затем останавливаем сервер, подготавливаем единственный разрешённый tp_recovery.bin и повторяем вход в recovery. Передача может сразу привести к записи без дополнительного вопроса. Питание и кабель во время записи не прерывать.

Отдельно фиксируем: запрос → завершение передачи → загрузку ОС → версию → Ethernet/Wi-Fi. Только успешная передача не является успешным восстановлением. Копия настроек conf.bin не содержит загрузчик и радиокалибровки. После опыта остановите сервер, удалите только созданное правило firewall и верните сохранённые параметры USB-адаптера.

Статус сейчас: файлы и конфигурация сервера подготовлены; адрес/firewall не применены; сервер не запущен; запрос/запись/загрузка через recovery не испытаны. Веб-интерфейс штатной ОС не нужен для TFTP загрузчика.

5. Сохранить материалы на годы

Локально сохранены исходный ZIP, BIN, PDF и лицензия, снимок страницы и манифест. В Pages публикуем собственную памятку RU/EN, точные хэши и исходные ссылки; исходные бинарники не кладём в Git. Локальная копия не является публичным зеркалом: ссылка на наше зеркало ещё не опубликована.

Для долговременного комплекта нужны как минимум две независимые копии. При подготовке публичного архива отдельно проверяем условия распространения всего OEM комплекта; GPL-файл внутри не означает разрешения на все его компоненты. Затем закрепляем неизменяемый архив в хранилище релизов и добавляем ссылку зеркала в JSON. Сохраняем исходное имя, SHA, источник, дату, лицензии и журнал любых преобразований.

Новые модели получают отдельный паспорт и результаты испытаний. Успех восстановления этого MR3020 не будет автоматически считаться проверкой других ревизий.
