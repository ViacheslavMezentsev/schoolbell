1. Prepare hardware

First acceptance profile: TL-MR3020 EU v3.30, reliable power, USB audio card, powered speaker and, if needed, a powered USB hub. Use a laptop with a dedicated USB–Ethernet adapter. Exact hardware and software versions are still being frozen.

Speaker USB power and audio input may be separate cables; power does not carry the audio signal.

Conceptual signal path: USB → audio card → speaker input. Speaker/hub power is separate; this is not an electrical or power-budget diagram.

Devices and TFTP recovery

2. Prepare OpenWrt

The existing engineering bench uses OpenWrt 19.07.9. This does not establish compatibility with every new unit or another release. The exact new-device image, SHA-256 and recovery procedure will be added after verification.

{{BENCH}}

Use the dedicated adapter for the bench and preserve the primary laptop connection. Do not automatically enable bridging or connection sharing. Choose adapter addresses/routes after checking subnet conflicts.

  1. Verify model, region and hardware revision; save stock settings.
  2. Prepare the exact first-install image, official checksum and recovery tools.
  3. After approval, flash and verify first access, version and ABI. A verified step-by-step procedure is not published here yet.

Factory, sysupgrade and recovery are different procedures. This draft does not select an image for immediate flashing; recovery needs revision-specific instructions.

3. Install a ready-made bundle

Most users need a ready-made offline bundle, not a source build. Application candidate: {{VERSION}}. Firmware, kernel ABI and all dependencies also determine compatibility.

  1. Select the exact OpenWrt profile and verify manifest, sizes and SHA-256.
  2. Back up, check free space and retain a rollback package.
  3. Install the agreed IPKs/dependencies locally without requiring on-device downloads.
  4. Verify versions, interface access and automatic bells disabled.

A verified bundle link and exact commands will follow clean-install acceptance. Engineering packaging notes include historical examples; do not use their versions without checking.

In 5.1.25 Settings → Date and time combines timezone, confirmed browser-time setting and trust verification. Setting leaves automatic bells off and NTP unchanged. Pages simulates this action; device acceptance is pending.

4. First startup

  1. Sign in through LuCI using the device password.
  2. Check school timezone, date/time and time trust in Settings. Confirming time does not set the clock.
  3. Add melodies, schedules and named calendar plans; paint dates or import a compatible .sbp.
  4. Save the draft and review its preview. Saving/importing does not enable bells.
  5. During an approved window, test short low-volume manual audio, then separately apply a plan and verify an automatic bell.

Browser playback uses the computer/phone; Shkolnik speakers use the connected device. Disable automatic bells after testing unless operational use has been agreed.

5. Operation and recovery

Download .sbb before updates, replacement or recovery. .sbp transfers selected plans/dependencies; .sbb backs up settings and media. Pages supports bundled melodies and read-only import preview.

After power loss, the current profile requires staff to verify time and explicitly enable the saved plan. Unattended external-RTC startup is not accepted yet. A week of observation cannot guarantee clock accuracy for an academic season.

Use troubleshooting and preserve the journal; do not blindly repeat a write with an unknown outcome. Verify data and auto-off after restoration/update.

6. Developers: build and acceptance

Source builds are a separate path. Pin a clean commit, tools, firmware profile and dependencies; run tests and build IPKs/offline bundle with a manifest. Native dependencies must match the target ABI. This page is not yet a reproducible one-command build recipe.
